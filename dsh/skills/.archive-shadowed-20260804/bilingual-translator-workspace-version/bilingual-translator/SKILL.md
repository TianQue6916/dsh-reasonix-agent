# Bilingual Translator（双语翻译技能）

> ⚠️ **铁律：禁止英中分段对照。** 输出必须是**中文主体 + 英文术语行内嵌入**的单行双语格式。见下方「核心格式」与「❌ 致命错误」。

将各种格式的文件（PDF、DOCX、TXT、HTML 等）翻译为 **行内双语 Markdown**：句子主体用中文自然叙述，关键英文术语保留原文，首次出现时用括号紧跟中文翻译。数学公式、代码块、URL 等保持原样。

## 核心格式（必须严格遵守）

### ✅ 唯一正确的格式

**句子主体用中文自然叙述**，关键英文术语保留原文，首次出现时紧跟括号中文翻译。同一术语在后续出现时可省略括号翻译，只保留英文。

```
Transformer 架构依赖 self-attention 机制（自注意力机制）来捕获序列中的 long-range dependencies（长程依赖关系），并使用 positional encoding（位置编码）来注入关于 tokens（词元/标记）相对位置的信息。
```

格式模板：**`English term（中文翻译）`** —— 英文术语先出现，中文翻译用括号紧随其后。

整段输出中**没有完整的英文原句**，英文只以术语片段的形式出现在中文句子中。每条内容只写**一行**（一段中文），而不是「一行英文 + 一行中文」。

### ❌ 致命错误：英中分段对照

以下是我犯过的错误——**绝对禁止**：

```
In a weighted directed graph G = (V, E), the weighted eccentricity ε(u) of a vertex u ∈ V is the shortest weighted distance to its farthest vertex v...
在带权有向图 G = (V, E) 中，顶点 u ∈ V 的 weighted eccentricity（带权离心率）ε(u)...
```

（问题：先写完整英文段落，再写中文翻译段落。这是英中对照，不是行内双语。）

✅ **正确写法应该是**：

```
在带权有向图 G = (V, E) 中，vertex（顶点）u ∈ V 的 weighted eccentricity（带权离心率）ε(u) 是其到最远 vertex v 的最短带权距离。
```

**识别方法：** 如果输出中有任何一行以英文单词开头、长度超过 10 个词且后面紧跟着一行中文翻译，那就错了。正确的输出中**没有完整的英文原句**。

### ❌ 反复出现的错误（2025.07 实战记录）

以下是在翻译《Elementary Real Analysis》50页的过程中反复出现的错误，均已修正。这些被列为**新增铁律**：

**① 英文句子开头（铁律）**
- ❌ `A sequence（序列）就是...`（英文单词开句）
- ✅ `一个 sequence（序列）就是...`（中文开句，英文术语嵌入）
- 规则：**每句话的第一个字必须是中文**，不能是英文。英文术语只能出现在中文句子中间。

**② 引导箭头式英中对照（铁律）**
- ❌ 
  ```
  Real number system also enjoys an order structure.
  -->
  实数系统还拥有一个 order structure（序结构）。
  ```
  或
  ```
  Real number system also enjoys an order structure.
  实数系统还拥有一个 order structure（序结构）。
  ```
- ✅ `实数系统还拥有一个 order structure（序结构）。`
- 规则：**一行中不能出现先写完整英文再写中文的模式**。如果一行以英文单词开头且该行也有中文，但英文部分是一个完整的句子（有主谓宾），则立即判定为违规。

**③ 同一术语反复加括号（建议）**
- ❌ `用 real numbers（实数）来研究 real numbers（实数）的性质。`
- ✅ `用 real numbers（实数）来研究实数的性质。`（首次出现加括号，后续省略）
- 规则：同一段落/同一小标题下，一个英文术语**首次出现**时加括号翻译，**后续出现**时只保留英文或只保留中文，不再重复加括号。

**④ 多句合并式压缩（铁律）**
- ❌ 将原文3-5句压缩为1句中文翻译
- ✅ 原文的**每一句**都对应至少一句独立的中文翻译
- 规则：除非原文两句明显是同一意思的不同表述，否则**不得合并句子**。每读一句原文，就写一句中文。逐句阅读→逐句翻译→逐句输出。

**⑤ 数学公式环境不能翻译（铁律）**
- ❌ 将 `$$...$$` internal 的 `\text{for all }` 翻译成中文
- ✅ 所有 LaTeX 环境内的文本保持英文原样
- 规则：`$...$`、`$$...$$`、`\begin{aligned}...\end{aligned}` 等 LaTeX 环境内部**不做任何翻译**，即使是 `\text{}` 内的内容也保持原文。

### ❌ 子 agent 常见陷阱（2025.07 Strang 教材翻译记录）

以下是在翻译《Linear Algebra and Learning From Data》50页时子 agent 反复出现的错误。

**① "English sentence（中文）"单行对照（铁律）**
- ❌ `This is how we usually compute each number in $AB = C$（这就是我们通常计算的方式）。`
- ✅ `这就是我们通常计算 $AB=C$ 中每个数字的方式。`
- 识别方法：一行以 The/This/That/We/It/They 开头，英文部分是完整句子（有动词），后跟（中文翻译）。立即判定违规。

**② 伪逐句翻译——实际在概括（铁律）**
- 规则：子 agent 翻译须用中文密度双重验证。低于平均每行6个中文字说明在概括。正文应达30-40行/页。

**③ 缺少 OCR 预处理**
- 规则：翻译前替换常见OCR错误：Aæ→Ax、鬱→x、丛→A、丆→I等。

**④ 章节密度差异过大**
- 规则：全文各章节密度应保持一致。某章明显稀疏说明在压缩。


## 排版规范

### 标题层级

```
# 课程全称
## 讲次/大节（Lecture N）
### 定理/推论（Theorem / Corollary）
#### 定义（Definition）
```

用标题层级实现视觉区分，**不使用** `<div>`（MarkText 中不渲染）。`>` blockquote 可用于虚化次要内容（MarkText 中自动虚化）。

**🚨 铁律：`#` `##` `###` `####` 等 heading markers（标题标记）必须位于行首。** 行首不能有 `<span>` 或其他 HTML tag 在 `#` 之前，否则 Markdown 解析器不会将其识别为标题。

```markdown
✅ ### <span style="color:#2471a3;">**[problem]**</span> <span style="color:#c0392b">Title</span>
❌ <span style="color:#2471a3;">**[problem]**</span> ### <span style="color:#c0392b">Title</span>
```


对于习题集/Problem Set 类文档，遵循以下层级与字号规范：

| Markdown 层级 | 字号 | 颜色 | 用途 |
|:---|:---:|:---:|:---|
| `#` h1 | 最大 | 默认 | 课程全称 |
| `##` h2 | 大 | `#c0392b` 深红 | 讲次/大节标题（如 Problem Session N） |
| `###` h3 | 中 | `#c0392b` 深红 | 题目标题（如 Problem N-M. Title） |
| `<span>正文</span>` | 1em | 默认 | **题目描述**——完整的双语行内翻译 |
| `> blockquote` | 虚化 | 默认虚化 | **答案/解答**——完整行内双语翻译 + 虚化显示 |

### 内容层次原则

每个功能模块用 `<span style="color:#2471a3;">**[tag]**</span>` 标签开头，蓝色统一。

对「题目 + 答案」这种成对结构，严格区分处理规则：

1. **题目（原文）**—— **不得缩颈**。保持完整的行内双语翻译，正文 1em，默认色。原文的故事、背景、细节全部保留。
2. **答案（解答）**—— **完整翻译 + 虚化显示**。用 `>` blockquote 包裹答案全文（与题目一样完整的行内双语翻译），MarkText 自动渲染为虚化文字。答案内容同样保留完整论证，不缩减。
   ```
   > [solution] **Solution（解答）:** 完整翻译的答案内容。
   ```

代码块（```python 等）不受上述字号缩放影响，保持默认大小。

### 译者补充与替代解法

若你对题目或答案有更好的想法，或知道工业界/学术界有更优的解法，用专门标签标注后附加在原文之后：

- **`[note]`** — 背景知识补充、术语解释、上下文关联、历史沿革等。使用深绿色 `#1e8449`。
  ```
  > <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 此算法在现代工业界已由 XX 替代。
  ```
- **`[alternative]`** — 优于原文的解法、现代替代方案、工业界实践等。使用深紫色 `#7d3c98`。
  ```
  > <span style="color:#7d3c98;">**[alternative] Alternative（替代解法）:**</span> 实际工程中多用 YY 算法，时间复杂度更低。
  ```

补充内容同样遵循行内双语格式，放在原文答案之后，用 `>` blockquote 包裹以保持视觉层次。

**注意：**
- 必须明确标注标签，让读者能清晰区分「原文」与「译者补充」。
- **🚨 补充内容必须基于真实来源，不得依赖训练数据瞎写。** 写 `[note]` 或 `[alternative]` 前必须用 web search / GitHub / 论文检索验证信息准确性。例如查证：
  - 工业界当前使用什么算法/框架（GitHub 仓库、技术博客、官方文档）
  - 算法的时间复杂度或工程实践是否有更新
  - 是否有已知的更优解法（SOTA 论文、竞赛获奖方案）
- 如果无法查到可靠来源，则不写补充，不要编造。

### 数学规范

- **🚨 所有数学公式必须使用 LaTeX `$...$`，不允许用文字代替。** 包括：复杂度 $O(n \log n)$、变量 $\delta(s, v)$、下标 $G_k$、上标 $k^*$、负数 $-6$、集合 $\{a, b, c\}$、运算符 $\min$、$\max$、$\le$、$\ge$ 等。
- 数集用 `\mathbb{}`：$\mathbb{R}, \mathbb{Q}, \mathbb{Z}, \mathbb{N}$
- 变量用斜体：$x, m, n, h$
- 定理陈述作为独立命题，证明以 ∎ 结尾
- ✅ 正确：复杂度为 $O(|V|^3)$，其中 $\delta(s, v)$ 表示最短路径距离
- ❌ 错误：复杂度为 O(|V|³)，其中 δ(s, v) 表示最短路径距离（文字代替 LaTeX）

## 示例对照

### 原文
```
The intermediate value theorem says that there exists a c between a and b where f(c) = 0.
```

### ✅ 正确输出
```
[theorem] ### Theorem（定理）
**Intermediate Value Theorem（介值定理）.**
若 $f$ 在 $[a,b]$ 上连续且 $f(a)f(b)<0$，则存在 $c\in(a,b)$ 使得 $f(c)=0$。

[proof] *Proof（证明）.* ……
```

### ❌ 错误输出1（中文在前，英文在后）
```
**介值定理（Intermediate Value Theorem）** 表明：...
```
（问题：`中文（English）` 而非 `English（中文）`）

### ❌ 错误输出2（全部中文化）
```
**介值定理** 表明：...
```
（问题：所有英文术语被强行翻译，失去了双语对照的价值）

### ❌ 错误输出3（使用 div）
```
<div style="...">Theorem（定理）...</div>
```
（问题：MarkText 中 div 不渲染或显示"空的HTML块"）

> ✅ blockquote 可用于虚化次要内容（答案、证明等），MarkText 中自动渲染为虚化文字。

### ❌ 错误输出4（英中分段对照）
```
In a weighted directed graph G = (V, E), the weighted eccentricity ε(u) of a vertex u ∈ V is...
在带权有向图 G = (V, E) 中，顶点 u ∈ V 的 weighted eccentricity（带权离心率）ε(u)...
```
（问题：先写完整英文段落，再写中文翻译段落。这是英中对照/逐段翻译，不是行内双语。
✅ 正确写法：中文为主体，英文术语`English term（中文翻译）`行内嵌入，没有完整英文原句。）

## 工作流程

### Step 1: 读入
- 读取源文件，识别文件类型
- 提取文本内容，保留结构信息（标题层级、列表、表格、代码块、数学公式）
- 对于 PDF：用 PyMuPDF 提取含颜色/字体的文本

### Step 2: 分析
- 识别文档结构：目录、章节、小节、段落
- 区分功能模块：定理、证明、定义、推论、例子、问题
- 识别关键术语、颜色信息

### Step 3: 排版规划
- 确定标题层级：`#` → `##` → `###` → `####`
- 为每个功能模块分配蓝色标签 `[theorem]` `[proof]` `[definition]` 等
- 规划配色方案

### Step 4: 翻译 + 排版输出
- **🚨 铁律：输出中不得出现完整的英文原句。** 英文只以术语片段的形式嵌入中文句子。
- 逐段阅读原文后，**直接用中文写作**，将英文术语作为行内元素嵌入。
- 格式：**`English term（中文翻译）`**，英文术语先出现，中文翻译用括号紧随其后。
- **禁止**「先写完整英文段 + 再写中文翻译段」的英中对照模式。
- 数学公式原样保留，遵循标准 LaTeX 规范。
- 每个功能模块前加蓝色标签。
- 用 `---` 分割线分隔大段落。
- 颜色匹配原文或按配色方案处理。
- **禁止使用** `<div>`（MarkText 不兼容）。`>` blockquote 可用于虚化次要内容。

### Step 5: 层次加工
- **区分主次内容**：题目（原文）和答案（解答）均保持**完整行内双语翻译**；答案用 `>` blockquote 包裹以实现虚化。答案内容不缩减。
- 答案内容不缩减，与题目一样保留完整行内双语翻译。
- 代码块不受字体缩放影响，保持 1em。
- 检查整体视觉层次：标题 → 题目原文 → 答案是否一眼可区分，原文是否被不当压缩。

### Step 6: 译者补充（可选）
- **🚨 写补充前必须先联网查证。** 不要依赖训练数据编写 `[note]` 或 `[alternative]` 内容。
- 用 web_fetch、GitHub 搜索等方式查证现代工业界做法、最新研究进展、SOTA 算法等。
- 判断是否有比原文更优的解法、工业界替代方案、或值得补充的背景知识。
- 如有可靠来源，用 `[note]`（深绿）或 `[alternative]`（深紫）标签标注，放在原文答案之后。
- 补充内容同样用 `>` blockquote 包裹，保持视觉一致。
- 如果查不到可靠来源，则不写补充，不要编造。
- **写完补充后必须二次审查：** 逐条检查每条补充是否（a）有真实来源支撑、（b）表述准确无歧义、（c）与原文答案清晰区分。不确定的宁可不写。

### Step 7: 最终审查
- 全文通读一遍，对照质量检查清单逐项确认。
- 重点核查：标题是否渲染正确、双语格式是否一致、答案是否虚化、补充内容是否有来源。
- 发现任何不符合技能规则的地方，立即修正后再输出。
