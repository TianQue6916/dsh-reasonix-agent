# AIGC — 降检测率技能（实测版）

> **结论先行**：检测器区分的是**你在描述世界，还是在论述应该怎么办**。
> 同一篇论文，只把论述段改写成现象段：**42.69% → 9.65%**（2026-11-08，PaperPass 免费版）。
> 句长、CoV、短句比例、设问密度、比喻数量——**全部无信号**，别再调这些。

---

## 一、判据

| | 判为人（黑 <50%） | 判为 AI（紫 50–60 / 橙 60–70 / 红 ≥70） |
|---|---|---|
| 内容 | 线圈怎么坏、数据怎么歪、路网怎么变 | 应该怎么做、这意味着什么、文献怎么写 |
| 主语 | 设备、数据、物理对象 | 这种方法、这类模型、此种分层 |
| 收尾 | 停在事实上 | 「更易被验证」「相当关键」「流于形式」 |
| 句式 | 陈述 | A 而非 B / 前者…后者 / 不在于…而在于 / 并非…而是 |

机制：这是困惑度检测。具体实体是低概率 token，抬高困惑度；「该方向是合理的」「代价在于」是高频搭配，困惑度最低。

## 二、分数怎么算

PaperPass 把正文切成**片段**（几十到二百字一块），每块给一个分数：

- 红 ≥70｜橙 60~70｜紫 50~60｜黑 <50｜灰不检测
- **总分 ≈ 非黑片段汉字 / 总汉字**（实测两组都吻合到小数点后一位）

改写的目标不是让红变黑，而是**把每个片段压到 50 以下**。53 分和 49 分在分数上差 4 点，在结果上差一个整数百分点。

## 三、四条改写动作

### 1. 论述 → 现象

> ❌ 更现实的位置是离线分析与策略评估，而不是实时调度回路。离线分析要的是精度，可解释性可以稍后补。
>
> ✅ 把图卷积放在离线分析岗，每周跑一次，输出的结果由规划人员复核之后再决定是否调整配时。信号机的实时控制回路则多用规则模型：单点感应控制、干线协调、公交优先，这些逻辑写死在信号机里，出问题当场就能改，不需要重新训练。

### 2. 元评论 → 整句删

「论文里几乎不写这部分成本」「界定条件的用意不在于否定该方法」「各家的做法不统一」「多数文献把这一点视为既定步骤」——**删，不要改写**。这些句子不承载信息，只承载 AI 腔。

### 3. 抽象主语 → 具体对象

「这类模型」→「信号机里写死的单点感应控制」；「此种分层」→「常态拥堵用历史均值，事件场景用模型」；「这条路线的代价」→「参数翻倍，小数据集上过拟合」。

### 4. 评价性收尾 → 事实收尾

砍掉句尾的价值判断。段落停在被描述的对象上，不要停在对它的评价上。

### 具体化 ≠ 堆专名

堆专名只能把 60~70 压到 50~60（实测 v4→v5 仅降 11.6 点）。**结构才是决定性的**（v5→v6 降 33 点）。专名是必要条件不是充分条件。

## 四、写作时的结构约束

1. **每一段都要有一个可指名的对象**：设备、数据集、指标缩写、路段类型、岗位。
2. **删掉所有总结段**。「把上述讨论合起来」「综上」「由此可见」——这类段落 100% 判 AI。
3. **不写分层建议**。「常态与事件场景要求不同，前者…后者…此种分层应当确立」——教科书级 AI 结构，实测 54.96。
4. **设问必须紧跟具体回答**。「脱离评价口径的低误差说明了什么？现有文献很少交代」→ 判人；「答案取决于下游任务」→ 判 AI。
5. **比喻只在承担论证时用**。嵌在具体对象之间的比喻判人（照片 vs 影像），装饰性比喻判 AI（反复涂抹同一种颜色）。
6. **不要口语化**。口语化能降分（实测 38.54%）但过不了审核，且与正式语体冲突。

## 五、检测管线（PaperPass）

启动带调试端口的 Edge（独立 profile，不影响日常窗口）：

```
msedge.exe --remote-debugging-port=9222 --user-data-dir=C:\Users\27063\.dsh\edge-aigc
```

| 脚本 | 作用 |
|---|---|
| `browser.py login` | 打开登录页，**人工登录一次**（profile 持久化） |
| `upload.py x.docx dry` | 只选文件不提交，用于确认字数 |
| `upload.py x.docx` | 选文件+填标题，**图形验证码必须人工过**（唯一人工环节） |
| `poll.py <标题关键字> 200` | 轮询报告列表，返回 AIGC 总分 |
| `grab.py <online-report filename> v7` | 取 report id，存 `out/_ai-v7.html` |
| `score_parse.py out/_ai-v7.html` | 解析 `data-score`，输出片段级分数 + 文本 |

报告页结构：`<a href="sentence_detail_ai.html" data-id="N" data-score="56.52">` ，同一 `data-id` 的多个 `<a>` 属于同一片段，按 id 聚合。

**额度**：免费版 `0元/千字仅支持中文每天5篇`。一次迭代消耗 1 篇。

## 六、失效清单（别再试）

| 假设 | 实测 |
|---|---|
| 句长分布像人就能过 | 判黑 33.7 字 vs 判红 31.9 字，无差别 |
| CoV 高就是人 | CoV 22.2% 的交火稿得 **96.17%** |
| 多模型交替写能打散指纹 | 四模型分句交火 **96.17%**，比正常写更差 |
| 设问是人类特征（lieflat R=17） | 加了 6 个设问，**全部判红** |
| 短评句是 AI 特征 | 判黑片段里短评更多（15% vs 4%） |
| 比喻是人类特征 | 装饰性比喻判红，承担论证的判黑 |
| 堆具体名词就能降 | 只降 11.6 点，卡在 50~60 |
| LLM 改写 AI 文本 | 叠加指纹，越改越高 |
