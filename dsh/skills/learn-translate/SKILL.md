# learn-translate · 方舟学习引擎 v6

> **这个技能是什么**：把「读原始资料」与「把东西真正学进去」压成同一条流水线。翻译不是目的，翻译是取料——译完的双语讲义就是学习形态的输入；反过来，讲透一个概念的判据（四问）也决定了译文里哪些地方必须加注。
>
> **本文件只放「每次都会用到」的东西**：判据、闸门、路由。README 式的历史、变更叙事、某一次事故的全过程，一律下沉到 `references/`——**历史不参与决策，读它是成本**。变更记录见 `references/changelog.md`。

## 0 · 交付前八条闸门（最高频违规点，先记这一节）

八条全部来自实测违规，按被违反的频次排序。**任何要落盘的产物，逐条打勾再发。**

| # | 闸门 | 判据（可机械检查） | 出处 |
|---|---|---|---|
| 1 | **术语每次出现都带括号** | 正文里每个技术名词写成 `English（中文）` 或 `中文（English）`；**不是只首现加**。交付前跑「裸用术语计数」，必须为 0 | 铁律 3 |
| 2 | **双语是行内嵌入，不是分段对照** | 一段中文里嵌 English term，禁止「英一段 / 中一段」并排。密度 30–40 行/页、6–7 中文字/行 | 铁律 1、4 |
| 3 | **信息不丢** | 原书插图、例题、图注全部保留；习题（Exercises）可跳，例题必译；字幕引文另有一条——**必附中文翻译** `（翻译：……）` | 铁律 9、10、26 |
| 4 | **数学格式** | 行内 `$...$`、块级 fenced math block；**禁 `$$`**、禁 Unicode 上下标；KaTeX 全量解析 0 失败 | 铁律 6、32 |
| 5 | **断言真跑过** | 凡能用代码验证的（反例、数值、符号、量纲），贴真实 stdout；不能验证就写「未经检验的结论」 | 铁律 36 |
| 6 | **落盘位置解析过** | `ls -la` 父目录 → `readlink -f` 解链接 → `find -maxdepth 3` 枚举同名目录，三步都跑过才写 | 铁律 39 |
| 7 | **交付物是 md，不是散文件** | 图 base64 内嵌；源码同目录；两端 `md5sum` 一致；聊天里只留结论 + 路径 | 契约 19、铁律 31、41、42 |
| 8 | **该画图就必须画，且四件套齐全** | 出现几何 / 包含 / 极限 / 不等式链 / 参数临界 / 反例 / 证明的唯一非等号步 → 必画；画就交齐视角 A、视角 B、静态总图、联动动图 | 铁律 40、43、44 |

**为什么把这八条提到最前**：技能原有的 47 条铁律是编年史顺序（哪年哪次踩了什么就加一条），而违规不是均匀分布的——2026-10-22 至 11-22 一个月的会话记录里，用户追加纠正集中在四类：术语格式（4 次）、落盘路径（4 次）、该画图却没画（多次）、「要注意技能要求的每一个点，不要忽略了某个地方」。闸门表按频次重排，就是为了让最容易忘的四类在开工第一屏就撞见。

| 形态 | 输入 | 产出 | 主体流程 |
|---|---|---|---|
| **A · 翻译** | PDF / DOCX / HTML 讲义、教材章、习题集、字幕 | 行内双语 Markdown（可再渲染 PDF） | 第 4 节 A 流水线 |

## 2 · 四问锚点（形态 B 主干，缺一问即未完成）

任何「讲清楚 X」都按四问输出，顺序固定：先本质，后公式。

**Q1 本质**——剥掉所有符号与术语，它到底断言了什么？写一句**可判真假**的话。只能复述定义，说明还没懂。

**Q2 公式**——给**最小充分形式**（不是最一般形式）+ 逐个符号的现实所指。数学一律「本质 → 公式 → 跨学科连接」，先直觉后符号；不掩盖核心思想，不为化简牺牲正确性。

**Q3 现实承重**——现实里**哪个系统的哪个功能**由它实现？必须给到「组件 + 该功能」的具体锚点，并做**消失测试**：假设这个概念/机制不存在，哪个系统会在哪一步崩、退化成什么复杂度、报什么错。
- 合格：`cache line`（缓存行）承重于「CPU 取指与访存带宽」；消失 → 每次访存直落 DRAM，Memory Mountain 谷底变成峰值。
- 不合格：「cache 很重要」「广泛用于计算机系统」——名词搬运，未做承重分析。
- 定位不到 → 写 `[未定位]` + 待查方向，**禁止编造场景**（铁律 27）；同时标之前必须真检索过（铁律 38）。

**Q4 拓展进阶**——四层各给至少一条**可点开**的坐标（课程节号 / arXiv id / 源码 `文件:行` / 教材章节）：
- **L1 上游**：它依赖哪条更基本的事实？抽掉那条，它是否还成立？
- **L2 平行**：另一个领域里同构的机制，精确到「课程名 + 概念 + 连接路径」（铁律 15）。
- **L3 实现**：真实代码/硬件里它在哪个模块、哪一行（**读源码 > 读博客**）。
- **L4 前沿**：当前开问题、边界失效处、今天就能做的验证实验。

四问的完整写法、消失测试题库、卡点卡、Anki 生成、学习会话模板 → `references/learning-engine.md`。学习法的证据分级（哪些「科学学习法」其实只是社区口传）→ `references/learning-science.md`。

模型全流程统一 **v4.1 flash**（`deepseek-v4.1-flash`）；正文写「v4.1 flash」，命令写完整 id。

| # | 契约 | 一句话执行 |
|---|------|-----------|
| 1 | **通道** | dsh 环境用内建 `subagent` / `subagent_fork` / `workflow`。**思考强度是参数不是形容词**：`subagent` 暴露 `reasoning_effort`（`low/medium/high/max`），effort id 由 adapter 拥有**不许猜**，先 `list_subagent_models({provider, model})` 看枚举。审稿/审计一律 `max`，**同时**在 prompt 里写「以最高思考强度」——参数管采样预算，措辞管行为方式 |

## 4 · 两条流水线

### A · 译文流水线（8 步）

1. **任务上下文确认**——5 个元问题（文档类型 / 受众 / 期望效果 / 格式约束 / 其他约束）
2. **全资源搜索**（铁律 13）——PocketWiki + ZIM 优先，再查盘区 / 主力机 / 网络
3. **读取源文件**——`pdftotext` → `-layout` / `-raw` → `pdfplumber` → TextIn 兜底
4. **搜字幕**——先读目录结构，不做纯关键词匹配
5. **分析与排版规划**——结构 / 功能模块 / 术语 / 标题层级 / 标签配色
6. **翻译主体**——小规模（≤50 页或 ≤500 行英文）主代理直译；大规模走第 7 步
7. **大规模路径**——25×2 波次：翻译 25 / 页级审计 10 + 写注 3 + 交叉引用 2 / 超强审计 / 格式审计；主代理只切分·派发·合并·回填
8. **最终审查**（所有规模必做）——超强审计 + 格式审计（均审计+修复一体）→ Reader Testing 盲检 → 错误记忆落盘

各步参数、审计清单、报告模板、判级标准 → `references/workflow-core.md` + `references/workflow-large-scale.md`。

### B · 学习流水线（5 步）

1. **定锚**——这一步回答哪个问题？在方舟体系里是**中轴 / 前置 / 出口**？答不出生态位就先别往下推。
2. **取料**——按第 6 节资料层顺序检索；命中即注入，缺料先补料再讲，**不许凭印象讲**。
3. **四问**——Q1 本质 → Q2 公式 → Q3 现实承重（+消失测试）→ Q4 四层拓展。
4. **验证**——给一条可复现验证路径（数值实验 / 构造反例 / 跑源码 / 小证明），跑不通就改口。AI 是**可质疑的推导引擎**，不是知识库。
5. **落盘**——锚点卡（Markdown + 双链）+ `[我的卡点]`（卡在哪 / 为什么卡 / 怎么破）+ 复习队列（Anki tsv 可选）。默认 `C:/Users/27063/Desktop/课程文件/锚点卡/<课程>/<概念>.md`，Anki tsv 同目录 `_anki/`（放进课程文件树，才随课程 repo 备份与同步）。

### 与相邻技能的分工

| 技能 | 管什么 | 与本技能的分工 |
|---|---|---|
| `course-summarizer` | 整本书 / 整门课的重构 | 它做**全局**结构，本技能 B 形态做**单点**四问 |
| `learning-method` | 通用学习法条目（费曼 / 间隔 / 刻意练习 / Zettelkasten） | 它给方法论名词，本技能给**可执行判据 + 证据级别** |
| `tool-offline-wiki` / `tool-pocketwiki` | 离线维基检索工具 | 本技能的资料层**调用**它们，不重复实现 |
| `thinking-modes` | 压缩 / 推演 / 全貌三种输出模式 | 输出**风格**由它定，内容**结构**由本技能四问定 |

## 5 · 四十七条铁律（判据全集）

分八类：**格式 1–10 / 分工 11–13 / 来源 14–18 / 流程 19–26 / 学习 27–32 / 派发与并发 33 / 学习纪律 34–36 / 交付纪律 37–47**。每条只留判据与必要的定量锚点；事故全过程在 `references/verification-discipline.md` 与 `references/changelog.md`。

### 格式类（1–10）

**1 禁止英中分段对照**（最高铁律）——一段中文里嵌 English term，不是「英文一段、中文一段」并排。

**2 英文句首禁止**——每段以中文开头，English term 只出现在句子内部。

**3 术语一律 `English（中文）`，每次出现都带括号**——不存在「首现加括号、后文省」这种规则（2026-11-18 明确纠正）。交付前跑裸用计数，0 才算过（脚本见 `references/verification-discipline.md` 第 10.1 节）。

**4 不合并句子**——逐句译；密度 30–40 行/页、6–7 中文字/行。低于此即概括式伪翻译。

**5 LaTeX 环境内不翻译**——`\begin{...}` 到 `\end{...}` 之间的内容原样保留。

**6 数学格式**——行内 `$...$`；块级 fenced math block（三个反引号 + `math`）；**禁 `$$`**；禁 Unicode 上下标。**禁写 `\[2pt]`**：`\[` 会被 markdown-it-katex 当成 display math 起始符，一处真错在 MarkText 里放大成多处「无效数学公式」。

**7 标题标记在行首**——`#`、`>`、`-` 必须在行首，前面不许有空格或中文。

**8 禁止 `<div>`**——HTML 块会破坏渲染，用 Markdown 原生语法。

**9 非必要习题跳过、例题必译**——Exercises 保留英文原文；Example / 例题全部译。

**10 字幕引文必附中文翻译**——🎥 标注 + `（翻译：……）`。

### 分工类（11–13）

**11 小规模主代理直译、大规模分派**——≤50 页或 ≤500 行英文由主代理直译；超过则按第 4 节 A-7 的 25×2 波次派发，主代理只切分·派发·合并·回填。

**12 全任务统一 v4.1 flash**——`deepseek-v4.1-flash`；pro 已弃用。「一档模型 + 分档思考强度」是铁律 22。

**13 全资源搜索必做**——开工前搜双盘区 + 主力机 + 本机 PocketWiki / ZIM + 网络；找不到就补料，**不许凭印象讲**。

### 来源类（14–18）

**14 补充内容必须有真实来源**——每条补充标等级（见铁律 29）；无来源的一段删掉，不补。

**15 译者注禁止甩名词**——连接精确到「课程名 + 具体概念 + 连接路径」，一条 800–1200 字；禁止空洞赞美。

**16 每 200 行自检 + 交付前 grep 扫英文行首**——两处常规闸门，不能只做一处。

**17 全量完整输出、不交增量补丁**——交付即完整文件；补丁式改稿只用于机械替换（铁律 25）。

**18 绝不硬编码编号**——章节号、页码、块号从源文件读取，不许手写死值。

### 流程类（19–26）

**19 每步备份**——改大文件前先 `.bak-<时间戳>-pre-<改动名>`。

**20 审计 = 审计 + 修复一体**——直接输出修订后全文，禁止只列意见清单。

**21 不绕道另一台机器派子代理**——dsh 环境里内建的 `subagent` / `subagent_fork` / `workflow` 就是通道（2026-11-19 实测：`dsh-remote` 只是 Android 客户端 apk，不在 PATH）。**旧版的「全转主力机 dsh」已退役**——它和契约 1 冲突，以契约 1 为准。

**22 一档模型 + 分档思考强度**——「不换模型」与「换 effort」是两回事：换模型（改 `provider`/`model`）会**删掉继承的 effort 并重新 prefill**；换 `reasoning_effort` 不动路由、不破 cache。难任务靠资料·prompt·多轮 + `max`。**配置侧两条生效条件**：改 `cordis.patch.yml` 的 `modelSelectionSettings` 后必须重启 Electron，且必须开**新会话**（旧会话拿不到新字段）——细节与源码位置见 `references/changelog.md` 的 v5.5 条。

**23 派发前主代理先查 wiki**——PocketWiki + 离线 ZIM 命中结果注入 prompt，子代理不重复查。

**24 扫描版必做视觉核对**——无文字层时用 v4.1 flash 图像输入逐页转写，作权威原文比对。

**25 替换式改稿覆盖公式边界 + 交付前公式体检**——替换串必须跨过 `$...$` 边界；改完跑公式体检（铁律 32 的 KaTeX 全量解析）。

**26 原书插图是内容，不得静默丢弃**——图注翻译不能替代图本身。首选裁切保留（`references/image-pipeline.md` 第 10.2 节路线 A，`page.get_pixmap(dpi=300, clip=...)`）；文字描述只是 bbox 定位失败时的退路，且必须写明原因。实测：20 页 14 张图一次做完共 1.2 MB——「图多」从来不是不裁的理由。

### 学习类（27–32）

**27 四问必答**——Q1 本质 / Q2 公式 / Q3 现实承重（含消失测试）任一缺失即未完成。定位不到写 `[未定位]` + 待查方向，**禁止编造现实场景**。

**28 拓展必给坐标**——L1 上游 / L2 平行 / L3 实现 / L4 前沿各至少一条，必须可点开（节号 · arXiv id · `文件:行`），不许写「详见相关资料」。

**29 来源分级**——A 一手（论文原文 / 源码 commit / 官方文档 / 标准 / errata / 作者讲义与 PSet solution）> B 二手（教科书 / 综述 / 他人讲义）> C 三手（博客 / 视频 / 论坛）。三手只用于找入口与直觉，**结论必须回 A 核对**；每条补充内容标等级。学习法主张同样分级：[MA] 元分析 / [RCT] 随机对照 / [EXP] 实验 / [CS] 案例 / [OBS] 观察 / [D] 社区口传——[D] 级只能借外壳，不能当理由。

**30 未学概念必须详析，不许只甩名字**——遇到他没学过的概念（群论 / 环论 / 拓扑 / 非标准分析 / metric space 等）**不是不能提**，而是必须就地建桥：用他已有的节点（6.042J 离散 / CSAPP / 6.006 算法 / Strang 线代 / Thomson 实分析 / 概率论）讲清它是什么、解决什么原始问题、边界在哪；讲不清就标 `[待建桥]` 先不引入。**禁止的是「丢一个名词就走」。**

**31 讲解图是论证不是装饰**——帮助理解的图必须过五条硬标准，每条都有可判定判据：① **删除测试**：删掉这张图，论点是否变弱？不变弱就是装饰；② **遮标题测试**：遮住标题仍能看出结论；③ **标注贴身**：数字标在对象上，不放远处对照表；④ **一图一主张**；⑤ **图注是可被反驳的主张句**（「这是一个球」不可反驳，「内圆右缘 1.366 越过大圆边界 1」可反驳）。数学图另有专规：截断轴必标 break、离散量不画光滑曲线、误差必须画、黑白打印可读、色盲调色板（Okabe-Ito / Paul Tol / CUDO）。**源码必须入库**，禁止只交裸 PNG。**视觉复核是阻塞步骤不是收尾抽查**：出图 → `read_image` 读 PNG → 过五条判据 → 才允许写进 md；**代码跑通 ≠ 图合格**（2026-10-24 实测：三处硬缺陷全部漏到交付）。细则 → `references/figures.md` 第 8 节。

**32 渲染校验**——公式交付前必须用**目标渲染器同款 KaTeX** 全量解析：行内 `$...$` 与 math 块逐条 `renderToString({throwOnError:true})`，基线 0 失败；再跑逐行美元符号奇偶检查，以及反斜杠方括号与双美元符的残留扫描。脚本模板 → `references/figures.md` 第 8.4 节。**校验器自身会假阳性**（行内代码里的双美元符被当公式），所以失败项要逐条人工确认。

### 派发与并发纪律（33）

**33 批量派发与并发纪律**——并发上限 8（`subagent.maxActiveSubagents` 本机已放开到 32，但重型实施 4 路是拐点：32 逻辑核下 1 路 410ms、4 路 462ms、8 路 684ms、16 路 1126ms，>8 路溢出到 E-core 而 E-core 单线程慢 2.8 倍）；单 worker 上限「教材 2 块=40 页 / 讲义解答 3 份 / 幻灯片 5 份」；派发前必 `ls -la` 目标文件（已存在且 >30 KB 一律不覆盖，改审计）；交付后必跑「md5 + 页标记连续性 + 跨文件重复」三查；补注类必跑「SRC 每行按序是 DST 子序列」无损检查；**prompt 里禁止预设章节归属**（让 worker 用 fitz 抽首末页自证）；**同一路径绝不允许两个 worker 同时写**。详见 `references/batch-dispatch.md`。

### 学习纪律（34–36）

**34 一次讲透，不考他**——听到问题就给完整答案：**本质一句话 → 完整定义（可照抄）→ 直觉 → 为什么必须是这个形式 → 例子与非例子 → 历史坐标**。**禁止出题、留空位让他填、反问「你怎么想」、问「你要不要先自己试试」**——他没学过的概念，问了也答不上。练习权在他手上：他说「给我几道题」才给。「先攻后守」是他自己的学习方法，不是模型对他施加的流程。

**35 一般化要说清代价**——在 R 上讲就默认只在 R 上讲；确实存在更一般的版本时**可以说**，条件是一句话交代它一般化在哪里、为什么现在用不上。不能只丢名字然后走人。

**36 断言必须真跑**——凡能用代码验证的断言（反例、数值实验、符号计算、量纲检查），必须用 bash 跑 python（或对应运行时）并把**真实 stdout** 贴出来；判据是**可复现**（他重跑一遍要逐字一致）。不能验证的，明说「这是未经检验的结论」，禁止当事实陈述。

### 交付纪律类（37–47）

**37 控制字符体检**——交付前必跑：BEL(0x07) / BS(0x08) / TAB(0x09) / VT(0x0B) / FF(0x0C) 在 md 正文里计数全 0。起因：heredoc 把 `\alpha` 折成 BEL + 「lpha」，肉眼不可见、grep 照样命中、到 KaTeX 才炸且报错指不出源头。**LaTeX 一律用 write 工具落盘**；必须走 shell 时用 `chr(92)` 拼接，写完立刻体检。**为什么只能靠控制字符体检**：heredoc 把 `\` 折成 `\` 时矩阵会静默塌成一行，而 **KaTeX 照常渲染、不报错**——渲染校验在这里是瞎的。

**38 `[未定位]` 必须先检索**——标之前完成一次针对性检索，写清检索词与命中情况；确实查不到写「已检索 N 次无一手来源」。**禁止用「材料不够」当挡箭牌**。

**39 落盘前解析真实路径**——写文件前必跑三条：① `ls -la <目标父目录>`；② `readlink -f <目标目录>` 解析符号链接；③ `find <根> -maxdepth 3 -name "<目录名>"` **枚举所有同名目录**。起因：`桌面/待处理文件夹` 与 `桌面/课程文件/待处理文件夹` 两处同名，连续 4 轮放错。**用户说「不对」时先枚举候选，不要只挪一层**。语义判据：`桌面/待处理文件夹/` = 未完成（与 `桌面/课程文件/` 平级）；`课程文件/<课程>/` = 已归档。

**40 数学内容必须配图**——凡讲解涉及**本身带视觉结构**的对象（几何形状、球 / 开集 / 包含关系、区间、函数图像、「越来越近」的收敛、三角不等式的绕道比较），必须给图。判据：① 遮挡标题后仍能看出结论；② 图上每个关键量（圆心、半径、漏出去的点）标出数值；③ 对比型讲解画并排双图、同一坐标轴范围；④ 图 base64 内嵌（契约 19）+ 出图后先 `read_image` 过判据再写进 md。**反例**：只报区间端点、让读者自己在脑子里画数轴。**什么时候不画**：纯符号变形、离散计数、单个数值事实、已在前一张图里表达过的同一内容。判据一句话：**这个结论能不能「看」出来？能看出来就必须画；画的每一笔都能被一句公式替代，就不要画。**

**41 讲透即出文档**——形态 B 的讲解默认交付 md 文件（含 Q1–Q4 + 内嵌图），聊天只留结论、路径与一处关键图。**「已经很清楚了」不等于交付**：聊天里的推导不可检索、不可引用、不能带图，复习时等于不存在。

**42 媒体产物必须打包进 md 并双端落盘**——静态图与动图一律 base64 内嵌（`mdimg.py --mode embed`）；源码（.py / .html / .tex）同目录入库；视频过大无法内嵌时，md 用相对路径引用 + 视频同目录存放，并在 md 顶部注明「视频为外置文件」。交付后双端落盘（Windows `D:\Desktop\课程文件\待处理文件夹\` + Linux `~/桌面/待处理文件夹/`）并两端 `md5sum` 比对一致。**禁止只交散落的 png/gif/mp4**——散落文件不可检索、不可引用、移动即断链，而他在 Linux 端打开的是 md。

**43 两张图的各自主张**（与 44 是同一件事的两层，43 管内容、44 管数量）——(a) **几何+长度一体图**：上半画对象（圆 / 球 / 区间），下半把关键长度抽成标尺，用一条竖直参考线贯穿上下，让「边界」与「标尺端点」落在同一条线上；(b) **参数图**：横轴放变量（如 $p$），画临界线（如 $\rho=0.5$），让「从哪开始失效」变成曲线的穿越点。两张各说一件事：第一张说「现在越界多少」，第二张说「从哪开始越界」。**禁止用两张同几何、只换配色的图冒充两种视角**。排版硬指标：**成图宽 ≥1600 px、字号 ≥12 px**、标注分开放置并加白底、换行必须是真换行（写 `\n` 会渲染成字面 `
`）。

**44 出图即四件套，不许缩水**——**只要决定画图**，就出齐四样：视角 A 静态图（对象）/ 视角 B 静态图（参数或第二状态）/ 静态总图（A、B 并排 + 标题条 + 中缝分隔线）/ 联动动图（单画布双面板，共享一个 `render(t)`）。**禁止只交单张图，禁止把两段动画各录一遍再拼**（那不是联动，是两个动画并排）。第二个视角优先「对象 vs 参数」；对象没有参数维度时，用同一对象的两个取值 / 两个状态充当（$p=1$ 与 $p=2$、开集与闭集、收敛与不收敛），把其中一个变成横轴变量。拼接参数、`render(t)` 骨架、逐帧渲染命令、标尺「从 y 量」规则 → `references/figure-production.md`。

**45 证明交付只给链条**——问「定理怎么证明、怎么推出结论」时，交付物就是四段：① **名字归属**（谁证了什么 + 卷期页码 / DOI + 来源等级，先查证再写）② **每条事实的陈述 + 证明 + 它在链条哪一步用** ③ **汇合编号步**（每步标依赖）④ **前提承重表**（删掉哪条前提、崩在哪一步、退化成什么）。**禁止附诊断表 / 审稿清单 / 社区对照 / 四问拓展 / 验证链**——那些是元讨论不是证明。体量判据：**行数 ≈ 命题数 × 20**（实测：535 行 / 294 KB 被判「太繁杂」，224 行 / 13 KB 被采用——同一件事差出 **20 倍体量**，就是「把 200 行能说完的事撑到 3 万字」）。**格式不豁免**：术语 `English（中文）` 每次带括号——首版 225 行内容被判「无可挑剔」，却因整篇纯中文术语被当场退回。

**46 交付前必须派 subagent 以最高强度审查**——**哪怕只有 500 字也要审**。触发条件：任何要落盘的 md（讲解、证明、锚点卡、翻译件）。**强度和参数双写**：`reasoning_effort: "max"` 进工具参数（决定采样预算），prompt 里仍写「以最高思考强度做」（决定行为方式）。两者缺一都不算照做。**审查不通过不改口、直接改文档再复查**。
按任务分档，不要一刀切：

| 任务 | `agent_preset` | `reasoning_effort` |
|---|---|---|
| 写注 / 扩写 / 翻译（把 200 字撑到 1000 字，靠模板与资料） | 默认 | 省略（默认 `high`） |
| 概念讲解 / 数学推导 / 四问锚点卡 | `learn` | 省略或 `high` |
| **审稿 / 审计 / 挑错** | 默认 | **`"max"`** |
| 侦察 / 统计 / 落盘 / 搬运 | 默认 | `low` 或 `medium` |

审查清单（逐条过）：① **判据的方向**——等号 / 推出号两边的量词方向是否一致（「闭包为空」≠「只依赖三条」，前者是 $\varnothing$、后者是 $\subseteq\{M_1,M_2,M_3\}$）；② **每句「于是」前面有没有真前提**——跳步、未声明假设、循环引用；③ **与源文的编号与体例**是否对得上；④ **术语** `English（中文）` 方向正确、每次带括号；⑤ **格式**——`\{` 与 `\}` 成对（漏写时 KaTeX 报 `Expected 'EOF', got '}'`）、禁 `$$`、控制字符 0；⑥ **断言**——凡说「所以 / 因此」的结论，前提里必须真有那一条。
派发模板：`subagent({ description: "审稿：<范围>", prompt: "<下面这段>", reasoning_effort: "max" })`；prompt 正文：「你是审稿人。**以最高思考强度**逐行审查 `<文件路径>`，按上面六条清单挑错，只报**具体行号 + 错在哪 + 应改成什么**，不要泛泛评价，不要重写全文。**先核对范围**：哪些条目是本轮新写的、哪些是历史遗留，简报里的行号可能已过期——拿不准就自己 `grep` 确认。**审稿人的判断也可能是错的**（实测：审稿人报「全文 grep 无此句」，实际那句话真实存在），所以每条结论都要附上你自己跑过的定位证据。」

**47 引用必须自包含，每节先给动机**——两条同源：**读者手里只有这一屏**。
① **禁止纯编号代指**：`§1 的递归`、`事实 3(i) + 5`、`由 (ii)` 这类写法一律不合格——读者要回翻才懂，而回翻本身就说明写法失败。规则：每个编号后自带一句话内容，写成 `第 1 节的 recursion value（递归值）：terminal node（终局节点）直接取 payoff（收益），internal node（内部节点）按行动者取 $\max$ 或 $\min$`。交付前 `grep -c '§'` 目标 0。
② **每个引理小节先写「这一节要干什么」**：固定写法 = 先列要接起来的几个量**各自层次**（哪个已经能算 / 哪个是优化 / 哪个是执行结果）→ 为什么只能靠不等式接 → 为什么拿这个量当标尺 → 量词顺序为什么是这个形状。**动机段不是水**：省掉它等于让读者自己补，而读者补不出来。
③ **记号首用处给「是什么」，不只给「叫什么」**：`argmax` 与 `max` 的区别（返回集合 vs 返回数；等式两边都是集合）、「参数 vs 被优化的变量」（固定一个坐标得到一元函数，与偏导数 $\partial f/\partial x$ 同一动作；配一段 `best_response(s0)` 最省字）、`position（位形）`（棋盘上的局面 + 轮到谁走；perfect information（完美信息）下 position 与 history（历史）一一对应，用图论说就是 position = node（节点））。

## 7 · 图：什么时候画、交什么（判据在此，做法在 references）

**第一步永远是写一句主张句**：这张图要让人相信的那句话是什么？它必须**可被反驳**——「内圆右缘 $1.366$ 越过大圆边界 $1$」✓；「这是一个球」✗。**写不出主张句 → 不画。**

**硬触发（出现任一必须画）**：几何对象或点集 / 包含·越过·相交 / 「越来越近」与极限 / 不等式链的几何含义 / 随参数变化且有临界值 / 反例构造 / 证明里唯一的非等号步。

**不必画**：纯符号变形、离散计数、单个数值事实、已在前一张图里表达过的同一内容。

**出图 = 四件套**（视角 A / 视角 B / 静态总图 / 联动动图），判据见铁律 44；两张图各自该说什么见铁律 43；五条硬标准见铁律 31；**视觉复核的顺序与判据见 `references/figures.md` 第 8 节**。

做法（拼接参数、`render(t)` 骨架、逐帧渲染命令、标尺「从 y 量」规则、环境实测）→ **`references/figure-production.md`**。

## 8 · 派发 prompt 的五条硬约束

派 worker 时 prompt 必须满足（2026-10-28 实测——主代理自己发明了两条要求，直接违反铁律 9 与铁律 26，导致 6042J 前 19 块把大量习题逐译、四书 671 处插图全成文字占位）：

1. **铁律逐字引用，不许转述。**「非必要习题跳过、例题必译」不能写成「习题也要译」；「原书插图是内容，不得静默丢弃」不能降级成「图可以写成文字」。
2. **图的首选是裁切保留**：`page.get_pixmap(dpi=300, clip=fitz.Rect(...))` → `_assets/fig_<pdf页号>_<name>.png` + 双语图注；**文字描述只是 bbox 定位失败时的退路**，且必须在降级表写明原因。
3. **三条完整性闸门必须写进 prompt**：① 页标记数 == `pdf.page_count`，且页码集合 == `{start..start+19}`（不是「连续」就算过——18 页的块也连续）；② 节号序列（`^## \d+\.` / `^### \d+\.\d+`）与源 PDF 逐项比对，缺项显式报告；③ 每页「译文字数 / 源页非空白字符数」的异常值逐个解释。
4. **要求块尾写「下一块的衔接点」**：章节 + 编号 + 页码映射 + 文本层新映射。**worker 崩了也不丢信息。**
5. **`**[译注]**` 标签必须独占一行**，正文从下一行开始——否则按行统计的正则会把标签后的整行当标签的一部分吃掉，字数统计系统性偏低 80–90 字。

**子 agent 不是一次性的**：交付后能用 `send_message` 继续驱动它做补图 / 改口径 / 返工局部，比重新派更省。细则 → `references/batch-dispatch.md`。

## 附：本技能自己的维护规则

- **一份真相**：同一清单只存一份。主文件只放「每次都要用的判据」，历史与做法下沉到 `references/`，两处不重复写。
- **改完必须同步，两个方向都要**：① 改 `references/` 的条文却没同步第 5 节的摘要 → 摘要变成旧文本；② 改第 5 节的判据却没同步 `references/ironrules-*.md` 的原文 → 主文件说 A、它指向的原文说 ¬A。**两个方向都实测出过**（前者 2026-11-15，后者 2026-11-22 审稿时发现铁律 21 就是这个状态）。
- **`_proposal-v6/` 之类草稿目录不进技能**：它只在「准备替换主文件」时存在，替换完即删。
- **真身只有一份**：`~/.dsh/skills` 与 `~/.reasonix/skills` 都是指向 `~/ai-skills` 的 symlink，改这里即全端生效——**没有「同步三端」这个动作**（照 `ls -la` 的实际输出为准，不信文档）。
