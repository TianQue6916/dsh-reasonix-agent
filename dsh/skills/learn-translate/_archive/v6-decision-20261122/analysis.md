# learn-translate 技能体检与压缩方案（2026-11-22）

> 结论先行：**该压，而且压的是三块「历史」而不是「判据」**。主文件 61,059 B / 433 行 → 草案 37,031 B / 327 行（**−39.4%**），逐条铁律一条没少，判据一条没弱。搬出去的两块（变更记录 13,178 B、图的制作规格 10,789 B）合计 39% 字节，只在特定场合才需要。

## 一、它到底有多重（换算成真实成本）

`skill_load` 把 `SKILL.md` **整份**注入 context。系统里量到的原文是 **17K tokens**——这是每次加载都要付的 prefill，也是每次加载后一直占着窗口、参与注意力的空间。

| 事实 | 数值 | 来源 |
|---|---|---|
| `learn-translate` 的加载次数 | **135 次**（全站第 1；第 2 名 `study-coach` 只有 5 次） | `~/.dsh/storages/skill-usage.json` |
| 每次加载的正文体积 | 17K tokens（61,059 B UTF-8） | 本会话注入的 skill 内容 |
| 单次加载可省 | 约 **6.7K tokens** | 37,031 / 61,059 比例折算 |
| 总量级 | 135 × 6.7K ≈ **0.90M tokens** 的纯规则文本注入 | 上两行相乘（cache 命中后 prefill 便宜，但**窗口占用与注意力稀释**不打折） |

**为什么「省 token」不是这里的主要理由**：用户的历史纠正里没有一条是「太贵」。真正的理由是下面这条——

> 「要注意技能要求的每一个点，不要忽略了某个地方。」
> —— 用户在 11 月说过的话，原样在会话记录里。

一份 433 行、47 条铁律、22 个 reference 的文档，被读完的概率随长度单调下降。**臃肿的真实代价是「该遵守的条款被跳过」，不是「多花钱」。**

读法三条：

1. **主文件是唯一高负载入口**——它决定了 90% 的行为，所以「主文件臃肿」比「reference 臃肿」严重一个量级。压缩优先级按这个排。
2. **`references/` 平均每个文件一个月被打开 0–7 次**。它们不是垃圾（打开时都是救命的），但**不能指望它们承担「每次都要遵守」的条款**。凡是「每次都要做」的，必须留在主文件正文里。
3. **两张路由表 22 + 26 行，指向 22 个文件，其中 7 个一个月零打开**——路由表本身在制造「读不完」的感觉。真正需要的是「任务 → 1 个文件」，不是「任务 → 一句话描述 + 一个路径」。

### 2.3 用户实际在纠正什么（决定「突出哪些」）

对 792 个会话里的 `user/message` 做纠正语检索（`没有按` / `不符合` / `又出现` / `还是没有` / `再说一遍` / `忽略了` 等），逐条读人工抽样的命中：

| 纠正类型 | 原话（节选） | 对应条款 |
|---|---|---|
| **术语格式** | 「你这个文档那写得很好，无可挑剔，但是你没有按照技能 /learn-translate 里面说的属于规范，术语是中文（英文）这样做啊」（11-18） | 铁律 3 |
| **落盘路径** | 「你傻逼吧，我再说一遍，是桌面的待处理文件夹里面的????????」（连续第 4 次） | 铁律 39 |
| **该画图没画** | 「你都没有画图啊，你这种解释方式好难懂」 | 铁律 40 / 43 / 44 |
| **条款被跳过** | 「要注意技能要求的每一个点，不要忽略了某个地方」 | 全体 |
| **体量失控** | 「实在是太繁杂了」（535 行 / 294 KB 的交付被判退） | 铁律 45 |

**这四类被违反的次数，与它们在原文里的位置顺序无关**——术语格式（铁律 3）排在文档第 21 行，路径（铁律 39）排在**第 406 行**，图规格排在 147–325 行之间的深处。违反频次最高的三条，两条埋在文档后半。

这就是新版把「七条闸门」提到第 0 节的依据：**不按编号顺序，按被违反的频次。**

### 铁律叙述怎么压（举例）

原文（48 行一条，3598 B）：
> **37 控制字符体检**——交付前必跑：BEL(0x07)、BS(0x08)…… 起因：heredoc 把 \alpha 折成 BEL + 「lpha」，肉眼不可见、grep 照样命中、到 KaTeX 才炸且报错指不出源头。……

新版（124 B）：
> **37 控制字符体检**——交付前必跑：BEL(0x07) / BS(0x08) / TAB(0x09) / VT(0x0B) / FF(0x0C) 在 md 正文里计数全 0。**LaTeX 一律用 write 工具落盘**；必须走 shell 时用 `chr(92)` 拼接，写完立刻体检。

删掉的是「起因」与「为什么难查」，保留的是**可执行动作**与**唯一正确做法**。为什么这样删是安全的：起因属于「怎么发现这条规矩」的过程史，`references/changelog.md` 与 `verification-discipline.md` 里两处都有完整版；而执行时需要的只是「跑哪条检查、用什么工具写」。

## 五、风险与怎么验证「行为等价」

压缩的风险只有一个：**某条判据被压没了，而它恰好是下次要用的那条。** 三种失效方式与对应的防法：

| 风险 | 防法 | 本次结果 |
|---|---|---|
| 铁律被漏抄 | 逐条比对编号 1–47，一条不缺 | 47/47 齐全 |
| 定量锚点丢失 | 逐条找数字：行数比、密度、并发拐点、图尺寸、像素宽 | 全部保留（见 §3 末段） |
| 路径写错 / 指向不存在的文件 | 交付前跑引用存在性检查 | 20 个引用全部存在 |
| 公式渲染失败 | 用目标渲染器同款 KaTeX 全量解析（`references/tools/check-katex.js`） | 20 条公式，0 失败 |
| 控制字符污染 | BEL/BS/TAB/VT/FF 计数 | 全 0 |
| 分类改动导致找不到条目 | 五类标题 + 每类起止编号写死在标题里 | 格式 1–10 / 分工 11–13 / 来源 14–18 / 流程 19–26 / 学习与交付 27–47 |

### 自查抓到并已修的七处（这是「压完没压坏」的实际证据，不是保证）

用三种机械比对找的：① 定量锚点集合差（旧版 40 个 `数字+单位` 锚点逐个核）；② 英文 token 集合差（旧版 376 个 → 新版 293 个，93 个缺失逐个分类）；③ 章节编号与交叉引用一致性（`第 N 节` × `## N ·`）。

|---|---|---|---|

| 2 | 铁律 46 分档表丢了「200 字 → 1000 字」这个刻度 | 判据弱化 | 补回 |

第 5、6、7 条是从「英文 token 集合差」里捞出来的：它们的共同特征是**搬走的那块历史里夹着一条下次还要用的操作知识**。这类东西最容易在压缩时静默消失，因为它们看起来像叙事。

**一个诚实的保留**：这一版**还没跑过真实任务**。行为等价目前只有「文本级」证据（条目齐、锚点在、引用通、公式过），没有「任务级」证据（拿新主文件真跑一次翻译 + 一次讲解，与人读旧版的结果对比）。建议替换后第一次用它做真活，就把那次产物当回归样本；出问题按下面的回滚路径退回。
