# 批量派发与并发纪律（v4.5 新增，2026-10-28 一整夜实测）

> 适用：一次派 4 个以上 worker 翻整本书 / 整门课。这一夜实际跑了 136 份 / 4.5 MB、并发 8 个 worker，
> 下面每条都是**踩出真实损坏之后**才写下的判据，没有一条是推测。

## 0 并发上限（硬约束）
dsh subagent **active child limit = 8**。第 9 个报 `subagent limit reached (active child limit: 8)`。
⇒ 超过 8 的任务必须排队成波次，不要试图一次派完。

## 1 单 worker 工作量上限
| 内容类型 | 上限 | 依据 |
|---|---|---|
| 教材切块（20 页/块） | **2 块 = 40 页** | 实测 2 块产出 45–120 KB / 600–1200 行，已到上下文舒适上界 |
| 讲义 / 解答（5–15 页/份） | **3 份** | |
| 幻灯片（<20 页/份） | **5 份** | |
| 单份 > 50 页 | **必须切块**，不许整本交给一个 worker | |

**分批落盘**：每完成 ≤3 份立刻写文件 + 跑该目录 KaTeX + 报一次数字。**禁止攒到最后一次性输出**——长上下文里后半段质量会塌。

## 2 派发前必做：`ls -la` 目标文件
**这一夜重复派发发生 3 次**（p241-260 / p321-340 / p341-360），每次两个 worker 各花一整轮做同一批 40 页，后写者静默覆盖前者。

```
ls -la "<输出目录>/<你的目标文件>"
```
- 已存在且 **>30 KB** → **绝对不覆盖**，改做审计（只读），报告里注明「已被他人完成，我未动」
- 已存在但 **<30 KB 或缺页标记** → 可补写，文件头注明「初稿由他人完成，我补写 pXXX-pYYY」
- 不存在 → 正常翻译

## 3 交付后完整性三查（KaTeX 全绿不等于文件没被冲掉）
```
1) md5 逐文件
2) 页标记连续性：<!-- ===== pNNN ===== --> 应无缺号
3) 跨文件重复：同一页标记不得出现在两个文件里
```
**真实事故**：MacKay p161-180 被两个 worker 互相覆盖（64718 B ↔ 63128 B），而 KaTeX 全程 0 失败。
（另一个假警报：worker 报「64718 B」与 python `len(str)` 的「46119」差 1.4 倍，那是中文 3 字节/字，不是数据丢失。）

## 4 补注 / 改写类的机器化无损判据
任何**往已有译文里插入内容**的 worker 必须跑：
```
SRC 的每一行，按序是否都是 DST 的子序列 → 必须 100% True
```
```python
def is_subsequence(src_lines, dst_lines):
    it = iter(dst_lines)
    return all(any(l == d for d in it) for l in src_lines)
```
**它抓到过的真实 bug**：注被插在「整行中间」（用 `anchor+len` 定位），把原文两行劈成四段——人工核对很难发现，子序列检查立刻 False。

**目录隔离**：翻译 worker 只写 `<书名>/`，补注 worker 只写 `<书名>_补注/`，互不越界。

## 5 派发 prompt 里禁止预设章节归属
**这一夜对「某页块属于哪一章」判断错了 6 次**（源书认错 1、页码公式方向 1、章节归属 4）。

规矩：prompt 里**不写**「这两块应在 Ch.X」，改成固定一句：
> 「章节归属以 PDF 文字层实际内容为准；worker 应先用 `fitz` 抽首末页与页眉自行确认起止章节，并在文件头写明。」

需要给参考时只写**前序 worker 已实测确认**的内容（附页码映射与证据页码）。核源料成本 = 一条 `python -c`，比返工便宜两个数量级。

## 6 源料鉴定流程（别凭文件名推断）
```
用 fitz 读前 3 页 + 每页页脚 → 确认真实书名/版本/页码偏移
```
**真实事故**：把 `Information-Theory/03-textbook/book.pdf` 当 Cover & Thomas 派了 3 个 worker，
实际是 **MacKay《Information Theory, Inference, and Learning Algorithms》**（页脚印 `Copyright Cambridge University Press 2003 … mackay/itila/`）。
页码偏移也是猜反过：Boyd 是 **书页 = PDF − 14**，MacKay 是 **书页 = PDF − 12**，都靠页眉数字实测确认，不靠猜。

## 7 heredoc 会静默损坏矩阵（最危险的一类）
**`bash heredoc` 把 LaTeX 的 `\\`（换行分隔符）折成单个 `\`**：

```latex
\begin{bmatrix} a & b \\ c & d \end{bmatrix}   →   \begin{bmatrix} a & b \ c & d \end{bmatrix}
```

矩阵从 2×2 **静默塌成一行**，而 **KaTeX 完全不报错**（因为 `\ ` 是合法的空格命令）。单条 heredoc 超约 11 KB 还会被截断，留下半句话。

⇒ **矩阵/对齐公式必须用 write 工具写文件再 `cat >>` 追加，禁止 heredoc**；交付前 grep `bmatrix|aligned|cases` 确认分隔符是双反斜杠。

**同类静默损坏**：python 源码里写 `\binom` / `\beta` / `\approx`，
`\b` 与 `\a` 会被当成**转义序列**，变成退格与响铃控制字符，KaTeX 报 `Unexpected character`。
⇒ 反斜杠命令一律用 `chr(92)` 拼，或先写模板文件再读入；**改完立刻重跑 KaTeX，不能等收尾**。

**元证据（三次踩同一个坑）**：本文件第一版就是 heredoc 写的，第 7 节自己的示例被吃成 `egin{bmatrix}` / `inom` / `eta` / `pprox`；
第二版改用 `\\begin` 字面量重写，结果 `\b` 又被解释成退格，整节仍坏；第三版才全部改用 `chr(92)` 拼接成功。
**文档在描述这个坑的过程中，连踩三次。这就是它必须是铁律而不是建议的理由。**
## 8 校验工具本身也会骗人
`extract-formulas.py` v1 用 `re.sub("```.*?```", "", d, flags=re.S)` 剥围栏 —— 这条正则在真实讲义上会把大段正文一起吞掉，
**某份文件 126 个 `$` 只剩 10 个，漏检 82% 公式**。修成行级状态机后全库公式数从 92,636 涨到 105,815（+14%）。

⇒ 自建校验工具必须用**已知计数的文件**交叉验证：
```
我的抽取器 vs 独立计数（math 块数 + 行内 $ 对数）vs worker 自报数
三者对齐才算可用
```

## 9 每批必做三道审计
1. **格式**：KaTeX 真渲染 `files_with_errors = 0`
2. **静态规范**：英文分段 / `$$` 残留 / 未译英文行占比（>15% 要人看）
3. **内容层**（LLM，每 2–3 批抽 3–5 份）：覆盖完整性 / 数学正确性 / 术语一致性 / 注质量 / 注水 / **原文自身错误**；判 A/B/C 且理由可复核

## 10 译注（译者注）判据
**每条注都要有一个「可被反驳的失效对象」**——写不出「抽掉它哪步崩、退化成什么方法」就不合格。
- **200–400 字**，且至少含一个公式或一个数（重要处可到 800）
- 可点开落点：教材 §号 / 页号 / 课程节号 / arXiv id / 码 `文件:行`；定位不到写 `[未定位]`
- 挂载点挂到用户已掌握节点，禁越级（群论/环论/拓扑/非标准分析）
- 黑名单：`很重要` / `广泛用于` / `是基础` / `值得注意` / `非常关键`
- **标签纪律**：自写内容一律 `[译注]` + 绿色 `<span style="color:#1e8449;">`，**严禁蹭原书的 `[remark]/[theorem]` 标签与配色**（撞色后读者分不清哪句是原作者写的）

## 11 每批报告必须含「最不放心的三处」+「没敢下注的地方」
这一夜里最有价值的产出，往往不是注本身，而是 worker 列出的「我记不准所以留空」清单——
它直接定义了下一轮该补什么，也避免「听起来对但其实是编的」内容混进译文。

## 12 重建内容必须给可复算验证
凡按语义重建（文字层毁版、矩阵错位、表合并单元格）的内容，必须给一条**别人能照着算一遍**的验证：
- 校验位：ISBN `Σn·x_n mod 11 = x_10`（两个实例都对上）
- 计数：weight enumerator 总和 = $2^{N-K}$、Golay $1+23+253+1771=2048=2^{11}$
- 数值：`log₂φ = 0.6942`、integral image 用 2×2 例子复算
- 反例：`diag(1,-1)` 与 `diag(1,1)` 证 $\mathrm{tr}(AB)=0 
ot\Rightarrow AB=0$

### 6.1 `pdftotext` 必须带 `-enc UTF-8`（否则落成 Latin-1，`≤ ∈ α ≠` 全丢）

### 6.2 某些 PDF 存在**系统性符号错映射**（不是丢，是映射错 —— 比丢更危险）
**实测样本：Boyd《Convex Optimization》官方 Solutions Manual**

| 原符号 | 文字层给出的 | 危害 |
|---|---|---|
| `⪰` | `0` | 广义不等式变成数字零，整式无意义 |
| `⪯` | `b` | 同上 |
| `≠` | `=` | **等式与不等式被抹平，结论可能整个反掉** |
| `∉` | `∈` | 否定被吃掉 |
| `Σ` / `Π` | 孤立 `i` 或空 | 求和消失，公式量级完全错 |

同类已知样本：MIT 6.006 讲义的 `pdftotext` ToUnicode CMap 损坏（δ/π/∞/∈/≤ 全丢，必须用 PyMuPDF）。
Boyd 教材正文的 `≤ ≥ ∈ ⊆` 也会整体丢失（LaTeX 直出 PDF 的字体映射问题）。

⇒ **纪律**：拿到一份新 PDF，先抽一页含不等式的公式，**把文字层输出与原页图像（`pdftoppm`）对照一次**，确认符号映射是否可信；
不可信就整份改用 PyMuPDF，或对关键页做视觉核对。**「公式对但方向反了」是这一夜出现频率最高的隐性错误。**

## 13 worker 失败 = 必须当轮重派（不是汇报）

`subagent` 返回 `failed before it finished. It left no closing message.` 时：
1. **立刻检查落盘**：`ls -la <目标文件>` —— 常见的结局是**一个字节都没写**。
2. **当轮重派**，不要把「失败」当成只需汇报的事件（真实事故：Boyd p461-500 的 worker 挂掉后，主 agent 只汇报了失败，并发空了 3.5 小时）。
3. **重派时减小工作量**：从 2 块（40 页）降到 1 块（20 页）。教材密度高（Boyd 实测 331–505 汉字/页），40 页已超上下文。
4. **加重中途落盘**：prompt 里写死「每写完 5 页就 `cat >>` 落盘一次，不要攒到最后」——崩了也留下一半，比零强。

## 14 续跑协议：turn 内撑住，别靠「等」

**dsh 没有定时器** —— turn 结束就真停。所以「预估休眠时间」只能这样实现：

每轮收尾前按顺序做，**不许跳过**：
1. `list_agents` → 有没有新 `finished`？
2. 有 → 当轮落地 + 当轮补派（同源下一块）
3. 只有 `running` 没新交付 → `timeout 90 sleep 90`，回到 1（禁止「只回复不动作」收尾）
4. 队列空 → 从清单取下一项补派，维持 3–5 并发
5. 仅当「无 running + 队列真空」才收尾

反例：worker 中途 failed，主 agent 只汇报失败就收尾 ⇒ 并发空 3.5 小时、零产出。

## 9. 派发 prompt 的反面教材（2026-10-28 实战，主代理自己踩的）

这一节记录的是**主代理（不是 worker）犯的错**：prompt 写错 → worker 严格执行 → 大面积返工。

### 9.1 三个错误，都是「自己发明硬要求」

| 我写进 prompt 的 | 技能原文 | 实际后果 |
|---|---|---|
| 「Problem **要逐题译**」 | 铁律 9：**非必要习题跳过、例题必译** | 6042J 前 19 块把大量纯练习题逐题译了，**白烧 token** |
| 「图用 `[Figure N：…]`、不可复原就明说」 | 铁律 26：**原书插图是内容，不得静默丢弃**；`image-pipeline.md` §10.2 路线 A = `get_pixmap(dpi=300, clip=Rect)` 裁切保留 | **四书 671 处插图全成文字占位，零张真图** |
| 把 worker 当一次性，交付即弃 | 子 agent 可 `send_message` 继续驱动 | 每块完工就丢，重派要重载技能 + 重抽 PDF + 重自证页码 |

**教训一句话**：**派发 prompt 里的每一条硬要求，都必须能在技能里找到原文**；找不到就别写。转述一律视为篡改。

### 9.2 图：实测成本远低于直觉

`6042J p381-400` 是第一个按铁律 26 正确做的块：

| 项 | 数值 |
|---|---|
| 页数 / 图数 | 20 页 / **14 张图** |
| 落盘 | `_assets/fig_<pdf页号>_<name>.png`，300 dpi，共 **1.2 MB** |
| 正文引用 | 16 处 `![]()` + 双语图注（有编号者给原文图注逐字 + 中译） |
| 用时 | 与不裁图的块同量级（一次做完） |

⇒ **「这块图太多」从来不是不裁的理由。** 正确顺序永远是：`get_drawings()` 提线段端点 → 算 bbox → `get_pixmap(dpi=300, clip=...)` → 落盘 → `![]()` + 双语图注。文字降级只是 **bbox 定位失败**时的退路，且必须在降级表写原因。

### 9.3 三条完整性闸门（3 行正则，堵住整页漏译）

1. `len(re.findall(r'<!-- ===== p', md)) == pdf.page_count` 且页码集合 == `{start..start+19}`
2. 节号序列（`^## \d+\.` / `^### \d+\.\d+`）与源 PDF 抽出的序列逐项一致，**缺项显式报告**
3. 每页「译文字数 / 源页非空白字符数」的异常值逐个解释（整页图、空白页、扉页、页归属错位都算合法解释，但必须写出来）

**真实事故**：MacKay `p321-340` 块把 PDF p336 整页 + p337 上半页**连标记带正文一起丢了**（第 25 章开篇 + §25.1 两个问题定义 + 五个公式 + 一个 Exercise）。
主代理一开始看到「18 个标记 vs 20 页」还判断成「只是漏标，内容在」—— **错了**。真正的判据是 grep 该页首行/末行的关键词，**全 0 命中就是内容缺**。
闸门 ①② 本来一秒就能堵住；闸门 ③（字数比）事后回溯时 13 个异常页**全部**对应真实情况，**零误报**。

### 9.4 worker 攒批 = 唯一的「零产出」死法

同一批两个 worker 对比：

| | 攒批的那个 | 每 5 页落盘的那个 |
|---|---|---|
| 首 5 页落盘 | 从未 | 5–10 分钟 |
| 结局 | **100 分钟零产出，被 `interrupt_agent` 中止** | 一次通过 |

⇒ prompt 必须写死：**「开工 25 分钟内必须写出前 5 页并 `cat >>` 落盘，之后每 5 页一次，绝不攒到最后」**。

### 9.5 worker 崩了，信息未必丢

`6042J p361-380` 的 worker 报 `failed before it finished`，但：
- 产出**完整**（20 页标记 / 21 条译注 / KaTeX 23,067 条 0 失败 / 六项格式全 0）
- **块尾的「§8 给下一块的衔接点」把章节、编号、页码映射、文本层新映射全写全了**

⇒ 这就是为什么 **§8 必须是 prompt 的硬要求**：它让「worker 发报告失败」不等于「信息丢失」。

### 9.6 探活与放弃的时间线（实测校准）

| 时长 | 动作 |
|---|---|
| 0–25 分钟 | 正常，不打扰 |
| **>45 分钟无文件增长** | `send_message` 探活：问「进行到哪一页 / 卡在哪 / 还要多久」，并要求「已写好的立刻落盘」 |
| **>90 分钟无落盘** | `interrupt_agent` + 重派（连探活都没回，别等） |

### 9.7 交付后先想「能不能 send_message 让它自己改」

同一批里，两条口径修正是**用 `send_message` 追发给在跑的 worker** 完成的，没有重派：
- 「习题不必逐题译」
- 「图必须裁切保留，不许降级成文字」

**重派的隐性成本**：重新加载技能、重新 fitz 抽 20 页、重新自证页码映射、重新踩一遍文本层坑。这些都白做。

## ★★★ 派发前必查：官方勘误表（v4.7 新增，2026-10-29）

**这是逐块审计的第 0 步，比任何自检都快。**

| 教材 | 官方勘误 | 实测 |
|---|---|---|
| MacKay ITILA | `https://www.inference.org.uk/itprnn/corrections.txt` | **curl http=200 / 28 KB / 859 行**；解析出 **194 条带页码勘误，覆盖 32 块中的 31 块** |
| Boyd 凸优化 / 答案手册 | `https://web.stanford.edu/~boyd/cvxbook/`（errata 页） | 待拉 |
| 6042J 离散数学 | MIT OCW 教材页 / 作者习题解答 | 待拉 |

**为什么必须做**：worker 会看到「原书说 X、图上画 Y」这类矛盾，**不知道是原书错就会去「修」译文**，把对的改错。
实例：`p.87 Fig 4.14 caption "1, 2, 100" → "1, 2, 1000"` 是**原书已知错误**；`p.69 Figure 4.2` 称重后 `"8-"` 与 `"*"` 应互换 —— 这些作者本人都记了，我们不要重新发现一遍。

**派发 prompt 必带三件套**：
1. **明确许可查证**：「术语 / 事实 / 公式有疑问就用 `web_search` 或直接 `curl` 一手 URL（作者主页 / errata / 官方 docs），别硬猜」。
2. **贴该块的勘误条目**（从核查表里取，见 `~/.dsh/tools/refs/MacKay-勘误核查表.md`）。
3. **「查不到就标 `[待核]`，别编」**。

**处理规则**：译文复现了原书错 → 修正并在该处加 `> **[勘误]** 原书此处有误：<原文> → <勘误>（来源）`；译文已是对的 → 也加一行说明，避免后人再查。

**注意**：技能旧结论「本机 curl 打外网不通（DNS 被注）」**已过时**（2026-10-29 实测 200）。检索顺序里「网络搜索」这一步现在能直接拿一手文件。
