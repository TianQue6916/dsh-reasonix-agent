# 第 3 章 译者注指南（[note] 写法）

> 🚨 **写注用 dsh flash v4.1（铁律 12，2026-09-10：v4.1 flash 全面超越 pro，全任务统一）**

## 3.1 注的类型（6 种）

1. **跨课程连接**：将当前内容与用户知识体系中的其他课程连接。**可用的连接锚点**：离散数学 6.042J（等价关系、偏序集、数论）、CSAPP（浮点表示、机器级编程、内存层次）、CLRS 算法导论（二分搜索、分治、复杂度分析）、线性代数 Strang（矩阵方法、SVD）。具体到课程名和章节，并解释连接路径。
2. **第一性原理洞察**：解释定理背后的核心直觉，追溯最基础的假设。回答"为什么必须这样？"用用户已经理解的简单概念作为脚手架搭建新概念。
3. **证明策略模板**：把证明方法抽象为可复用的思维模板（ε/2 技巧、ε-剥离法、峰点论证、分组放缩、归纳三步法、supremum sandwich 等）。**命名模板**（如"上确界夹逼法""ε-剥离法"）便于记忆复用。
4. **历史与人物**：数学家为什么这么想？当时要解决什么具体问题？对后世的影响。标注具体年份（如 Bolzano 1817、Cauchy 1821、Weierstrass 1872）。⚠️ 2026-09-03 用户校准：**以机制/概念为主，历史只作点缀**，不要堆年表（"查知识不是查历史"）。
5. **拓展前沿**：相关的更高级概念。**必须从用户已知概念出发解释**，不得裸甩名词。如果用户没学过前置知识，要么搭建脚手架解释，要么暂时不提。
6. **图解注（配图辅助理解，2026-09-03 用户要求）**：对空间/结构/流程类概念（子问题 DAG、状态转移表、递推树、依赖图、谱系嵌套图等），**自己生成示意图或找现成图**辅助理解。可以：① 用 matplotlib/graphviz/ASCII 艺术/Mermaid 手绘概念图嵌入注中；② 从离线维基/OCW 原文/教材找现成插图（标注来源）；③ 生成 SVG/PNG 存到译文同目录 `assets/` 并用 Markdown 图片语法引用。图要小、聚焦一个概念、配一句图注，不做装饰性配图。

> 🖼️ **图解注的完整规范见references/image-pipeline.md**（2026-09-23 增补）：§10.2 保留原书插图（视觉模型给百分比 bbox → PyMuPDF `clip` 裁切 → `assets/` + Markdown 引用）、references/image-pipeline.md §10.2.5 图内印字三选一决策树、references/image-pipeline.md §10.3 自创图（判定清单 + 四条生成通道 + 视觉模型"生成→复核→纠错"闭环）、references/image-pipeline.md §10.4 实测坑清单。**原书图一律不丢**（🚨 铁律 26）。

## 3.2 质量标准（必须严格遵守）

- **每条注 800-1200 字**（配图/公式/字幕引文不计入），信息密度高，不凑数、不注水；写成可独立阅读的"小专题"——机制展开 + 例子 + 连接
- 跨课程连接要明确提及**课程名 + 具体概念 + 连接路径**（如"你在 6.042J 学过的等价关系，在这里就是 rational number 的相等定义——同一个等价类内的表示被视为'相同'"而非"这在群论中叫商集"）
- 🚫 **禁止甩名词**——不得只提高级概念名而不解释。写注前先查 `memory`（`global/academic-level-and-teaching-style.md`）确认用户学业水平
- 分布均匀，每个关键定理至少一条注
- 结合视频字幕中的教授口语化讲解，增加"教学现场感"；引用字幕时使用 `🎥` 标注来源（🚨 铁律 10：每条引文必须附中文翻译）
- 📖 交叉引用：指向用户已有的讲义（如 L01/L02/L03）或教材（如 CLRS §x.y）
- 🖼️ **配图辅助（2026-09-03 用户要求）**：空间/结构/流程类概念尽量配图——自己生成（matplotlib/graphviz/Mermaid/ASCII）或找现成图（离线维基/OCW 原图/教材插图，标来源），存译文同目录 `assets/` 引用；图聚焦单一概念并配图注

## 3.3 拓展连接的铁律（PS01 教训）

用户对拓展知识**有强烈兴趣**（跨学科连接是人格画像核心特征），但**禁止甩名词**——不能只提一个高级概念的名字而不解释。这是 PS01 初版犯的错误（甩了群论/商环/拓扑学/非标准分析等用户没学过的概念）。

**每条拓展连接的处理规则：**

1. **先查学业水平**——写注前必须用 `memory` 工具查询 `global/academic-level-and-teaching-style.md`，判断用户是否已具备理解该概念的前置知识
2. **脚手架法**——如果用户没学过前置知识，要么从第一性原理构建解释（从用户已知的概念出发，逐步推导到新概念），要么暂时不提。**绝不裸甩名词**
3. **精确连接路径**——每条跨课程连接必须精确到：课程名 + 具体概念 + 为什么类比成立 + 区别在哪。不是"这在群论中也有"而是"你在 6.042J 学过的等价关系，在这里就是 rational number 的相等定义——同一个等价类内的所有分数表示被视为'相同'。群论中把这个结构称为'商群'，但核心思想你已经会了。"
4. **拓展 ≠ 炫耀**——拓展的目的是帮用户看到知识地图的全貌，不是展示你懂多少高级概念。如果一个拓展概念需要 3 页纸才能讲清楚，而当前上下文只够提一句名字，那就不要提

## 3.9 卡点诊断注（可选）

`[note]` 中可包含 `[我的卡点]` 片段，预判读者（用户）可能卡住的位置："这里的直觉陷阱是……如果以为……就会……正确理解是……"。

## 3.10 费曼式注

当某个概念特别抽象（如 supremum、eccentricity），写一条**费曼式注**：用不超过 3 句话、不用任何未解释术语的方式向"高中生"解释它，然后指出它和正式定义之间的差距（即"知识缺口"——正式定义里的每个词在费曼解释里对应什么）。费曼式注 + 卡点诊断注配合使用：前者给直觉，后者标陷阱。

## 3.11 效率视角类比

用户对"漂亮算法"与效率敏感。数学证明策略注可加"效率视角"类比——"这个证明技巧相当于把复杂度从 $O(n^2)$ 降到 $O(n \log n)$：ε-剥离法避免了反复重新检查整个区间"。用算法复杂度语言给数学证明建立直觉，是用户的母语。

## 3.13 注工程：统计口径、回填与分工（2026-11-22 实测增补）

> 来源：LaLFD 九文件注工程一轮（85 组注，实测数据在 `~/.dsh/.learn/run/lalfd/`）。这一节全是踩过的坑，不是设想。

### 3.13.1 统计口径：`[note]` 块 ≠ 一条注

同一个项目里注有**三种容器形态**，只按块数统计会得出相反结论（实测：交接文档按 `gen_notes_expand.py --scan` 报「37 注 / 7 个 md 0 注」，真实是 541 个 `[note]` 块 = 真注 123 + 短注 174 + OCR 脚注 284）：

| 形态 | 例子 | 特点 |
|---|---|---|
| 行内 blockquote | `> <span style="color:#1e8449;">**[note] Note（译者注：…）:**</span> …` | 一条注一块，插在正文行之间 |
| 节末小节 | `## 本节译者注` 下 3 段 `[note]` | **一条注横跨多块**，一节合计 600–8800 字 |
| 标题式 | `### [note] page_211 ｜ 主题` | 注标题独立成行 |

**判据**：
1. 抓注 = blockquote 块内首 200 字含 `color:#1e8449`（区别于 `#7f8c8d` 图注/页说明、`#2471a3` 结构标签）。
2. 聚合**注组**：相邻块行距 ≤6 且中间无 `## ` 标题 → 同组；**判定单位是组内合计 cjk**，不是单块。
3. 必须分列「真注 / 短注 / OCR 脚注」三张表；OCR 脚注（含 `OCR` 或 `残作`）永远不参与扩写。

### 3.13.2 功能性短注不扩（灌水判据）

图注、目录说明、交叉引用（「本页示例在下一页继续」）、OCR 修正脚注，扩到 800 字只能靠复述正文。
判据：`is_func()` = 含 `OCR`/`残作`，或首 300 字含「图 / Figure / 目录 / 见下页 / 下一页 / 交叉引用 / 本页为」。
实测：一份文件里 6 个 34–87 字的块全是这类；把它们算进待扩清单会让工作量虚高 2 倍。

### 3.13.3 组号是派生索引 → 必须 sha256 锚定

组号由 `short_groups(file)` 每次现算：目标文件一改（合并/拆分/某组已扩到 ≥800 掉出 short 列表），组号整体漂移，而**字数/格式校验发现不了错位**（新块本身合格，只是插错地方）。

判据：
- 任务书/prompt 头部写 `TARGET_SHA256=<生成那一刻的 hash>`
- 回填强制 `--expect-sha256`，不给或不符合 `exit 2`、**一个字节都不写**
- 派发时给的行号必须取自**生成 prompt 那一刻**的 `groups.json`，不能凭记忆（实测：一条注的真实锚点是 2341 行的 `## The Sylvester Equation`，凭记忆给的 2165 会悬空）

### 3.13.4 回填：块级替换，不是区间替换

组区间 `[首块起点, 末块终点)` 内可能夹着**正文行**；按区间整段替换会把正文删掉，而「区间外零改动」查不出来（正文在区间内）。

正确做法：**首块位置换新注、其余 note 块删除、块间非 note 行原样保留**。
无损判据升级：替换后「**全文非 note 行序列**」必须与原文逐字一致（比「区间外一致」强，顺手挡掉误删正文）。

### 3.13.5 两条体检闸门（都是实测踩出来的）

1. **控制字符必须含 TAB**：`ord(c) < 32 and c != '\n'` —— **不能**写 `c not in '\n\t'`。
   实测：`\times` 的 `\t` 被折成 TAB，`$2<TAB>imes3$` 只剩裸 `imes`，KaTeX 必炸，而 `grep`/白名单体检全过。
   成因不一定是 heredoc：上游生成脚本的 raw string 里可能已经是真控制字符。
2. **逐行 `$` 奇偶**：未配对的 `$` 会让公式正则（`\$[^$\n]{1,300}\$`）跨段吞掉正文，使 cjk **虚低**。
   实测：一份注按现口径 732 字、按严格口径 902 字，差的 170 字正是被一对未配对 `$` 夹住的段落。

### 3.13.6 分工判据：判断 vs 生成（不是「文本进文本出」）

| 任务性质 | 归属 | 理由 |
|---|---|---|
| **判断**：审稿、挑错、验收、来源判定 | 本机 `subagent` + `reasoning_effort:"max"` | 强度可调；能跑 python 复算；能读仓库上下文 |
| **生成**：写注、扩写、**按清单改注**、翻译、润色 | 远程 GUI 队列（WorkBuddy）；队列不可用时本机 `subagent`，**`reasoning_effort:"high"` 显式写**（不要靠「省略」，附实测见下） | 强度不可调但不需要；严格指令 + 固定输出格式即可，且不占本机算力 |

> **「按清单改注」为什么不是 max**：判据已经由审稿人给出（「这行错了 → 改成那样」），写手只做替换与自检，不需要重新判断。给它 `max` 是浪费采样预算，而且会让它开始「顺便重写别的部分」。
> **为什么不写「省略」**（2026-11-22 实测）：`list_subagent_models({provider:"commandcode-goat", model:"deepseek/deepseek-v4.1-flash"})` 只列出 5 档枚举 —— `off / low / medium / high / max`，**工具不报默认值**。所以「省略 = high」是未经检验的断言，技能原先那句「省略（默认 `high`）」应视为错误；一律显式写 `high` 或 `max`。
>
> **反面实测（2026-11-22 本轮）**：同一批活里，`7315eb41`（按 28 条审稿改 part001 四注）用默认 effort、`eea2c11d`（按 39 条审稿改 part002 十注）被我误给了 `max` —— 同一性质两种强度，这是执行不一致，不是设计。教训：**分档看「谁在判断」，不看「文本进文本出」**；审稿人 max，写手默认，两者别混。
| **工具链**：任务书、回填、校验、dupcheck、KaTeX、commit | 本机脚本 | 需要文件系统与 git |

**联网前移**：写注要查一手来源（铁律 7/29/36），但远程队列的搜索不可复现（给不出可点开的 URL）。做法是**本机先 `web_search` 落 `sources.json`，prompt 里塞好并明写「不准自己上网查；空的写『未能一手核实』」**。
