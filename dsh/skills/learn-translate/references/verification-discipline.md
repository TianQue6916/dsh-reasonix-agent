## 1. heredoc 折反斜杠：控制字符是隐形炸弹

**现象**（本轮连踩两次）
- `cat >> f.md <<'EOF'` 里写 `\alpha`，落地成 `BEL(0x07) + lpha`；`\beta` → `BS(0x08) + eta`；`\times` → `TAB + imes`；`\frac` → `FF + rac`。
- `pmatrix` 里的行分隔 `\\` 被折成 `\`，矩阵静默塌成一行，**KaTeX 可能不报错**（`\` 在 cases 里恰是换行符）。

**为什么危险**：文件肉眼完全正常（控制字符不显示）、`grep 关键词` 照样命中、KaTeX 只在真渲染时炸，且报错指向 `Unexpected character`，看不出源头。

**判据（交付前必跑，基线全 0）**
```python
b = open(path, 'rb').read()
for name, ch in [('BEL', 7), ('BS', 8), ('TAB', 9), ('VT', 11), ('FF', 12)]:
    assert b.count(bytes([ch])) == 0, (name, b.count(bytes([ch])))
```
（TAB 只在 md 正文里禁；代码块内允许，按需放行。）

**武器**：LaTeX 一律用 write 工具落盘；必须走 shell 时用 `chr(92)` 拼接；写完立刻跑体检，别等 KaTeX。

## 2. 先证伪验证器，再证伪命题

**现象**：SPNE 检验用「**整棵树**的收益」去判某个节点的偏离，一次跑出 **80 个假违例**（还附 43 个零和树违例）。根因不在数学：根没走那条路时，下层节点怎么选都不改变整棵树收益 ⇒ **不可达节点的空威胁被当成合法均衡行为**。

**判据**：出现「量级不对」的违例（几十个，而不是一两个）时，**先怀疑验证器**。数学命题很少错得这么整齐。

**武器**：偏离检验必须锚在被检验节点自己的子树上（`play_from(t, profile, path)`），而不是整棵树。修完 80 → 0。

## 4. hatch 在黑白打印里会消失

**现象**：两张图 v2 用 `hatch='//'` + 浅灰底，缩到 50% 看**完全不可见**，四个格退化成同一块灰 —— 黑白打印直接失去区分度。`read_image` 复核才发现（代码跑通 ≠ 图合格）。

3. `find <根> -maxdepth 3 -name "<目录名>" 2>/dev/null` —— **枚举所有同名目录**，逐个判断用户说的是哪个（判据通常是「哪个下面已经有他提到的子目录」）。

**推论（重要）**：技能文档里的路径条目本身可能是错的 —— §A2 曾把「锚点卡」写成规范路径，照做必错。**以 `ls` 的实际输出为准，不以文档为准**；发现文档与实际不符时，改文档（三端同步），不要迁就文档。

**这次的正确判据一句话**：`桌面/待处理文件夹/` = 未完成任务区（与 `桌面/课程文件/` 平级）；`课程文件/<课程>/` = 已归档区。**没做完 → 前者；定稿后才进后者。**

## 9. Windows 上改写含中文的 UTF-8 文件的三种失败（2026-11-15 实测）

在本机（Windows + Git Bash）对 `D:/Desktop/.../backward-induction-*.md` 做原地改写，连续踩三坑：

1. **`sed -i` 替换串里的反斜杠被当转义序列** → `sed: -e expression #1, char 129: Invalid back reference`，**静默不执行**（md5 没变，还以为是成功）。
2. **`perl -i -pe` 直接把文件写坏** —— Perl 按系统 locale（GBK）读写 UTF-8 文件，中文变乱码；之后 `open(..., encoding='utf-8')` 报 `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xb8 in position 282145`。**这是数据损坏，不是报错即止**；恢复靠 `scp` 从 Linux 侧拉回同 md5 副本。
3. **Python `open(path,'w')` 在该目录报 `PermissionError: [Errno 13]`** —— 同目录 `os.access(W_OK)` 返回 True、shell 的 `>` 与 `>>` 正常、`attrib` 只有 `A`。疑似目录 integrity / 策略层拦截；**不要在这上面耗时间**。

**可靠写法（纯 shell 重定向，已验证）**：

```bash
{ head -n $((N-1)) "$F"; echo 'REPLACEMENT LINE'; tail -n +$((N+1)) "$F"; } > t.$$ && mv -f t.$$ "$F"
```

**校验三连**：`md5sum` 变了、`python -c "open(F,encoding='utf-8').read()"` 通过、`sed -n 'Np'` 内容正确。

**推论**：在 Windows 上改中文名 UTF-8 文件，**优先让 Linux 侧（`ssh`）做**；只用 shell 拼装时立即做 UTF-8 体检；`perl -i` 一律视为不可靠。

## 10. 证明类需求：给链条，不给外围（2026-11-17）

**两个版本，同一份 §五。**

| | 行数 / 体积 | 内容 | 用户反应 |
|---|---|---|---|
| v1 | 535 行 / 294 KB | 诊断 J1–J4、拆解 A/B、审稿清单、卡点、四问、社区对照 8 条、验证链 | 「这个文档实在是有点太繁杂了」 |
| v2 | 224 行 / 13 KB | 名字归属 + 5 条事实的陈述与证明 + 汇合编号步 + 前提承重表 + 来源分级 | 采用 |

用户要的那句话：**「这一部分只说了定理名字，没有说他们这些定理都是怎么证明的，也没说这些证明是怎么推出的这个结论」**。他要的是证明链本体，不是围绕它的元讨论。

**四段结构（照抄即可）**

1. **名字归属**：谁证的、证的什么、坐标（卷期页码 / DOI / JFM）、等级。**先查证再写**——本次实测原文把「完美信息 ⇒ 纯策略 SPNE 存在」挂在 Kuhn 1953 名下是**错的**：该挂 Zermelo 1913（Proc. 5th ICM, vol. 2, 501–504）或 MWG 9.B.1（p. 272）；Kuhn 1953（Contributions to the Theory of Games II, 193–216）管的是 perfect recall 下 mixed ⇄ behavioral 的实现等价，与本链条无关。
2. **每条事实**：陈述 → 证明（可逐步复算）→ **它在链条哪一步用** → 不用会崩在哪。
3. **汇合节**：编号步骤，每步标注依赖哪个事实。定理的「推出」关系只在这里出现一次。
4. **前提承重表**：删掉哪条前提、崩在哪一步、退化成什么（有限性 / 完美信息 / 零和 各一行）。

**禁止附**：诊断表、审稿清单、社区对照清单、四问拓展（Q1–Q4）、验证链、卡点清单 —— 除非用户点名要其中某一样。它们是元讨论，不是证明。

**体量判据**：证明文档行数 ≈ 命题数 × 20。本次 5 条事实 → 224 行合理；535 行说明掺了外围。

**另一条副产品**：文献本身也会误标。Edinburgh AGTA lec11 的 PDF 标题写「proof of Kuhn's theorem (backward induction)」，正文证的却是「对子博弈深度归纳构造纯 SPNE」——引用前看**证明内容**，不要只看标题。

### 10.1 内容对 ≠ 交付合格：术语格式不豁免（2026-11-18）

铁律 45 只管**写什么**（链条），不改变**怎么写**。铁律 1-3 的术语格式在证明文档里同样生效。

**实测**：225 行证明文档被用户判「写得很好，无可挑剔」，紧接着一句「但是你没有按照技能里说的，术语是中文（英文）这样做啊」—— 整篇用的是纯中文术语（`纯策略` `完美信息` `零和` `收益` `公共值`），一个英文原词都没给。

**合格形态**：`pure strategy（纯策略）` —— **每次出现都带括号，不省**（用户 2026-11-18 明确：「只首现加括号」这个说法他没说过，一直都要加）。正文其余部分仍是中文句子。**不是**整句英文，也**不是**只有中文译名，也**不是**英文裸词。

**机器判据（两条都要 0）**：① 中文术语裸用 ② 英文术语裸用（英文后没跟 `（中文）`）。

```python
import re
s = open(path, encoding='utf-8').read()
for t in ['完美信息','纯策略','混合策略','零和','收益','节点','策略','分支','历史','值']:
    for m in re.finditer(t, s):
        seg = s[max(0, m.start()-40):m.start()]
        if '（' in seg and '）' not in seg[seg.rindex('（'):]:
            continue                      # 在未闭合括号内 = 合法注释
        print('裸用', t, 'line', s[:m.start()].count('\n')+1)
```

本次实测：改前 23 处裸用 → 改后 0；KaTeX 123 条公式 0 失败、控制字符全 0、双端 md5 一致。

**替换工具的选择（本条是踩坑得出的）**：
- 用 GNU `sed` 读 → 写新文件 → `mv`，**不要 `perl -i`**（§9：它会按 GBK 重写，直接损坏 UTF-8）。
- `sed` 替换串里避免反斜杠：`s/maximin 值/maximin value/g` 可行；`s/maximin 值 \$\underline/maximin value $\underline/g` **静默不生效**（`\u` 被当转义）。含公式的行单独处理，或先替换短模式再核对。
- 改完必须三查：`md5` 变了、`open(..., encoding='utf-8')` 能读、裸用计数归零。

## 11. 引用必须自包含：禁止纯编号代指（2026-11-22）

**触发**：用户原话「像这样的表述我根本记不起来第一部分是什么，不要再代指了，最多提一下这是第一部分，还是不要这样省略比较好」。原文 15 处 `§n` + 11 处 `事实 N` / `(i)(ii)` 全是裸编号。

**根因**：编号不携带内容。作者刚写完，脑子里还挂着上一节；读者隔一屏就丢了。**能让读者回翻的写法，就是失败的写法。**

**合格判据**：

| 检查 | 命令 | 通过线 |
|---|---|---|
| `§` 裸用 | `grep -c '§' 文件.md` | 0（或每处后紧跟内容名，如 `第 5 节的 sandwich（夹逼）`） |
| 编号后有内容 | 人工扫 `事实 N` / `(i)` / `第 n 步` | 每个编号后都有一句「它是什么」 |

**对照表（本次实测）**：

| 不合格 | 合格 |
|---|---|
| `§1 的递归，在 T 上逐 node 算出来的数` | `第 1 节的 recursion value（递归值）：terminal node（终局节点）直接取 payoff（收益），internal node（内部节点）按行动者取 max 或 min，逐 node（节点）算下去` |
| `见 §8 第三行` | `见第 8 节承重表里 zero-sum（零和）那一行` |
| `（§5 用）` | `（第 5 节的 sandwich（夹逼）用的就是这一套）` |
| `【事实 3(i) + 5】` | `【事实 3(i)（存在性的下界一半）+ 事实 5（mixed strategy（混合策略）不必要）】` |
| `由 (ii)，s₁* 对一切 s₀ 都 ≤ v` | `由第 4.1 节的 (ii)（存在一个 pure strategy（纯策略），使 u₀ 对一切对手 pure strategy（纯策略）都 ≤ v），…` |

**同批另两条相邻教训**：

1. **每个引理小节先写「这一节要干什么」**：四句 = 要接的量的层次（可算 / 优化 / 执行结果）→ 为什么只能靠不等式接 → 为什么拿它当标尺 → 量词顺序为什么是这样。反例：直接甩 `∃s₀* ∀s₁: u₀ ≥ v(root)`，用户「很突兀的就出现了」。
2. **分阶段脚本必须链式**：`s = f1(s); s = f2(s); s = f3(s)`，一个脚本跑完再落盘。若各阶段各写各的 `.md` 而中间不 `cp` 回目标，后一阶段读到的仍是**原始文件**，前几阶段改动静默丢失（本次真发生过，重做才对齐）。
