> **一条流程两档参数**：小规模（≤50 页或 ≤500 行英文）主代理直接翻译；大规模（>50 页）25×2 dsh 任务分工。**流程末尾的 2.8 双审计是交付前必经环节（所有规模）。**
> 旧版第 2/3 章（2.0-2.9 与 8a-8j 双编号）已合一，本节统一编号。历史沿革见 HISTORY.md。

## 2.1 任务上下文确认（开工前 5 个元问题）

翻译开工前先确认：
1. **文档类型**？讲义 / 习题集 / 教材章节——决定习题是否保留英文
2. **主要受众**？用户画像（构建主义、跨学科连接狂热）——决定注的深度与脚手架
3. **期望效果**？读完能做什么——决定注的类型配比
4. **格式约束**？现有翻译稿风格、编号体系、交叉引用要求
5. **其他约束**？篇幅、术语表、交付路径

## 2.3 读取源文件（PDF 多模式提取）

- 先用 `pdftotext` 默认模式提取
- 若内容明显缺失（定理陈述不完整、节标题后直接跳内容），尝试 `pdftotext -layout` 或 `pdftotext -raw`
- 对比不同模式，合并互补内容
- OCR（Tesseract）仅对扫描版 PDF 使用，对数字生成 PDF 帮助有限
- 处理不了的情况（公式乱码、表格错乱）：`pdfplumber` 表格提取 → TextIn API 兜底（命令见references/toolchain.md 5.2）
- 使用顺序：`pdftotext` 默认 → `-layout`/`-raw` → `pdfplumber` → TextIn

## 2.4 搜索课程视频字幕（MIT OCW / OCW 类课程专用）

翻译 MIT OCW 讲义时，必须搜索字幕（如果课程有视频讲座）。字幕含教授的口语化讲解，是译者注的第一手素材。

**⚠️ 关键教训：不要只做关键词匹配搜索，要先读取目录结构。**

1. **列出目录结构**：连接主力机（control-main-machine / SSH），先看 `D:\b站视频\解析视频\` 有哪些子目录
   ```powershell
   powershell -Command "& { Get-ChildItem 'D:\b站视频\解析视频\' -Directory | ForEach-Object { $_.Name } }"
   ```
2. **识别课程目录**：B 站课程名可能与 MIT 编号不同。已知映射：18.100B → "数学分析"；6.006 → "【MIT6.006最新】算法导论(中英2020春)…"；18.046 可能包含实分析内容
3. **深入目标目录**：字幕在 `06-字幕文件\` 或 `06-字幕文件\终版字幕\`（独立 .srt/.webvtt），视频配套字幕在 `05-视频讲座\`（.srt + .zho-hans.srt 中英双语）
4. **读取字幕内容**：
   ```powershell
   powershell -Command "& { Get-Content 'D:\b站视频\解析视频\{课程目录}\06-字幕文件\终版字幕\V{NN} - {Title}.srt' -Encoding UTF8 }"
   ```
5. **提取关键教学片段**：教授对核心概念的口语化解释、直觉比喻、关键条件强调——写译者注的第一手素材（引用格式见铁律 10）
6. **编码注意**：中文路径用 `ForEach-Object { $_.Name }` 避免编码破坏；读取文件指定 `-Encoding UTF8`；输出可能 GBK，用 `decode('gbk', errors='replace')`
7. **已记录路径**：18.100B（数学分析）字幕在 `D:\b站视频\解析视频\数学分析\06-字幕文件\终版字幕\`，文件命名 `V{NN} - {Title}.srt` / `.zho-hans.srt`（记忆 `100b-subtitle-paths`、`bili-subtitles-path`）
8. **完整连接代码**（含 GBK 兜底 + SFTP 下载）见references/toolchain.md 5.5

主力机不可达或 SSH 失败时：记录错误后继续执行，**不中断流水线**。

## 2.5 分析与排版规划

- 识别文档结构：目录、章节、小节、段落
- 区分功能模块：定理、证明、定义、推论、例子、问题
- 识别关键术语、颜色信息
- 确定标题层级：`#` → `##` → `###` → `####`
- 为每个功能模块分配标签（见references/format.md标签表）
- 规划配色方案（见references/format.md配色表）

## 2.6 翻译主体（小规模：主代理直译；大规模：25×2 dsh 任务）

### 2.6.1 翻译通用规范（🚨 铁律 1-9 全程生效）

- 中文主体、无英文开句、术语 `English（中文）` 仅首次加括号、逐句不合并、LaTeX 环境不翻译、行内 `$...$` 与块级 fenced math block（无 `$$`）、标题标记行首、无 `<div>`、习题保留英文
- 逐段阅读原文后**直接用中文写作**，英文术语作为行内元素嵌入
- 每个功能模块前加蓝色标签（`<span style="color:#2471a3;">**[tag]**</span>`）
- 用 `---` 分割线分隔大段落
- 颜色匹配原文或按references/format.md配色方案处理
- **翻译节奏自检**：每输出约 200 行执行一次「英中对照自检」；交付前 `grep -nE '^[A-Z][a-z]+ [a-z]+' 输出.md` 扫英文行首（铁律 16）
- 逐句翻译密度标准：每页 30-40 行译文、平均每行 6-7 个中文字（铁律 4）

### 2.6.2 小规模路径（≤50 页或 ≤500 行英文）

- 主代理直接逐句翻译 + 排版输出
- **层次加工**：题目（原文）与答案（解答）均保持**完整行内双语翻译**；答案用 `>` blockquote 包裹实现虚化（MarkText 自动虚化），内容不缩减
- 代码块不受字体缩放影响，保持 1em
- 检查整体视觉层次：标题 → 题目原文 → 答案是否一眼可区分，原文是否被不当压缩
- **译者补充与替代解法（可选）**：若对题目或答案有更好的想法，或知道工业界/学术界更优解法，用专门标签标注后附加在原文之后（🚨 铁律 14：必须有真实来源）：
  - **`[note]`** — 背景知识补充、术语解释、上下文关联、历史沿革。深绿色（见 4.1 配色表）
    ```
    > <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 此算法在现代工业界已由 XX 替代。
    ```
  - **`[alternative]`** — 优于原文的解法、现代替代方案、工业界实践。深紫色（见 4.1 配色表）
    ```
    > <span style="color:#7d3c98;">**[alternative] Alternative（替代解法）:**</span> 实际工程中多用 YY 算法，时间复杂度更低。
    ```
  - 补充内容用 `>` blockquote 包裹，放在原文答案之后，与原文清晰区分。写完后二次审查（见铁律 14）
- 大规模路径见下节 2.7
