# Superpowers — 开发方法论

完整的软件开发方法论集合，来自 obra/superpowers（132K⭐）。在编码之前**必须**检查是否有适用的技能。

## 核心原则

1. **先技能，后行动** — 即使只有 1% 的可能性适用，也先检查技能
2. **流程技能优先** — brainstorming → 执行 → 测试 → 审查
3. **用户指令 > 技能 > 系统默认** — 用户始终有最高控制权

## 包含的子方法论

### 1. TDD（测试驱动开发）

对任何功能实现，遵循：
```
1. 写测试（先失败）
2. 写最少代码通过测试
3. 重构
4. 验证所有测试通过
```

测试类型：
- 单元测试（函数/组件）
- 集成测试（模块间交互）
- E2E 测试（完整流程）

### 2. 代码审查

提交前自我审查清单：
- [ ] 功能正确 — 代码做了该做的事吗？
- [ ] 安全 — SQL 注入？XSS？敏感信息泄露？路径遍历？
- [ ] 错误处理 — 所有路径都有错误处理？
- [ ] 并发 — 竞态条件？死锁？
- [ ] 资源泄露 — 文件句柄/连接是否释放？
- [ ] 向后兼容 — 现有调用者会 break 吗？

### 3. 系统化调试

```
Step 1: 复现 — 精确的复现步骤
Step 2: 隔离 — 找到最小复现场景
Step 3: 根因 — 使用二分法 / 日志 / 工具定位
Step 4: 修复 — 应用修复并验证
Step 5: 防止 — 添加测试防止回归
```

调试工具链：
- 日志分析（grep 错误模式）
- 二分法（注释/回退代码块）
- 最小测试用例（隔离问题）

### 4. 计划执行

```
1. brainstorming — 探索方案、权衡
2. 写计划 — 分解为可执行步骤
3. 子代理执行 — 并行分配独立任务
4. 验证 — 验证完成状态
```

### 5. 子代理驱动开发

适合多模块并行开发的模式：
1. 将大任务分解为独立的子任务
2. 每个子任务分配给独立子代理
3. 子代理完成后再合并集成
4. 全量测试验证

### 6. 验证在前完成在后

任务声称 "完成" 前必须：
- [ ] 所有测试通过
- [ ] 代码审查通过
- [ ] 无已知回归
- [ ] 文档已更新

### 7. Git Worktree 模式

并行开发多个分支时：
```bash
git worktree add ../project-feature feature-branch
```
每个 worktree 独立可测试，互不干扰。

## 执行优先级

1. 用户的明确指令（最高）
2. Superpowers 技能
3. 系统默认行为（最低）

## 红牌思维（立即停止并检查技能）

| 想法 | 现实 |
|------|------|
| "这只是个简单问题" | 问题也是任务，检查技能 |
| "我先探索一下代码" | 技能告诉你如何探索 |
| "这个不需要正式的流程" | 如果有技能，就用它 |

## 最常用的组合

| 场景 | 技能组合 |
|------|---------|
| 修 bug | 系统化调试 → TDD（加回归测试） |
| 加功能 | Brainstorming → 写计划 → 子代理执行 → 审查 |
| 重构 | 写计划 → TDD（先写测试）→ 重构 → 验证 |
| 新项目 | Brainstorming → TDD → 代码审查 |
