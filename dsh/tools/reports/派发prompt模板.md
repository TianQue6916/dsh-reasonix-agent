### 格式契约（违反即失败）
- **行内双语**：中文主体，English term 写 `English（中文）`，**仅首次加括号**，后文只留 English。严禁英文段+中文段对照。
- 术语保留英文原词（{{领域术语示例}} 一律不译）；代码名/变量名/运算符原样。
- 公式：行内 `$...$`，块级 ```math 围栏；**禁 `$$`**、**禁 `\[`**、**禁 Unicode 上下标**；`\text{}` 内不写反斜杠数学命令。
- {{教材：章节标题保留原编号；定理/定义/证明/例用 HTML span 配色标签}}
- {{讲义/PPT：保留 bullet 与编号结构；每页 `<!-- ===== pN ===== -->`}}
- {{解答：题目编号/分值/答题区保留；推导链逐步，不许把「由 X 得」压成结论}}
- 习题题干留英文并标 `[exercise]`；例题必译。
- 图用 `[Figure N：描述]` 保留，不得静默丢弃。
- 页眉页脚页码合并成一行来源注。

### 已知陷阱（踩过的，必须规避）
1. **同一行不要混放裸 `<` 与 `>`**（`extract-formulas.py` 早期版本会把中间内容当 HTML 吞掉）。数学里写 `\lt` / `\gt`，渲染等价。
2. **`f'(x)^2` 会触发 KaTeX `Double superscript`** → 写 `(f'(x))^2` 或 `f''(x)`。
3. **PDF 文字层可能坏**：`pdftotext` 的 ToUnicode CMap 在 MIT 讲义上会丢 δ/π/∞/∈/≤，改用 PyMuPDF（`import fitz`）。
4. **合并单元格表格**：文字层常整列错位，缺失格标 `†` 并说明「按语义推定」，不许假装原文。
5. **批量替换脚本**：所有字面 `$`、`\` 必须 `re.escape()`；改别人文件前先 `cp` 备份。
6. **扫描件判据**：`get_text()` 近 0 字符 + 每题 1 张图 = 纯图像，进 OCR 单轨，不要硬翻。

## 单 worker 工作量上限（2026-10-28 用户明确要求）

> 用户原话：「不要给单个子 agent 派太多工作量，不要把上下文撑爆了。」

| 内容类型 | 单 worker 上限 | 理由 |
|---|---|---|
| 教材切块（20 页/块） | **2 块 = 40 页** | 实测 Boyd 2 块产出 51-54 KB / 900-990 行，已接近上下文舒适区上界 |
| 讲义/解答（5-15 页/份） | **3 份** | |
| 幻灯片（<20 页/份） | **5 份** | |
| 单份 >50 页 | **必须切块**，不许整本交给一个 worker | |

**硬规则**：任何一批一旦估到 >60 页或 >6 个文件，必须拆成 2 个以上 worker。
**分批落盘**：每完成一小组（≤3 份）立刻写文件 + 跑该目录 KaTeX 校验 + 报一次数字，**不许攒到最后一次性输出**（长上下文里后半段质量会塌）。

## 审计层（每 2-3 批必做一次，用户要求「记得确认审计」）

三道审计，缺一不可：

1. **格式审计（自动，每批必做）**：`extract-formulas.py` + `katex-check.js` → `files_with_errors = 0`。
2. **静态规范审计（自动，每批必做）**：`audit-bilingual.py`（英文分段/`$$`/短语/密度）+ `untr-v3.py`（未译英文行占比，>15% 要人看）。
3. **内容层审计（LLM，每 2-3 批抽 3-5 份）**：对照原 PDF 查 5 条 —— ①覆盖完整性（整块漏译）②术语一致性（同一 term 多种译法）③译者注质量（是否名词搬运）④注水/合并句子 ⑤原文自身的错误（记号不一致、跳步、印错）。
   判级 A 可直接学 / B 需小修 / C 需重译，**理由必须可复核**。

**审计 agent 的 prompt 模板**见 `旧译内容层审计` 那一轮实测（产出 8 份 A0/B7/C1 + 19 条原书勘误）。

## ⚠️ 路径坑（2026-10-28 由 worker 实测发现，必须遵守）

**不要把临时 JSON 写到 `/tmp/`。** Git Bash 的 `/tmp` 是 `AppData/Local/Temp`，而 Windows 原生 Python 把 `/tmp` 解析成 `C:\tmp`，
两边不是同一目录 ⇒ `extract-formulas.py` 写出的文件 `katex-check.js`（node，走 Windows 路径）读不到，报 `Cannot find module`。

**统一写成绝对路径**：`C:/Users/27063/AppData/Local/Temp/xxx.json`。

另外两条实测坑：
- `extract-formulas.py` 的正则式抽取会**漏掉「一行里放多个公式」的长行**（worker 自写更完备抽取器后，同一份从 395 公式变多）。所以 KaTeX 通过 ≠ 全覆盖，重要批次可让 worker 用自写抽取器复算一遍。
- 目录级 KaTeX 校验会把**同目录其他 worker 的文件**一起算进去，报错时归属容易误判 ⇒ 报告里必须区分「目录合并数」与「我独占数」。

## 译者注硬要求（2026-10-28 审计后追加，前 6 份 Boyd 因缺这条被判 B）

**每块至少 1 条合格译者注**（核心契约 8 + 铁律 15/27-30）。合格判据：
- 说清**这个概念为什么这样定义、抽掉它系统会崩在哪**（机制），再给**可点开的落点**（教材 §号 / 页号 / 课程节号 / arXiv id / 源码 `文件:行`）。
- 长度：能 800–1200 字最好；不行也要给到「机制 + 坐标」，不许只写一句感想。
- **禁止**名词搬运（「这很重要」「广泛用于」）、**禁止编造场景**；定位不到写 `[未定位]`。
- 不越级（禁群论/环论/拓扑/非标准分析），必须挂到用户已掌握节点：6.042J 离散、CSAPP、6.006 算法、Strang 线代、Thomson 实分析。

**标签纪律（防源混淆）**：自写内容一律用 `[译注]` + 绿色 `<span style="color:#1e8449;">`；
**严禁**把自己写的话套上原书的 `[remark]/[theorem]/[definition]` 标签与配色 —— 审计发现前 6 份有 9 处这种混淆，读者分不清哪句是原作者。

## ⛔ 禁止在 prompt 里预设章节归属（2026-10-28，同一错误犯了 6 次后立规）

**事实**：这一夜我对「某页块属于哪一章」的判断**错了 6 次**：
| # | 我的假设 | 实际 |
|---|---|---|
| 1 | `book.pdf` 是 Cover & Thomas | MacKay ITILA |
| 2 | Boyd「PDF = 原书 − 14」 | 反了，是「书页 = PDF − 14」 |
| 3 | MacKay p121-160 是 Ch.2 | 是 Ch.6–9 |
| 4 | Boyd p161-200 含「convex functions 章末 + 4.1」 | 是 4.3–4.7 |

| 6 | MacKay p241-260 是「13 章末 + 14 章开头」 | 横跨 4 个章号（14/15/16/17） |

**规则（从此不再犯）**：
1. 派发 prompt 里**不写**「这两块应在 Ch.X / §Y」，改为一句：
   `章节归属以 PDF 文字层实际内容为准；worker 应先用 fitz 抽第 1 页与页眉，自行确认起止章节，并在文件头写明。`
2. 需要给 worker 参考时，只写**已由前序 worker 实测确认**的内容（附页码映射与证据页码），不写我的推断。
3. 若必须给预期，格式写成：`我的猜测可能有误，请以实测为准并回报偏差` —— 这一夜 6 次都是 worker 反过来纠正我，说明这条提示有效。

**根因**：凭文件名/印象推断，没有先跑脚本。**核源料成本 = 一条 `python -c` + `fitz` 抽首末页**，比返工便宜两个数量级。

## ✅ 补注/改写类任务的机器化无损判据（2026-10-28，worker 发明，我采纳）

任何**往已有译文里插入内容**的 worker（补注、修错、加译者注）都必须跑这条：

```
对每一份：
  读 SRC（原目录里的完整译文）与 DST（你写的补注版）
  检查 SRC 的每一行，按序是否都是 DST 的子序列
  → 必须 100% True
```

```python
# 参考实现（逐行子序列检查）
def is_subsequence(src_lines, dst_lines):
    it = iter(dst_lines)
    return all(any(l == d for d in it) for l in src_lines)
```

**它抓到过的真实 bug**：注被插在「整行中间」（用 `anchor+len` 定位），把原文两行劈成四段 —— 人工核对很难发现，子序列检查立刻 False。

配套纪律：
- 补注 worker **只写 `<书名>_补注/`**，绝不读改 `<书名>/` 原目录（读 SRC 可以，写不行）。
- 交付前**跨文件查重**：若原目录已有同主题的 `[译注]`，改掉自己撞车的（这一夜有 worker 靠查重换掉了两条同质注）。
