## 二、三条阅读路径

**路径 A · 新 agent 上岗（先读这四篇，20 分钟）**
`01` 方法论 → `09` 宿主限制（不然第一步就会往 D 盘写）→ `02` 重启边界（不然会白改）→ `08` 备份铁律（不然会往 public 仓库塞凭据）。

**路径 B · 出故障（先 10，再定位域）**
`10` 否证档案（含测量纪律）→ 按现象跳到 `04`/`05`/`07`/`09`。
顺序很重要：**先建立"怎么算证据"的框架，再去查具体域**，否则会在同一个未被验证的假说上反复。

**路径 C · 要动手改东西（先 02，再 01）**
`02` 判断这次改动属于哪个重载层 → `01` 用定好的验证姿势（新 session / 重启 / dump-config）→ 改完把新判据回写 `PLAN.md`。

## 三、每篇的统一结构

```
D 定论  —— 一句话结论，先给答案（可直接抄进 runbook）
M 机制  —— 为什么会这样（第一性原理层，不是"官方这么说"）
J 判据  —— 怎么判断"这次也是它"（可观测信号 + 命令）
X 反例  —— 试过并已否证的路径（和结论同等重要）
R 复现  —— 命令 / 步骤
S 溯源  —— 结论对应的 fact 文件名（不写"据说"）
```

**为什么是这个顺序**：先给可用结论（省时间），再给机制（省未来的时间），再给判据（省下一次的时间），反例防止重复劳动，溯源防止腐烂。

## 四、素材与方法

| 素材 | 位置 | 规模 |
|---|---|---|
| memory fact（canonical 语料） | `~/.reasonix/memory/global/*.md` | 312 条，平均 2.7 KB |
| 作战记录 | `~/.dsh/PLAN.md` | 1473 行（2026-09-28 → 10-26） |
| 原始会话 | `~/.dsh/sessions/**`（zstd） | 291 MB —— **未纳入**，见下 |

**提炼流程（可重跑）**：

1. 扫 fact frontmatter（`name` / `description`）→ 建立索引；
2. 按关键词聚成主题桶 → 每桶 20–60 条；
3. 逐桶精读，只保留"有数量、有判据、可否证"的结论；
4. 每条结论在 `S 溯源` 里挂回 fact 文件名；
5. 冲突不合并，写进 `## 存疑`。

**没有纳入的部分（明确记账）**：
- `~/.dsh/sessions/**` 的原始对话（291 MB / 1448 个 `.zstd`）—— 体量与信噪比不允许全量精读。它们是**下一位接手者的增量素材**：任何一篇要扩写时，按主题回捞对应 session 重读。
- 2026-06 之前的历史。

## 五、维护规约

1. **新增一篇的条件**：这个域至少有 8 条独立 fact，且有 ≥ 3 条"有数量级证据"的结论。否则并进现有篇。
2. **结论要带日期**：软件会升级，`2026-10` 的结论在 0.3.x 上可能不成立。写入时给年月。
3. **不许写"据说/应该是"**：没有观测的写进 `## 存疑`，不要混进 `D 定论`。
4. **凭据零容忍**：任何 key/token 只写 `<REDACTED>` 或形态描述（如 `user_` 前缀 93 字符）。
5. **失效要标注而不是删除**：结论被推翻时，在原文加 `> ⚠️ 2026-11 更新：…`，并把它移 `X 反例` 的思路里 —— 保留"曾经这么以为"本身就是经验。
