# 2026-10-05 白纸图标第四轮：失败率按 iconcache 尺寸分档分裂

承接同一故障线的三篇既有文档：`2a3a3f1e-f17c-470d-a66e-f595588d583a`（第 1 轮，症状定位与 shell extension 审计）、
`c97a2a01-a6de-4ed5-951c-52cb0d00cd2b`（第 2 轮，定案为 Windows cumulative update 处于 InstallPending / 组件版本不同步）、
`d71561f3-518a-4e33-ad58-fd71036a1a25`（第 3 轮，失败点收敛到 .lnk 的 IconHandler，裸 exe 提取正常）。
本文是第 4 轮的净增量：**只记录既有文档未覆盖的"按尺寸分档"观察与配套操作方案**，不重复前三轮的证据链。

## 核心观察：同一批 .lnk，两个 DPI 上下文结果不同

复测脚本 `test_icons.py` 同时以非 DPI-aware（32x32）与 DPI-aware（48x48）两个上下文枚举同一批任务栏/桌面 `.lnk`，
判据为 `image list idx != 0 && 颜色饱和度正常`（同脚本内含裸 exe 阳性对照，两次都拿到 COLOR）。

```
非 DPI-aware (32x32)  -> 正常 9 / 异常 1   （唯一异常：DeepSeek Harness.lnk）
DPI-aware   (48x48)   -> 正常 3 / 异常 7   （File Explorer / Firefox / Edge 好，其余白）
```

32x32 那次 `idx` 是 50→61 连续分配，说明 image list 本身工作正常。
更早约 20 分钟前的同批测量是**全部 `idx=0 WHITE`**，即 32 档是在 TiWorker 那一轮推进（CPU 105s→290s）**之后自愈**的。

## 机制：iconcache 按尺寸分文件

`%LOCALAPPDATA%\Microsoft\Windows\Explorer\` 下：

| 文件 | 尺寸档 | 本次状态 |
|---|---|---|
| `iconcache_32.db` | 32x32 | 已恢复（9/10） |
| `iconcache_48.db` | 48x48 | 条目仍坏（3/10） |
| `iconcache_idx.db` | 索引 | 正常（02:37 后被重写） |

任务栏图标走 32 档，资源管理器「大图标 / 超大图标」及以上走 48 档 —— 与用户最初的
「任务栏图标消失 + 桌面白纸」描述精确对应，说明这是**两个独立 cache 文件的独立损坏状态**，
而不是单一上游组件的统一失效。

## 操作方案（与 00:33 那次全删的关键差别）

重启后若 48 档仍坏：**只删 `iconcache_48.db` 这一个档位**，保留已修好的 `iconcache_32.db` 与 `iconcache_idx.db`，
流程为 停 explorer → 删 → 起 explorer。

依据：`iconcache_32.db` 已恢复到 9/10，**证明当前 shell 具备正确重建 cache 的能力**；
而 00:33 那次是在"重建能力未知"的前提下把全部缓存删光，实测**加重了图标问题**（该影响此前已如实记录）。

## 本次得到硬信号支持的重启判据

- `CBS RebootPending = True`（用 `Test-Path` 查询，可靠），在 DISM/SFC 跑完后由 False 变为 True；
- `SessionsPending` 子键 9 个，`CBS.log` 仍在写；
- `TiWorker.exe` CPU 停止增长、`Dism.exe`/`DismHost.exe` 已退出 ⇒ 处于**等重启收尾**状态。

即这次重启不是"再试一次"，而是 CBS 收尾要求 + shell 运行时状态清零。

## 与既有定案的张力（未解决）

`c97a2a01` 把根因定在 InstallPending 导致的组件版本不同步；本轮观察到的**按尺寸分裂**与之并不直接冲突
（同一上游可能只影响部分 cache 分片），但**分档现象本身尚未在重启后复验**。
若重启后 32 档保持正常而 48 档仍坏，则单靠 InstallPending 不足以解释，需按本轮方案做 48 档单独重建。

## 本轮新增的 4 条脚本假信号教训（都已作废，未进入结论）

1. **Python 拼 PowerShell 字符串要避免**：f-string 的 `{...}` 与 PowerShell 的 `{...}`（如 CLSID、脚本块）冲突，
   手工 patch 时 `\n` 也易被写成真换行。**改为写成独立 `.ps1` 文件再调用**。
2. **PowerShell 注册表 provider 会把 `*` 当 glob 展开**：`Get-ChildItem -Path HKLM:\SOFTWARE\Classes\*\shellex -Recurse`
   会展开成 1548 个类并打出一堆重复键名。查通配键必须用 **`-LiteralPath`**。
3. **CPU 时间口径必须自洽**：一次取 `UserModeTime`、另一次取 `User+Kernel`，会伪造出
   "TiWorker CPU 289.8→126.9 回退"这类假象。跨次比较前先固定口径。
4. **"查不到 DLL"常是漏查 HKCU**：首次判 `OneDrive1-7` overlay 为孤儿键并据此猜"overlay 槽位超限"，
   补查 HKCU 后 7 项 DLL 全部存在 ⇒ **孤儿键/超限假说不成立**（且 overlay 超限只影响小徽章，不影响主图标）。
