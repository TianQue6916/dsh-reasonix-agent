## 5. 修复概率与用户决策（重要：不做"保证"）

明确回答用户"能保证解决吗"：**不能**。根因未定位（只确认形态 + 否证 16 项），在根因未知时不做保证。给出的概率 × 代价表：

| 方案 | 修好概率 | 代价 | 失败后损失 |
|---|---|---|---|
| Clean Boot（诊断） | 不修问题，只判定是否第三方 | 1 次重启 | 无（可完全还原） |
| Repair Install | 估计 70–85% | 30–60 分钟 + 20 GB | 时间；小概率卡住重来 |
| 接受现状 + 绕过 | 0 | 无 | 图标一直白 |

补充判断依据（来自本轮复读早前证据）：
- `NTUSER.DAT` / `NTUSER.DAT.LOG1` / `LOG2` 的 ChangeTime = 2026-10-04 15:42:08，正好在用户报告故障（10-04 18:35 重启）之前几小时；桌面 lnk 大量消失；用户原话"就像电脑被重置了一样""一些协议需要重新同意" ⇒ 指向**用户配置（HKCU）被部分重置**而非系统损坏。
- 两者修复方式相反：**系统坏** → Repair Install 有效；**HKCU 坏** → Repair Install **无效**（它特意保留用户配置），会白等 40 分钟。
- 因此提出唯一能区分二者的廉价实验：**临时本地账户登录对照**（新账户图标正常 ⇒ 故障在 HKCU，可导出两账户 HKCU 相关键做 diff 精准修复；新账户也白 ⇒ 系统层，Repair Install 才有意义）。用户答复"**A**"，但附加要求：**先做一份清单，最大化保证之后还能恢复**。

### 6.1 操作要点与本次踩到的坑

- **系统还原可用性判断必须提权**：非提权下查询 `Get-CimInstance SystemRestore` 报"拒绝访问"，`Win32_ShadowCopy` 返回"无卷影副本"、VSS/swprv/SDRSVC 均 Stopped/Manual —— 这会造成"系统保护已关闭"的**假阴性**。提权复核后还原点创建正常成功。（教训：权限不足的否定结果不能当结论。）
- **`quser` 在部分环境不可用**（`CommandNotFoundException`），快照脚本里应容错，不要因此判定快照失败。
- 基线快照的价值：`before-A` 中"无还原点/账户列表/服务与驱动清单"是回滚时的对照基准。

## 7. 临时账户对照实验：执行与修正

- 创建：`New-LocalUser` 成功，账户名 `dsh_test_temp`，`Enabled=True`，`PrincipalSource=Local`，SID 尾 `-1004`；**不在 Administrators**。
- **本人误判并已修正**：脚本把 `Users` 组和 Administrators 一起当"特权组"检查，报"不在 Users 组（好）"是错的 —— **`Users` 组是登录所必需的普通组**，临时账户必须属于它。之后按 SID 显式加入 `Users` 组。
- 登录界面可见性检查：系统常规账户数 = 2（原 `27063` + 新账户），临时账户已出现于欢迎屏。
- 反例排除：`27063` 为 MicrosoftAccount 且 Enabled=True，`Administrator`/`Guest`/`DefaultAccount`/`WDAGUtilityAccount` 均 False —— 基线账户状态清晰，未被本轮操作污染。

### 7.1 必须在指令里写清的会话保护

- **用「切换用户」，不要用「注销」**：注销会关闭当前会话 ⇒ **正在运行的 dsh 退出、对话中断**；`Win+L` 锁屏 + 选另一用户 = 当前会话在后台保留，切回原样。
- 新账户首次登录会弹 OneDrive / 隐私 / 绑定账号提示：一律"跳过 / 以后再说 / 否"，**不得输入真实账号凭据**；如强制设置安全问题，随便填。
- 返回后只需回答一个问题：**新账户里图标是彩色的还是白的** —— 这条单点结果决定后续走 HKCU 精准修复还是 Repair Install。
- 兜底话术：`rstrui.exe` 选 `before-temp-account-test-1006-0959` 可连注册表 + 系统文件一起回滚。

## 8. 本轮教训汇总

1. **"显示截断"不等于"执行截断"**：早前一版把"备份"与"禁用服务"写在同一个 PowerShell 脚本里，`head -5` 只截断显示、脚本仍执行到底（涉及 RustDesk / Tailscale 远程连接风险）。破坏性操作必须单独成脚本且默认不执行。
2. 权限不足会制造假阴性（系统还原"无卷影副本" / "拒绝访问"），任何否定结论先确认权限位。
3. 探测姿势错误会产生假阳性/假阴性双向噪声（`BindToHandler` ⇒ `MK_E_NOOBJECT` 对裸 exe 同样出现；对 firefox.exe 也 E_FAIL）—— 测试对象必须包含阳性对照，否则结果作废。
4. 用户问"能不能保证"时，根因未定位就直说不能，只给概率 + 代价 + 失败损失。
5. 有风险的动作前先建**可回滚**退路（还原点 / 注册表导出 / 快照 / 恢复清单），并优先选纯增量、可完全撤销的操作（新增本地账户 vs 迁移数据是两回事，须向用户讲清区别）。
