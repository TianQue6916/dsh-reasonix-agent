# 翻译工程第二轮：内容层审计与自动化边界（2026-10-28）

| 术语括号失控（核心契约被系统性违反） | STRANG part002 **625 对括号 / 3308 行**；TBB005 380 对；L01 66 对；`positive definite（正定）` 在 L8–L12 **连续 5 行**重复加括号 |

**方法论教训**：格式校验通过 ⇒ 内容可用 是错误的推论。审计必须分层，且要**抽读含数学推导的段落**，不能只看标题/表格。
完整报告：`.dsh/tools/reports/旧译内容层审计-20261028.md`。

另一个影响可核对性的发现：`概率导论/lecture最终版`、`计算机网络/课堂讲义`、`算法进阶/lecture` 三处**只有 .bilingual.md 没有原 PDF**；LaLFD 原书 434 页只有 3 页有文字层（其余为扫描图）——这些课程的「覆盖完整性」无法验证，报覆盖率时必须标注不可核对。

## 二、自动化边界：机械翻转术语括号注定失败（三轮全败）

对 6.046J 的 9,000+ 处反向术语括号做脚本翻转，三轮都以数据损坏告终：

| 版本 | 规则 | 失败方式 |
|---|---|---|
| v1 | 无长度限制 | `美国职业棒球大联盟（Major League Baseball）` → **`国职业棒球大联盟`**（静默丢字） |
| v2 | 中文段长度 ≤ 8 字 | 仍截断 |
| v3 | 加词边界 `(?<![\u4e00-\u9fff])` | 仍把 `不含底特律（Detroit）`、`天真的体育记者` 当作待翻转术语，产出 `Detroit（的积分榜，不含底特律）` 这类破坏句法的结果 |

**正解（已确立）**：脚本只产**候选清单**（含 context）→ LLM 判定是否为真术语 → 输出**精确 old→new 替换对** → diff 验证 → 才允许应用。
与更早的公式修复教训同型（v1 12 处最优 / v2 71 处 / v3 51 处：改动越"聪明"越差）。

推论：**能正则化的结构性问题（括号配对、包裹形式）可以批修；涉及语义边界的（哪些是术语、哪些是句子成分）必须 LLM 逐条判**。

## 三、避免无用功：三源交叉核对与「全资源搜索」的真实边界

- **LNotes 1–20 确认从未翻译**，三条独立证据：gh-publish/Linux `Introduction-to-Algorithms` 的 20 个 bilingual 是 `lec15–19` + `book chunk01–06` + 作业解答 + `review2`，均不含 LNotes；该仓库 `git rev-list --count` 仅 1 个 commit 且 `git log --all` 中 LNotes bilingual 出现 0 次（不存在「翻过又删」）；2026-09-23 记录里的「LNotes/ 已成套」指 PDF 原件而非译本。
- **踩坑记录**：第一轮只扫 `Desktop/课程文件` 与 `D:/10-学习`，漏掉 `D:/gh-publish`（14 个课程仓库的实际主目录）。补扫后确认它是 Linux `~/课程资料` 的同源镜像（数字几乎一致），才排除「别处还有一份译本」。扫描根已固化写入 `.dsh/tools/SCAN-ROOTS.txt`（10 行）。

复核判据沉淀：判断「是否翻过」要同时看 **文件名 stem 精确匹配**、**编号次级匹配**、**目标仓库 git 历史（是否翻过又被删）**、**同名目录里是否有原件**；只看文件名会把 `L10.bilingual.md` 与 `L10 - xxx.pdf` 判成不同文件（`kb-gaps.py` v1 曾因此误报 16 份）。
