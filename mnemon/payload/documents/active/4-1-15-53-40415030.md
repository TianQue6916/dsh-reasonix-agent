# 微信 4.1.15.53 升级后「打不开」诊断与修复（2026-10-13）

## 任务与症状

用户报「微信打不开」（m00001）。追问后用户回答 **「AB兼有」**（m00106）：A = 双击图标无反应 / 窗口不弹出；B = 窗口出来但一片空白只有深色背景。
环境：微信安装目录 `D:\60-通信\微信\Weixin\`（`D:\微信\Weixin\` 是 junction 指向它），版本 **4.1.15.53**；`Weixin.exe` CreationTime = 2026/10/13 **17:04:20**，本次启动 17:07:06。

## 结论（因果链）

1. 17:04 刚跑完一次版本升级 `4.1.12.55` → `4.1.15.53`（旧目录 `4.1.12.55\` 被清空到只剩一个 `crashpad_handler.exe`，**不是可回退的完整旧版本**，正常升级收尾不该长这样 → 升级收尾不完整）。
2. 17:07 启动新版：进程建了、Qt window 建了、message loop 活着，但 **Radium（微信 4.x 的 UI 框架层）初始化没走完**。
3. 那个半死实例**占住了 single-instance lock** → 之后点图标走「激活已有实例」分支，不新建窗口（现象 A）。
4. 而它唯一那个窗口的 renderer 从未产出内容 → 一片空白（现象 B）。

**A 与 B 不是两个故障，是同一次「不完整初始化」在两个观测面上的投影**，所以修法只有一个方向：让该实例彻底消失 → 走一遍干净冷启动。

## 取证方法与判据

### 1. 进程 / 窗口层（区分「是否卡死」）
- `IsHungAppWindow = False`；`SendMessageTimeout(WM_NULL, 3000ms) result=1`（0 才是 hung/timeout）→ **message loop 活着，主进程没卡死**。
- 窗口 `hwnd=3211324`，class `Qt51514QWindowIcon`（Qt 5.15.14 自绘 UI），title `微信`，`visible=True iconic=False hung=False`，`rect=(629,116)-(1524,763)` = 895x647，完全落在 1707×1067 屏幕内 → 排除「窗口跑到屏外/最小化到托盘」。
- 子窗口有 `MMUIRenderSubWindowHW`（微信自绘渲染窗口）→ UI 层窗口对象被创建出来了。
- 修复前进程：5 个 `Weixin.exe`，主 PID **25208**（17:07:06），子进程 508 / 5560 / 14996 / 20756（17:07:33–34）。

### 2. 日志 / dump 层（哪些线是死的）
- `log/radium/host*.xlog`、`log/xplayer*`、`log/player/`：mars xlog 格式且**已加密**（头部 `07 01 00 11 11 9c …` / `07 06 00 01 01 50 02 …`），`strings` 只出噪声 → 日志线到此为止。
- `log/mm*.mmap3`：混淆（`tex` 乱码 / 无 printable）→ 读不出。
- `crashinfo/reports` 共 **97 个 `WeChatAppEx_*.dmp`**（17:02×8、17:03×10、17:04×3、17:05×6、17:06×4、17:07×5、17:08×6），但 10-07 / 10-09 / 10-12 也有同规模崩溃簇 → **长期常态，不是本次根因**；`WeChatAppEx` 是小程序容器，与主界面是两条独立链条。
- `xwechat/radium/crashpad/` **是空的** → 主 UI 层自己没崩。
- `grep Weixin.dll`（204MB）只命中 `--no-sandbox`，**没有 `--disable-gpu`** → 微信 4.x **不存在禁 GPU 的启动开关**，那条修法路径直接排除。

### 3. 决定性判据：`radium/cache/*.mmap` 的 mtime
`%APPDATA%\Tencent\xwechat\radium\cache\` 有 6 个文件 `host.mmap / host1.mmap / ilink.mmap / ilink1.mmap / main.mmap / main1.mmap`（各 204800 B）。
- **修复前**：最新 mtime 是 **2026-06-04 21:37**（其余 2025-07-31 / 2026-03-28）；17:07 那次启动**完全没写过它们** → 证明 UI 层这轮启动从未初始化。
- 对照：`log/mm*.mmap3`（17:10 仍在写）、`log/xplayer/xplayer.mmap`（17:05）都是活的 → mmap 写入与否可作 init 完成度指示器。
- `radium/mmkv/codecache_appid_dict` 停在 2025-11-21、`xweb_*_storage` 空 → 不是 codecache 损坏。
- **修复后**：`radium/cache/host.mmap` 204800 B、mtime **17:18**（刚重建）；`log/radium/host_20261013.xlog` 21144 B @17:18 → **Radium UI 层 init 成功的硬证据**。

## 修法（方案 1 + 2，一次到位）

1. 结束全部 `Weixin.exe`（`Weixin.exe` / `WeixinExt.exe` / `WeixinUpdate.exe` / `WeChatAppEx.exe` 均报 `not found`，说明已自行退出）。残留 3 个 `crashpad_handler.exe`（PID 7560 / 9780 / 11592）**Access is denied、不受保护进程影响，可忽略**。
2. **备份**（改名，不删，可逆）`%APPDATA%\Tencent\xwechat\radium\cache\` 下 6 个 `*.mmap` → `backup/`。
3. 冷启动 `Weixin.exe`。
4. 验收（非视觉）：新主窗口 **hwnd=854790**（与修复前 3211324 不同 → 是全新窗口，不是复用旧句柄）、5 个进程（主 PID 14212，318 MB）、`MMUIRenderSubWindowHW` 存在、`radium/cache/host.mmap` 于 17:18 重建、新的 `host_*.xlog` 生成。

风险提示（执行前已向用户确认）：消息在服务器不会丢；会丢的是**输入框里没发出去的草稿**；会中断**进行中的语音/视频通话**。

### 冷启动的坑：`cmd //c start "" Weixin.exe` → `Access is denied`
`start` 在 Git Bash 传参下出现权限/引号问题；已核实 `Weixin.exe` 的 manifest 是 `requestedExecutionLevel level="asInvoker"`、不需要提权，**不是 UAC 的锅**。
改用 bash 直接 `./Weixin.exe &` **一次就成**。**以后启 GUI 程序直接这样。**

## 防误判教训（重要）

- **`PrintWindow(PW_RENDERFULLCONTENT)` 对 Qt 窗口返回全黑**（采样 36288 像素、`uniqueColors=1`、100% `0,0,0`）——这是已知 false negative，**不能当白屏证据**。
- 锁屏时 `CopyFromScreen` 抓的是**锁屏壁纸**：`foreground hwnd=132032 class='Windows.UI.Core.CoreWindow' title='Windows 默认锁屏界面' pid=9804`（LockApp）。那次抓到的 895x647 是蓝调渐变照片（8310 色 / 0 个白像素），与微信界面无关。**⇒ 修复前观察到的「88.22% 是 RGB(21,21,23)、无白色块」很可能同样是锁屏/桌面，不能作为白屏判据；白屏的唯一可靠判据是用户肉眼。**
- 抓屏统计只取颜色直方图，不读窗口内容。

## 未决 / 回退

- 修复后仍需**用户解锁屏幕肉眼确认**窗口是否正常渲染（检查点结束时仍 open）。
- 若仍白屏 → 方案 3：卸载重装 4.1.15.53（`%APPDATA%` 数据可保留）。**无法回退到 4.1.12.55**，因为该目录已被升级清空。
- 用户曾问是否把「微信 Radium 白屏 → 冷启动 + 清 radium cache」写进 `PLAN.md` 或长期记忆；检查点内**未收到用户答复**，故本文件是唯一落点。
