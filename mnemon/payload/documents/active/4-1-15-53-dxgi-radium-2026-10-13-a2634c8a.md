# 微信 4.1.15.53 登录成功但主界面全黑：DXGI 虚拟显示适配器假设与 Radium 渲染层定层取证

性质：带实测证据的故障定层调查（第二层症状），承接既有文档 `40415030-ca27-43a0-9ecc-f731dfceb5fe`（《微信 4.1.15.53 升级后「打不开」（窗口不激活 + 白屏）诊断与冷启动修复定案》）。该文档覆盖 radium/cache mmap mtime 判据与冷启动修法；本文只记录其后新增的**登录态判据**与 **GPU/DXGI 层假设**，避免重复。

## 本轮结论（与用户主观报告冲突，以取证为准）

用户回「A」（主界面出不来）；取证显示**扫码登录其实成功了**，黑的是 UI 渲染层，而非登录失败：

- 主窗口：`pid=12160 hwnd=1051228 cls=Qt51514QWindowIcon title=微信 rect=(629,116)-(1524,763) size=895x647 visible=True`。**尺寸即阶段判据：`295x387` = 登录窗口，`895x647` = 主界面布局**；登录成功后微信会重建窗口（早期 `hwnd=788606` → 登录后 `1051228`）。
- 登录态文件更新时间：`...\xwechat\login\wxid_dlsn6ncrtblg32\key_info.dat` = 179 B，mtime 从 17:34 → **18:28**（扫码/登录成功才写）。
- 进程数 1 → 5：`--type=wxocr` / `--type=wxutility` / `--type=wxpublic` / `--type=xplayer` 四个插件宿主**只在登录成功之后才被拉起**，登录前微信根本不加载它们；主进程工作集 183 MB → 404 MB。⇒ 进程拓扑本身可当登录成功判据。
- 核心日志在增长：`C:\Users\27063\AppData\Roaming\Tencent\xwechat\log\mm_20261013.xlog` 4,126,189 B @17:38 → 4,954,297 B @18:29。
- 同时窗内抓到 5 个 `WeChatAppEx_*.dmp`（17:38/17:39，各约 340 KB）——`WeChatAppEx` 是小程序/公众号文章/内置浏览器（Chromium 内核）宿主，即小程序层在反复崩。
- 反面证据：`radium\log\` 只剩 `host1_20261013.xlog`（17:07）**零新增**，`radium\web\` **为空**。`Radium` 是微信 4.x 的 UI 框架层 ⇒ **UI 层没起来，所以 895x647 窗口里什么都没有**，这就是黑屏。

## 主假设：DXGI 枚举选中了无真实显示器的虚拟输出

- `--disable-gpu`（加在两个 `微信.lnk` 上）是 **Chromium 开关，管不到 `Radium`**（后者走 **D3D11 直渲**），因此表现为「能扫码、能登录，但主界面依旧全黑」。
- 设备枚举显示本机存在**三个虚拟显示适配器**且状态均 `OK`：
  - `ROOT\DISPLAY\0000` ExtensoDesk Display
  - `ROOT\DISPLAY\0001` GameViewer Virtual Display Adapter
  - `ROOT\DISPLAY\0002` USB Mobile Monitor Virtual Display
  - 真实 GPU：`PCI\VEN_8086&DEV_A788…` Intel(R) UHD Graphics、`PCI\VEN_10DE&DEV_2D18…` NVIDIA GeForce RTX 5070 Laptop GPU
- 假设机制：启动时枚举 DXGI adapter 撞上 `GameViewer Virtual Display Adapter`——状态正常、分辨率 2560x1600 与内屏一致、**但没有真实显示器**——D3D11 swapchain 建在它上面，于是窗口建对了、尺寸对了、消息泵活着，画面永远没东西。

## 教训 / 防误判

- **不要在证据与用户描述冲突时直接执行破坏性动作**：用户说「A（进不去）」、要求重装；进程拓扑 + 窗口尺寸 + `key_info.dat` mtime + xlog 增长四条证据都指向「已登录成功、只是没画出来」。重装会把正常部分原样再装一遍，而虚拟显示适配器是 GameViewer 装的驱动、与微信程序无关——**换程序换不掉它**，故重装被判为大概率白跑，改推 10 秒的 `fix-weixin-gpu.bat`。
- `--disable-gpu` 有效范围只到 Chromium 层（可让扫码/登录流程通过），**不能推广为「GPU 已排除」**。
- 非交互 shell 调 `Start-Process -Verb RunAs` 会**阻塞等 UAC 响应**（60s 被杀、无输出、日志文件不生成）。提权动作要么交给用户双击 `.bat`，要么明确告知需人工点「是」。
- 截屏取证在本机不可靠：`CopyFromScreen` 拿的是屏幕合成结果（微信被 dsh 窗口盖住就抓成 dsh），`PrintWindow` 对 GPU 合成窗口一律返回全黑（已知假阴性）——**像素验证失效时改用进程/窗口类名尺寸/文件 mtime/日志增长等结构化判据**。
- 从 `Weixin.dll` 提取 `--xxx` 开关（ASCII + UTF-16LE，`tr -d '\0'` 压宽字符）共 37 个，可辨认的只有 `--no-sandbox` / `--command` / `--config` / `--dataid` / `--debug` / `--environment` / `--getdefaultgateway6` / `--interface` / `--plugin` / `--savescene` / `--scene` / `--schedule` / `--show_version` / `--sourceinfo` / `--username` / `--xeditor` / `--parameters` / `--s-r` 等，**没有任何 gpu / adapter / d3d / render 相关开关**——即微信 4.x 未提供命令行层面的渲染后端切换。
