# 小米插座路线判死与最终收敛（2026-10-25 续查）

## 前置结论（不在本文重述）

- 现象与 60 天实证数据、逐项排除清单：见 `f7c9342c-8f53-4d5f-a8b7-405828718eae`
- 推翻 Realtek WoL 定论、转向「EC 误判 AC_PRESENT 0→1 边沿」、Kernel-Power 105 / BootType / hiberfil / S0ix 实测：见 `8f426f8b-b86c-42e6-9985-473fa201d22b`

本文只记录 8f426f8b 之后新增的**排除证据**与**最终方案收敛**。

## 约束前提

用户的需求是「远程开机依赖通电自启」，操作方式 = **智能插座 APP 点断电 → 点通电**（不是 WoL，官方文档确认该主板无 S5 WoL）。
因此 BIOS 侧 `Power On after AC Loss` 必须保留，而它和「关机后 13~21 秒假自启」在判据层不可区分 —— 这决定了只能从「消灭假边沿的物理条件」或「OS 侧事后兜住」入手。

## A1（插座功率规则自动断电）：判死

- 用户设备 = 小米智能插座，**无电量统计（功率检测）功能**
- 即便有，米家自动化里「功率 < X 瓦持续 N 秒」的 N **最短只能设 1 分钟**
- 假边沿发生在关机后 **13~21 秒**；1 分钟后机器早已被点亮、功率重新上去，规则永远不触发
- ⇒ 时序上不可能赢，A1 排除

## A2（miIO 局域网直接发 off/on）：判死

miIO 是 **UDP 局域网协议（54321）**，跨不了网段。本机实测拓扑：

| 接口 | IPv4 | 网关 | 性质 |
|---|---|---|---|
| 以太网 2 | 192.168.0.100 | 192.168.0.1 | **RNDIS，手机 USB 网络共享** |
| WLAN | 192.168.0.102 | 192.168.0.1 | 同上 |
| 以太网（Realtek） | 192.168.243.1 | 无 | **ICS 主机地址**（在给别的设备共享网络） |
| Tailscale | 100.84.67.49 | — | 虚拟网卡 |
| Radmin VPN | 26.248.141.36 | — | 虚拟网卡 |

- 整条上网链路由**手机 USB 共享**撑起，有线口在做 ICS；插座无论挂在哪个路由器下都不在这些可广播网段内
- miIO 发现扫描（UDP 54321 广播 + M-SEARCH 1982）：**total hits 0**
- `python-miio 0.5.12` 可从镜像装（wheel 下载成功），工具链不是瓶颈，**拓扑才是**
- 走小米云 API 技术可行但需交出账号密码、对抗风控、实现签名/加密全套 —— 与「一个次要问题」收益完全不成比例，主动放弃

## 已同时封死的其他路

- **只改 BIOS 策略**：`Power On` 的判据就是「看到 AC 0→1」，与远程开机的真边沿同源，信号层不可区分
- **休眠 S4 代替关机**：S4 与 S5 在主电源断、内存内容写法之外对 EC/适配器负载完全同构，假边沿照样产生；且 60 天 BootType 实测 `0x0 ×68 / 0x1 ×0` 证明从未真正用过 S4

## 最终方案 B：OS 侧假自启自愈（未落地，待用户拍板）

判据只依赖一个已验证的物理事实 —— 假自启永远落在关机后 13~21 秒：

```
开机 → 等事件日志服务就绪
     → 读最近一条 Kernel-Power 109 (Shutdown Off) 时间戳
     → 若「本次 boot 时间 − 109 时间」< 60 秒 ⇒ 判定假自启 ⇒ shutdown /s
     → 否则正常开机，不动作
```

- **60 秒阈值安全性**：对 13~21 秒窗口有约 3 倍余量；远程开机时上次正常关机至少数十分钟前，不会误杀
- **唯一误杀窗口**：手动关机后 60 秒内反悔再开机 —— 用 30 秒倒计时 + `shutdown /a` 取消兜住
- **代价**：每次误自启白跑一轮开关机（约 30 秒关机 + 12 秒启动）
- **计划落地形态**（设计已定、未执行）：`wake-guard.ps1`（含日志、事件日志就绪重试、失败不影响开机）+ 计划任务 `WakeGuard`（`/sc onstart /ru SYSTEM /rl HIGHEST`，延迟 20 秒避开日志服务启动窗口）；回滚一行 `schtasks /delete /tn WakeGuard /f`
- **验收探针**：连续关机 5 次，用 109→27 配对脚本确认不再出现 ≤120 秒的 `off->boot` 记录

## 对后续任何「局域网控制智能设备」方案的提醒

本机当前网络形态（手机 USB 共享 + ICS + 两个虚拟网卡）不是临时状态，任何依赖 UDP 局域网发现/直连的方案（miIO、Tuya Local、mDNS 设备）都会先撞上这一层。要么先把设备和主机放到同一真实网段，要么改走云端/中控（如 Home Assistant）。
