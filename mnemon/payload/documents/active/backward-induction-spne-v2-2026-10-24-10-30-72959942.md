# backward induction 与 SPNE 的四条件分离

主题来源：硬币行（从两端取硬币、两人轮流）题解里一段「逆向归纳法」证明的复核。核心结论不是「逆推对」这一句，而是**把一句话拆成四个互不替代的条件**。

## 一、证明链（三条定理，不可合并成一句）

1. **定理 1（Kuhn 1953）**：有限、完美信息博弈至少存在**一个纯策略 SPNE**，由按 node 深度（= 到叶子的最长距离）做**强归纳**的逆推构造出来。基例是叶子（`depth=0`，NE 平凡成立），归纳步骤只需检查当前行动者在 `h` 处不偏离，因为其余玩家在该 node 无行动权。
   - 立足点：**完美信息 ⇒ 每个信息集是单点 ⇒ 任一 node 都起一个子博弈**。判据是「信息集单点」，不是「祖先只有一个行动」。
2. **单步偏离原理（one-shot deviation principle）**：有限无环完美信息博弈中，`s` 是 SPNE ⇔ 在任何子博弈内都不存在「只在单个 node 改一次行动、此后仍按 `s` 走」可获利的偏离。这条是归纳 + 无环的**推论**，不是额外假设；证明里不点名它，就只能证到 NE 而不是 SPNE。
3. **BI 值 = maximin 值只在二人零和时成立**。von Neumann 1928 是一般理论（允许混合策略），完美信息（纯策略足够）才是它的特例 —— 方向不要写反。非零和下 BI 值只是「**假设对手也按 BI 最优时的收益**」，不是「我能保证的收益」。

## 二、四个独立条件（本轮最重要的可复用结论）

| 命题 | 最小前提 | 缺前提会怎样 |
|---|---|---|
| 值唯一 | 二人零和 | tie 只改分配路径，不改总额 → 与 tie 无关 |
| 策略存在 | 有限 + 完美信息 | —（Kuhn 保证至少一个） |
| 策略唯一 | 无 tie（每个 node 的行动者对后继严格排序） | 有 tie 时 SPNE 可多解 |
| tie 的后果 | 非零和 **且** 有 tie | 不同 SPNE 给同一玩家的收益可以不同 |

常见误述即把这四条压成一句「多人、确定性、无联盟 ⇒ BI 给出唯一的 SPNE」——「存在」真、「唯一」假，且把「多人」误当成唯一性的敌人（真正的敌人是 tie）。

## 三、两个反例（都可用暴力枚举脚本实测）

**反例 A（2 人非零和 + tie，杀掉「唯一」）**：root 属玩家 0，L → sub（玩家 1，A→(0,5)、B→(10,5)）；R → (3,0)。玩家 1 在 sub 上完全 indifferent，于是 `(L,B)→(10,5)` 与 `(R,A)→(3,0)` 都是 SPNE，收益不同。

**反例 B（同树，杀掉「保证」语义）**：玩家 0 取 L，玩家 1 tie-break 倒向 B 得 10、倒向 A 得 0，而 maximin 保证值只有 3。玩家 1 倒向 A 完全符合其自身最优性（5 vs 5），无可指责。
注意：**0 不属于任何均衡收益集合** —— 玩家 0 在根上会偏离到 R 拿 3，所以 (L,A) 不是 SPNE。写图注/表格时把 0 说成「三种合法的 SPNE 收益」是硬错。

> 可记忆的分离式：**值唯一 ≠ 策略唯一**。单人 DP 里两者通常同时成立，造成误绑；代码上表现为 `V[i][j]` 与 tie-break 无关（可断言），`choice[i][j]` 与 tie-break 有关（不可断言）。

## 四、硬币行递推的三处实现级修正

递推（`S(i,j)` 为区间和，`V` 是**当前行动方**能拿到的最大总数）：

```
V(i,j) = max( c_i + (S(i+1,j) - V(i+1,j)),
              c_j + (S(i,j-1) - V(i,j-1)) )
V(i,i) = c_i,  V(i,i-1) = 0
```

1. **真正的基例是空区间 `V(i,i-1)=0`**，不是「区间长度 1」。`L=1` 的转移要读 `V(i+1,i)`，漏掉就是 `IndexError`。
2. **填充顺序只有「L 递增」或「i 递减 + j 递增」合法**。单纯 `j` 递增本身没问题（算 `(i,j)` 时 `(i,j-1)` 已在同一行算完）；缺依赖的是 `i` 递增。这是**递推有向无环**的直接要求，不是实现细节。
3. `S - V` 这一步减法**只因零和才成立**；总和不等（非零和）时必须拆成每人一张值表。

反直觉实测（脚本 `[2]`）：偶数 `n` 时先手有 parity 策略保证拿到 `max(奇位和, 偶位和) ≥ S/2`；**奇数 `n` 没有这个保证**（`[1,9,1]` 先手只拿 2/总 11；`[100,1,1,100,1,1,100]` 先手 103/总 304）。300 组随机数据下值随 tie-break 变化 0 次，变化的是策略表。

## 六、文档审计规程（本轮因被扣而固化）

1. **审计即修复一体**：只列问题清单不修，等于没审计。
2. **读图是阻塞步骤**：图必须用 `read_image` 实际看过再下结论，不能凭源码想象。
3. **图内标题/轴标签/图例与正文同等级核对**：图内文字比图注更像「已定稿的事实」，最容易被当成印刷体跳过 —— 本轮三处硬错有两处就在图内（「三个数都合法」「按 i 或 j 递增」）。
4. **自检脚本 `assert old in s` 必须在写盘之前**；写盘脚本要打印逐项 OK 并对最终文件做残留检查（例如 grep「三处」应为 0）与 md5 三端比对。
