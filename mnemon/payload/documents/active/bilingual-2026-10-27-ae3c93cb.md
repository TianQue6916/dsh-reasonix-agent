# 双机课程翻译资产盘点与 bilingual 成品静态审计（2026-10-27）

起因：用户问「11-03 套餐结束前额度花在哪」，要求两件事——**点名到底哪些还没翻译**，以及**对已产出的全部双语成品做质量抽查**（不是抽样几份，而是全覆盖）。下文的数量均为 2026-10-27 快照，会随进度变化；方法与判据才是可复用部分。

## 一、可复跑工具链

全部放在 `~/.dsh/tools/`，纯静态、无 LLM 调用，几秒级完成：

| 脚本 | 作用 | 产出 |
|---|---|---|
| `kb-inventory.py` | 扫两机课程树，统计 `bilingual.md` / `bilingual.pdf` / 原始 pdf / `zho-hans.srt` / 全部 srt | `资产总清单-20261027.md` |
| `kb-gaps.py` | 按「有 PDF 但无同名 bilingual」比对缺口，分机器输出 | 控制台 + `win.gap` / `lin.gap` |
| `_gap_report.py` | 汇总两机缺口、做目录分布与跨机去重 | 控制台 |
| `audit-bilingual.py` | 对全部 `bilingual.md` 跑规则审计（见第三节） | 控制台 + 命中明细 |

快照口径：`bilingual.md` 1103、`bilingual.pdf` 35、原始 pdf 555、`zho-hans.srt` 84、全部 srt 289。这些脚本每次翻完重跑即可看进度，清单不是死文件。

## 二、两个必须避开的判据陷阱（本次实测踩到）

### 1. stem 精确匹配会制造大规模误报

原始判据是「`X.bilingual.md` 的 stem 需与 `X.pdf` 的 stem 完全相等」。但实际命名并存两种形态：

- 翻译产物：`L10.bilingual.md`（短 stem）
- 原始讲义：`L10 - Continuous Functions; Exponential Function (cont.).pdf`（stem 带标题）

结果 100B 实分析的 L10–L23 被整批误判为「未翻译」。修正判据后，Windows 侧未翻数从 **146 → 108**，`100b实分析/01-讲义笔记` 从 16 项降为 1 项。

**教训：跨目录、跨机器比对文件名前，必须先做规范化**——截断 ` - ` 之后的中文/英文描述段、统一大小写、把 `_`、空格、连字符折叠为同一分隔符，再做匹配。否则盘点结论会系统性高估工作量。

### 2. 逐机缺口相加会高估总量

两台机器课程树高度重叠，直接相加得到 146 + 166。按规范化文件名跨机去重后，唯一 PDF 缺口只有 **112**，分布为：仅 Windows 6、两机都有（同时缺）39、仅 Linux 67。两机都未翻的集中在 `006算法导论/主机文件`（35）、`100b实分析` 讲义与习题（25）、`data lerning`（6）。

**结论：缺口报数必须先跨机去重，再拆「哪台机器上做」**——两机都有缺的可以只做一次再同步；仅一侧缺的才是真正的机器专属债。

## 三、静态审计规则体系与可修复性判定

判据全部取自教学技能既有铁律的可判定项，不是主观印象。核心结论：**内容层基本合格，缺陷几乎全在格式与渲染层，可程序化批量修复，不需要重译。**

| 规则 | 含义 | 快照命中 | 是否需要重译 |
|---|---|---|---|
| R9 | 整段英文未译（≥4 连续行英文） | 1 份 | **是**（唯一真重译） |
| R11 | 文件过短（<1200 字符），疑似截断 | 1 份 | **是** |
| R8 | `\[2pt]` / `\[` 残留（铁律 32 相关） | 18 / 29 份 | 否，批量替换（会渲染成 `<无效数学公式>`） |
| R6 | 出现 `$$`，违反铁律 6（应 `$...$` 或代码块） | 34 份 | 否，批量改 |
| R7 | 未转义 `$` 字面量，会把后续文字吞进公式 | 158 份 | 否，批量加反斜杠 |
| R2 | 英文行首（≥3 或 ≥4 行）违反铁律 2 | 96 份 | 否，逐段修 |
| R12 | 缺 `[theorem]` / `[proof]` 等结构标签（老格式） | 87 份 | 否，可选补 |
| R13 | 术语一致性命中（术语表词命中） | 158 份 | 多为噪声，需词表校准 |

R13 是最容易自欺的一条：它统计的是「术语表中的词出现」，而不是「译文是否与原文对应」，因而大面积误报，不能当作质量结论，只能当线索。

## 四、审计脚本自身的迭代过程（重要流程教训）

首轮审计输出「341 份，341 份 ERR」，明细全是 `ERR_unterminated character set at position 2`——原因是 Python 正则字符串里 `\[` 未转义触发了 `SyntaxWarning` 并在拼接后破坏了字符集。**必须先把 ERR 类与规则命中类分开看，否则会把脚本 bug 当成数据结论。** 修好转义后命中数 341 → 287 → 257（期间把 R7 从「未转义 `$` 总数」细分为 `odd_dollar_lines_N`），说明规则需要多轮校准而非一次定稿。

R7 的人工复核也证明批量修不能全自动：`$1M Millennium Prize` 这类字面量 `$` 需要转义，但 OCR 说明里对 `$...$` 的引用属于合法上下文，得逐类判断。
