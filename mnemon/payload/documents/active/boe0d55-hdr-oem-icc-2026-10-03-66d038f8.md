# 内屏 BOE0D55 色彩管线：HDR 与 OEM 校色互斥（2026-10-03）

性质：带实测证据的硬件色彩调查 + 已执行的修复与回滚交接。

## 结论

HDR 与机械革命校色**不是并列选项，而是同一条颜色管线的两个互斥档位**。内屏 `DISPLAY\BOE0D55\4&40c9f7a&0&UID8388688` = BOE `NE160QDM-NZL` 是 sRGB 级色域面板，撑不起真 HDR；默认应待在「关 HDR = 校色生效」档，HDR 当作按需开关（`Win+Alt+B`）。

## 面板 EDID 硬事实（解析自 EDID）

- 基色 R(0.6465,0.3301) G(0.2939,0.6299) B(0.1514,0.0537) → **109.7% sRGB / 80.9% DCI-P3**（典型 sRGB 屏，非广色域）
- EOTF `05016a6a48`：bit0 + **bit2 = PQ/ST2084**，**无 HLG**
- 峰值/FALL 亮度 code `0x6A`=106 → 50·2^(106/32) ≈ **497 cd/m²**；最小亮度 code `0x48` ≈ 0.40 cd/m²
- gamma 2.20；CTA Colorimetry `8000` = 支持 BT.2020 RGB（容器声明，非能力）
- 动态范围 ≈ 0.40–497 nits ≈ 10.3 stops，IPS 边光、静态对比 ~1000:1、无分区背光证据 → 属"HDR400 级营销 HDR"：PQ 输出真实（10 bpc + PQ），但拿不到动态范围红利，只承担高光压缩 + SDR tone map 代价

## OEM 校色数据（真实存在，非噱头）

ICC 载体：`Default.icm` 9616 B / `sRGB.icm` 35864 B，源目录 `C:\Program Files\OEM\机械革命控制中心\AiStoneService\MyControlCenter\ICCProfile\`，生成时间 2025-05-23。

- 每份内嵌 `CxF ` tag（`ZXML\0\0\0\0` + zlib，inflate 出 87 KB X-Rite Prism CxF3 XML）= 逐机实测：`TargetLuminosityLevel = 200.66`、`ProfileType = MatrixBased`、`StandardGamma` 2.4(Default)/2.2(sRGB)、`AmbientLuminanceLevel = 500`
- `Default.icm` 带 **vcgt**（18 字节 header + 3×256 uint16）：`starts=[0,2,0]`，mid(128)=[29753, 29288, 30388]，ends(255)=[64885, 64069, 65535]
- `sRGB.icm` 另带 **MHC2**（3180 B）= 厂家自做的 HDR 校准矩阵 → OEM 内部同样把 SDR/HDR 当两条独立管线

## 机制：为什么互斥

注册表键：`HKCU\SOFTWARE\Microsoft\Windows NT\CurrentVersion\ICM\ProfileAssociations\Display\{4d36e96e-e325-11ce-bfc1-08002be10318}\<NNNN>`，每设备两组值 —— `ICMProfile`（SDR 路）与 `ICMProfileAC`（AC = Advanced Color = HDR 路）。校色 profile 只装在 SDR 那条。

内屏驱动键：`MONITOR\BOE0D55\{4d36e96e-e325-11ce-bfc1-08002be10318}\0001`，`UsePerUserProfiles=1`。

### A/B 实验证据（同文件状态，只切 HDR 一个变量）

| 条件 | `GetDeviceGammaRamp(\\.\DISPLAY1)` |
|---|---|
| 已装回 profile + HDR 开 | 纯 identity（`R/G/B[i]==i*257`）⇒ 校色完全没加载 |
| 同文件 + HDR 关（`SET_ADVANCED_COLOR_STATE` value=0，ret=0） | `R[128]=29812 R[255]=64764 / G[255]=63993 / B[128]=30326 B[255]=65535` ⇒ 与 vcgt 期望值 29753/64885/64069/30388/65535 吻合（差异仅插值） |

旁证：Windows 加载 vcgt **不要求 profile 排在列表首位**（`sRGB.icm` 排第一也照样加载 trim）。关 HDR 后 `GET_ADVANCED_COLOR_INFO` raw `0x3` → **`0x7`**（`supported=1, enabled=1, wideColorEnforced=1`，末位=1 即 SDR + ACM），`SDR_WHITE_LEVEL` raw 从 4650 回落到 **1000**。

### 两个已确认的脏状态

1. `\0001` 的 `ICMProfileAC` 首位 = `HDR 校准配置文件 2025-8-8 15500.icc`，自报峰值 **290 nits**（`lumi` tag），而 EDID 自报 ~497 → **低报 42%**，HDR tone mapping 会提前 roll-off、在面板上限前剪切高光。
2. `\0003` 上 `HDR 校准配置文件 2026-8-1 174721.icc` 自报 **970 nits**（超报近 2 倍）。`Enum\DISPLAY\BOE0D55` 有两个实例：`4&40c9f7a&0&UID8388688` → Driver `\0001`（活跃）、`5&de222c0&0&UID8448` → Driver `\0003`（同一块屏的旧实例）→ **两份互相矛盾的 HDR 校准挂在同一面板上**。

## 复现/验证

```bash
python - <<'PY'
import ctypes, ctypes.wintypes as w
u=ctypes.WinDLL('user32'); g=ctypes.WinDLL('gdi32')
h=g.CreateDCW("DISPLAY", r"\\.\DISPLAY1", None, None)
buf=(w.WORD*768)(); r=g.GetDeviceGammaRamp(h, buf)
print("ramp rc",r, "R[128]",buf[128], "identity?", all(buf[i]==i*257 for i in range(768)))
PY
```

`R[128]≈29812` 而非 `32768` ⇒ 校色在生效。

## 操作注意事项

- **不要碰控制中心的校色开关来"对齐状态"**：它当前显示 OFF 但校色实际在生效。开启它 → 重装并把 `Default.icm` 排回第一（可接受，vcgt 照样加载）；关闭它 → 再次 `UninstallCalibration` 删文件，悬空关联复现。该组件在此机本就不可靠：日志中 `GetInternalMonitorID | ####QueryDisplayConfig failed, ret=87`、`####ScanEdidFromRegistry returned null for ID=BOE0D55`（连内屏 EDID 都读不到）。
- **开 HDR 前先跑 Windows「HDR 校准」应用**，峰值按面板真实 450–500 nits 设（拖到顶 = 超报，即 `2026-8-1` 那份的错法）；在那之前开 HDR 只会让高光更早剪切。
- **MUX 待确认**：BIOS 变量 `OemDisplayMode = 0x04`（独显直连）与 `EnumDisplayDevices` 把内屏挂在 Intel 适配器下相矛盾；若确为独显直连，颜色管线归 NVIDIA，切回混合模式后应复验 ramp。

## 工具陷阱（踩坑记录）

- PowerShell + P/Invoke 探测 DISPLAYCONFIG 反复"无输出"，真因是 access violation 时进程 stdout 块缓冲被丢弃 → 改 `python -u` 且**结果写文件再 cat**。
- Python raw string **不能以反斜杠结尾**（`r"...\{4d36e96e-...}\"` + 变量拼接 → `SyntaxError: unterminated string literal`）。
- `ctypes.wintypes` **没有 `UINT32`**（只有 `UINT`）→ `AttributeError`。
- 生成文档的脚本里 docstring 出现 `%**`/`%` 占位符会触发 `TypeError: * wants int` → 用 `.replace()` 而非 `%` 格式化。
- `mscms` 导出名带 W 后缀：`WcsGetDefaultColorProfileW`、`GetICMProfileW`、`InstallColorProfile`/`UninstallColorProfile`（无 W 版）**MISSING**；`SetICMProfileW` 调用成功但**不改注册表键**（`keys changed by probe: []`），需直接改 `ICMProfile` 顺序才生效。
