## 一、五项加固：机制 + 验证方式

| # | 修复 | 机制 | 怎么验的 |
|---|---|---|---|
| ⑥ | **失败告警** | cron wrapper 失败时写 `~/.dsh/logs/sync-FAILED.json`（`at`/`rc`/`tail`，tail 只留最后 3 行含 Error/Traceback/失败），并 `notify-send -u critical`；成功则 `rm -f` marker | 故意指向不存在的 py 跑一次 → marker 生成且 `json.load` 校验合法 |
| ② | **双向 PLAN 镜像** | 保留 `PEER_MIRRORS` 拉对端 → `peers/win/`；新增 `PEER_PUSH` 推本机 → 对端 `peers/linux/`，在 `main()` 挂钩 | dry-run 同时输出 `[dry] peer-mirror win/PLAN.md` 与 `[dry] peer-push linux/PLAN.md` |
| ④ | **本机覆盖钩子** | `sync_dsh_local.py`（已进 `EXCLUDE_FILES`，各机自维护、不入同步），在 `main()` 之前 exec；附 `sync_dsh_local.py.example` 模板 | 文件不存在时静默跳过（dry-run 确认无报错） |
| ⑤ | **依赖自检** | `import paramiko` 失败 → 打印 3 行中文可执行提示（含 `python3 -m pip install --user --break-system-packages paramiko` 与「升级 Python 小版本后需重装」）+ `SystemExit(2)`，不再抛原始 Traceback | `python3 -S`（跳过 site-packages）模拟缺失，三行提示与退出码正常 |
| ⑦ | **日志轮转** | `> 5 MB` 时 `tail -n 2000` 重写 | `bash -n` 通过 |

失败告警的设计理由（值得记住的判据）：**「cron 失败了但没人知道」比「cron 没跑」更危险** —— paramiko 被 apt autoremove 带走后连续两天只有「同步开始」没有「完成」，日志里有 Traceback 但没有任何主动通知。marker 文件是给「下一次 agent 会话/人」看的，notify-send 是给「当下人」看的，两者互补；cron 下 `DISPLAY` 可能为空，所以 notify-send 失败必须 `|| true` 不影响退出码。

## 五、教训：用 `python3 -c` / heredoc 拼 shell 命令写文件

用 `python3 -c` 或 heredoc 往文件里插代码块时踩了两次：`\\n` 经 Python 字符串求值后**变成真实换行**写进文件，把

```bash
printf '{"at":"%s","rc":%d}\n' ...
tr '\n' ' '
```

撕成多行，报 `SyntaxError: unterminated string literal (detected at line 50)`。

**可靠姿势**：要插入的块先 `cat > /tmp/block <<'EOF' ... EOF`（带引号的 heredoc 不展开变量/转义），再用 Python 读文件插入。改走这条路后 `DEP_CHECK` 一次就成了。改完必须 `py_compile` / `bash -n` 验证，不要凭「写进去了」就宣告成功 —— 本次正是靠这一步才发现文件被撕裂。
