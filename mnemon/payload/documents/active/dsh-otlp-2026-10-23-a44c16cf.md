# DSH 实时调用链可视化调研（2026-10-23）

## 0. 需求（历史记录，非当前指令）

用户在 dsh 0.2.1-rc.2 上提问：有没有「科技感」的可视化插件，最好是**调用了什么、哪里就亮起来**的那种，并且要「评价还好」；第二轮追问「社区经验怎么说」。
需要区分的三件事：好看 / 真实 / 实时。用户此前已多次表达「先证后信、方案不自己拍」的偏好。

## 1. 核心结构判断：科技感 = 时间维度，dsh 没有 push seam

静态好看的图几乎不产生科技感；产生科技感的是**有一个东西正在穿过图**（脉冲沿 edge 扩散、节点高亮后衰减、粒子按权重跑），即 `state(t)`，而不是 `f(data)` 的静态图。

三范式对照（复用判据，勿再重新推导）：

| 范式 | 数据源 | 渲染 | 能否「点亮」 |
|---|---|---|---|
| 静态产物 | 已有结构化数据 | 一次画完（SVG/HTML） | 不能，只是快照 |
| 事件流驱动 | trace / span / hook 持续进来 | 60fps 增量重绘 | 能，这才是数据流 |
| 静态数据流分析 | 源码 def-use chain | 编辑器内高亮 | 半能，静态传播非运行时 |

**为什么 dsh 生态里没有**：dsh 的 agent 事件是 **pull 模型**——tool call 走会话消息流，回合结束才落成完整结果给 client 渲染；插件侧没有可订阅的 push event bus，也没有「tool-call 发生瞬间」的 client seam。因此现成插件最多做到「回合结束拍一张好看的图」。这是宿主未开接口，不是作者偷懒。

## 3. 社区经验（决定了「评价好」这个筛选信号不可用）

- **dsh 无中心化审核**：发布首日 `#dsh-plugin` 话题已混入大量无关 agent skills，只能靠 GitHub 话题发现，安装前务必读源码（ccwq/infocard-pub 的 dsh 评测笔记）。所以「评价好」在 dsh 生态里不是可靠信号，只有第三方各自的榜单和 CI。
- **有价值的社区产物是兼容性 CI**：`whyihaveyou/dsh-suite` 真装一遍记录结果。对接 rc.2 最重要的几条：`dsh-tavily-search` broken（incompatible with dsh 0.2.1-rc.2）、图表类的 `dsh-smart-charts` 同样 rc.2 拒装、`dsh-custom-tool` 是被 pnpm `allowBuilds` 策略拦截（插件本身可能没问题）、`distill` unknown。**结论：rc.2 这个时间点装冷门可视化插件踩坑概率不低。**
- **榜单定位**：`bruc3van/awesome-dsh-plugin` TOP200（人工维护、收录理由可回查 `data/approved.json` / `data/curated.json`）里，`Nagi-ovo/dsh-visualize` 排 **59/200、321 stars、Apache-2.0、最后更新 2026-10-22**，归 `UI & Experience · 界面与体验`。对照 npm 月下载 3,582 vs git-graph 125,946（差 35 倍）⇒ dsh-visualize 是**小众工具，不是社区共识级必需品**。
- **空白是真的空白**：按「实时数据流 / trace / 调用链可视化」搜 dsh 生态，**零命中**（无讨论、无 issue、无榜单条目）。中文社区讨论 dsh 很热闹，但聚焦提示词/模型行为（如知乎「V4 Pro 是否过拟合 DSH 极简模式」163 回答 / 58 万浏览），不是可视化工具。

## 4. 跨生态参考实现

- `@devtheops/opencode-plugin-otel`（见 skyming/awesome-ai-agent）：功能完善的开源 OTel 插件，完整呈现 Claude Code → OpenTelemetry 的数据链路，span 结构/字段设计可直接照抄。**自建路线的首选抄本。**
- 工业标准：Jaeger / Grafana Tempo（service map + trace waterfall，红绿表示耗时，最贴近原始需求）；Cilium Hubble UI（内核级实时 flow 图，天花板，但仅 Linux/k8s+eBPF，Windows 跑不了）；viztracer（`pip install` 一条命令出交互式调用嵌套 timeline，Python 实验最省事）；Chrome DevTools Performance（JS 火焰图）；React Flow / AntV G6 / Cytoscape.js（自建渲染层，active edge 的难点是「衰减」不是「点亮」）。
- 本机先例：`host-log-tee` 已证明能拿到 host 的 stdio 与 event-loop 心跳，同一 hook 面可拿到 `agent/pre-step`、tool-call 前后事件，按 OTLP 写 span 推本地 collector 即可有真实图。

## 5. 三选一建议（未定，用户拍板）

1. **装 `@nagi-ovo/dsh-visualize`** —— 5 分钟、零风险、兼容 rc.2，但在对话里看到的是示意图。适合只想看漂亮数据流图。
2. **自建 OTLP 埋点 + Jaeger** —— 1–2 天，得到可审计的真实数据，符合「先证后信」；社区里做成的也都是自己写，不是装现成的。**倾向此路。**
3. **只调试 Python 在跑什么** —— `pip install viztracer`，最省事。

不建议：随便装冷门图表插件（`dsh-smart-charts` 在 rc.2 已 broken + 市场无审核）。
下一步悬而未决的提议：扒 `opencode-plugin-otel` 的 span schema，对着 dsh 的 `agent/pre-step` hook 面看映射得上不上（纯读代码，不装不改）。
