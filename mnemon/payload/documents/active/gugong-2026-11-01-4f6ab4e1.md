# 故宫参数化建模（gugong）：屋顶同构与自写光栅化（2026-11-01）

项目根目录 `C:\Users\27063\projects\gugong`，1534 行 Python，依赖仅 numpy / PIL / scipy / matplotlib —— **零 3D 库**，渲染器是自写的 numpy 软件光栅化（`render/raster.py`）。全城生成 3.1 s、渲染 25 s（三张图 13–18 s/张）。承接 [a9c01787](documents/active/minecraft-2026-10-31-a9c01787.md) 的取源调查：那次确认了「官方无 3D mesh、Sketchfab 需登录下载」，并给出「故宫适合参数化生成」的结构论据；本次是把它真正建出来。

## 1. 核心洞察：四类官式屋顶是同一个生成器

所有屋顶可统一描述为：**平面矩形轮廓沿两个正交方向以不同速率逐层内缩，每层按举架抬升，直到收缩成一条正脊**。形制差异退化为两个决策（山面 x 向怎么收）：

| 形制 | x 向收缩 | 结果 |
|---|---|---|
| 庑殿 | 等比推山减速（p≈0.9） | 正脊被拉长 |
| 歇山 | 收到第 1 层后冻结（收山） | 冻结处自动生成垂直三角面 = 山花 |
| 悬山 | 第 0 层即冻结 + 端部悬出 | 只剩前后两坡 |
| 攒尖 | 两向同速缩到一点 | 四角攒尖 |

因此不必为四种形制写四份代码，只需一个参数化的 `rect_roof` 家族（`core/roof.py`）。

## 2. 两条数学：举架决定剖面，推山决定脊长

- **举架**：`h_k = Σ_{i≤k} jv_i · run_i`。因 `jv_k` 单调递增，故 `d²h/dx² > 0`，剖面是凹面朝上的凸函数 —— 屋顶的「曲线」是离散递推的极限形状，不是画出来的弧线。宋式举折（自脊向下按 1/10、1/20、1/40 等比递减）是同一族的另一种参数化。
- **推山**：`dx_k = dx_0 · p^k`，`L(p)` 严格单调 ⇒ **可反解**。给定目标脊长 31.8 m，二分法得 `p = 0.8996`，回代命中。这是沈源「以算求样」的可执行版本。
- **翼角**：不使用曲面细分，而是对角部施加径向形变场 `lift(t)=L·t^3.2`、`out(t)=U·t^3.2`，随层数向上衰减；垂脊由此自动变成上翘曲线。

## 5. 五条实战 bug（教训已留在注释里）

1. **shadow map 用透视公式却当正交投影用**：`sx = focal·x/z` 在正交投影中不该除 z，阴影随深度失真成大片斜条纹。
2. **bias 偏移方向错**：原用 `N·bias`，应为 `−L·bias`；对朝上的地面反而更远，acne 更重。
3. **`rect_roof` 生成以原点为中心的等高环，平移建筑时忘了平移屋顶**（`_ridge` 的 `y` 硬编码 0、`_dougong_band` 的 `box(0,0,…)` 同源）。单座渲染正常，集成后所有屋顶堆在原点，跨全场巨型三角形撑满光栅化 bbox → 进程 OOM 静默退出、无报错。失败模式是「没有输出 / exit 1」，不是画面变丑 —— 单测 × 集成测试对照是唯一能定位的手段。
4. **归一化参数与原始参数混用**：`solve_tuishan_p` 把未归一化的 `y_runs[0]` 当 `x_first` 传入，反解出 p=1.35 越界。规则：参数在边界处只归一化一次。
5. **SSM 对掠射平面天然失效**：地面第一步就自遮挡判定，整片变黑。最终改用「按建筑高度做剪切投影的地面 decal」作假阴影。

（反解 p 的调参轨迹 1.1782 → 1.3461 → 0.8996 反映的正是第 4 条。）
