# 真阴影修复 + 室内 / 铺作 / 隔扇（gugong 第三轮）

承接 [gugong 首版总览](documents/active/gugong-2026-11-01-4f6ab4e1.md) 与 [重檐通高反解](documents/active/gugong-2026-11-01-bbc11c5c.md)。项目根 `C:\Users\27063\projects\gugong`。

本轮的重点原本是室内建模，但先推翻并修掉了前两轮已判为「无法解决」的问题。

## 1. shadow map：两处叠加 bug，而非原理限制

前两轮的结论是「SSM 对掠射平面天然失效，因此改用按建筑高度做剪切投影的地面 decal 假阴影」。这个结论一半是错的——它是两个独立错误叠加：

**(a) 写入与查询用了不同投影**

```python
# depth_raster(ortho=True) 写入：正交，不除 z
sx = W * 0.5 + focal * Vc[:, 0]
# shadow_lookup 查询：透视，除 z
sx = res * 0.5 + focal * P[..., 0] / np.maximum(z, 1.0)
```

**(b) 深度轴方向反了**

`basis[2] = L`（指向光源），而 z-buffer 用 `min` 比较——于是保存下来的是**离光源最远**的表面。对地面这种平坦面，每个格子的深度都等于地面自身的深度，判据恒为「受光」。

两者叠加的表现极具误导性：一个让整片地面错误变黑，另一个让所有点都判受光；在两张诊断图之间来回切换时看起来像随机噪声，于是被归因为「SSM 原理不可行」。

修法只有两行：z 轴取 `-L`（背离光源，越大越远，`min` 才是最近面），查询改用与写入相同的正交式。验证用 4 个地面点，`lookup` 与期望逐项相等：

```
lookup = [1. 0. 1. 1.]   期望 = [1. 0. 1. 1.]   # 南侧受光 / 影中 / 影外 / 远处受光
```

**可迁移判据**：写下「原理上不可能，换替代方案」之前，先要求自己「用 4 个点、8 行脚本」证伪。证不出来就只是 bug——这类看似有理的放弃比继续排查更危险，并且会把错误结论写进文档传给下一轮。

## 2. 室内：`core/interior.py`

门洞、檐下、任何抬高机位都能看进去，空盒子会立刻穿帮。模块只用既有几何原语 `box` / `prism` / `add_quad`，不引入新类型：

| 构件 | 做法 |
|---|---|
| 金砖地 | 1.6 m 分格，缝宽 6 cm 露出底色 |
| 室内柱网 | 柱础（收分棱台）+ 柱身（收分 8%）+ 柱顶雀替 |
| 梁架 | 双向额枋 + 短柱，形成可见梁层 |
| 天花 | 井字格 + 暗色彩画底面 |
| 藻井 | 四层同轴棱台，半径按 0.74 递减，顶心宝珠 |
| 宝座 | 须弥座 + 座身 + 靠背 + 侧屏 + 香几 |

**藻井与屋顶几何同构**：都是「等高环逐层内收 + 抬高」；屋顶收成一条脊，藻井收成一个点。同一套 loft 逻辑可跨尺度复用。

开关在 `Hall.interior`（默认 True；大场面全开，远处配房可关）。

## 3. 立面与铺作

- **隔扇四件套**：外框（0.10 m 棂条）+ 竖棂 3 道 + 横棂 4 道 + 下部裙板。太和殿正面 11 间 × 4 扇 = 44 扇，每扇 14 个构件。
- **正面中间三间做成通透门洞**（不建墙面）——这是必须先做的前提，否则内檐装修做得再细也看不见。
- **铺作层重写**：原来是「一圈方块」，现在每攒含栌斗（0.92 m 见方）+ 三跳华拱（逐跳外挑 0.62/0.60/0.56，逐跳收窄 0.84/0.74/0.64）+ 跳头散斗 + 下昂斜杆，共 20 个 box；太和殿一圈约 120 攒。

## 4. 光照

太阳高度角 48° → **26°**（`light_dir=(0.50,-0.62,0.44)`），影子拉长一倍。`amb_k` / `sun_k` 已参数化，反差直接由两者之比控制。

低太阳下朝南坡面入射角变大、屋顶偏暗，这是**几何决定的**（`cos θ` 变小），不是调色问题；补偿方向是把 `sun` 调暖而非提亮。
