# 后期链与色调映射反调曝光（gugong 第五轮）

承接 [gugong 首版总览](documents/active/gugong-2026-11-01-4f6ab4e1.md)、[重檐通高反解](documents/active/gugong-2026-11-01-bbc11c5c.md)、[LOD 与内景/外景同轮推进](documents/active/lod-gugong-60-4-71-4-tri-c2a922db.md)。

几何停在 **71.4 万 tri / 138 万顶点**，本轮不加几何，只加后期链——因为「画面平」的成因一半不在几何。

## 核心判断

程序化 CPU 渲染器的每个像素亮度范围很窄：几何再密，也读不出「阳光」。**补后期链是本项目性价比最高的改动：1600×1000 约 0.9 s，2400×1500 约 2 s。**

## render/post.py（117 行，纯 numpy）

```
bloom(img, threshold, levels=5, strength):
    bright = np.maximum(img - threshold, 0.0)   # 逐通道截取亮部
    cur = bright
    for i in range(levels):
        cur = _down2(cur); cur = _box_blur(cur, 1)   # 2x2 平均 + 可分离 3x3
        out += _up2(cur, H, W) * spread**i
    return img + out * strength

tonemap(img, "aces"):   # Narkowicz: x(2.51x+0.03)/(x(2.43x+0.59)+0.14)
```

`render/raster.py` 在成像后串接 `bloom → tonemap → vignette`，`save()` 的 gamma 硬化不变；后期参数作为 `render(..., bloom_k, bloom_th, bloom_levels, tonemap_mode, vignette_k)` 参数暴露，便于单图关闭。

## 踩坑：按亮度「放大」≠ 截取亮部

错误写法（峰值被放大 1.7 倍，整幅图过曝成一片奶白）：

```python
bright = img * np.clip((lum - threshold) / threshold + 1.0, 0.0, None)
```

正确写法就一行：`bright = np.maximum(img - threshold, 0.0)`。判据：泛光只应来自**绝对亮度超过阈值**的像素，任何对原像素的乘性缩放都会把暗部一起抬进泛光。

## 曝光必须跟着 tonemap 反调

加 ACES 后原 `sun_k=1.35` 让琉璃瓦落在线性 1.30、曲线后仅 **0.79**（读成灰黄而非金）。这是**色调映射曲线决定的，不是颜色参数问题**：

| | 线性值 | ACES 后 |
|---|---|---|
| 琉璃瓦 0.96 × sun_k=1.35 | 1.30 | 0.79（灰） |
| 琉璃瓦 0.96 × sun_k=2.60 | 2.50 | 0.90（金） |
| 地面 0.40 × sun_k=2.60 | 1.04 | 0.72 |

定案：`sun_k=2.60`、`amb_k=1.30`。**通则：任何加色调映射的改动都必须重扫 sun_k/amb_k；曲线肩部会系统性吃掉高光饱和色，靠调材质颜色是拧不回来的。**
