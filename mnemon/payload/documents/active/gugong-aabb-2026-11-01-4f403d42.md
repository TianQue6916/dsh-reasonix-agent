# gugong 第十四轮：布局审计判据与近景细节（2026-11-01）

承接 [首版总览](documents/active/gugong-2026-11-01-4f6ab4e1.md)、[重檐通高反解](documents/active/gugong-2026-11-01-bbc11c5c.md)、[后期链与色调映射](documents/active/gugong-71-4-tri-2026-11-01-b66ae6a4.md)。本轮 commit `70b2598`，产物 115.6 万 tri / 生成 21.8 s / OBJ 346.9 万顶点。

## 1. 把「穿模」从肉眼找变成可判定

前几轮挂着的「02/03 近景有屋顶穿插」定位不到 —— 在 2000 px 里肉眼找 2 m 的穿插本来碰运气。做法：

- `core/mesh.py` 加 `Mesh.grp(name)` 上下文管理器：`with m.grp("hall:太和殿@0,305"):` 把区间内写入的三角形累加成**世界坐标 AABB**，存 `m.groups[name] = [x0,x1,y0,y1,z0,z1]`。渲染完全不用它，纯诊断元数据。
- `audit_layout.py`：对所有 group 两两求 AABB 交，输出「重叠对 + 三个方向的 overlap 分量」。

首跑 **174 对重叠**，其中实质穿模 3 类：

| 冲突 | overlap 数据 | 根因 |
|---|---|---|
| 东西六宫西配房 vs 院墙 | `ox=2.10 oy=35.80 oz=5.50` | **两套院墙系统**并存：`build_walls` 另画一套 x=±108 竖墙，而院落西配房正落在 108..114 |
| 体仁阁 vs 分隔宫墙 | 门厅 y 182..205 vs 墙 y 200..203 | `cy=196` 跨在墙线上 |
| 南三所正殿 vs 东西配房 | `ox=4.40 oy=14.00` | 台基 24 宽（±12）吃掉配房（±8.5..±13） |

修完剩 **114 对**，全部是墙-墙 T 形接头与「随墙门嵌在墙里」—— 设计使然。**判据留在仓库里**：改动布局跑一次即可回归，不必等渲染出来看。

## 2. 反直觉：中景「黄瓦横穿红墙」不是碰撞

audit 干净后那片横带**仍在**。真因是高度接近导致**颜色粘连**：东西六宫院墙 4.6 m + 0.5 m 黄瓦压顶 = 5.1 m，配房屋面 3.8 + 1.6 = 5.4 m，两种黄在 2400 px 鸟瞰里连成一条横带。修法不是挪几何，而是拉开材质分离度：院墙提到 **6.2 m**、压顶收窄到 **0.34 m**，横带消失。

推论（可复用到其他程序化场景）：**AABB 交集为空不代表视觉上不冲突；同色系 + 同高度的两个面在远景会合并成一个读错的对象。** 审计工具只能证伪几何碰撞，不能证伪「读成一体」。

## 3. 瓦件尺寸按则例取值，而不是拍脑袋

新写 `_tube(m, a, b, r, segs=4)`：断面 `p = c + s·r·cosθ + v·r·sinθ, θ∈[0,π]`，底面不封（贴瓦面）。segs=4 时每段 8 tri，与原来的方杆同价，但形状对。

尺寸来源：清工部《工程做法则例》瓦件表 —— 二样筒瓦直径 6.5 寸 = **0.208 m**、二样板瓦宽 1.1 尺 = **0.352 m**（1 营造尺 = 0.32 m）⇒ 半圆半径 **0.104**、垄间距 **0.36**。原参数 0.13 / 0.44 比则例偏大 25%，近景会读成「粗杆」。

## 4. 近景细节修复（按视觉收益排序）

1. **`gable_roof` 补齐壳体**：原先只有两片斜坡 + 两块山花，从下看是**悬空斜板**，仰角过 30° 屋顶下沿漏光。补底面 + 檐口瓦口（0.16 m，按则例「板瓦高 ×1/3 作底台 + 板瓦自身高」）+ 山面博缝。
2. **`_dougong_band` 去掉外扩大盒**：原外扩 0.55 m 把每攒斗拱全包住，近景是一整片青平面。改成贴墙暗色底 + 连檐，斗拱凸出墙面，可数出攒数。
3. **斗欹 + 斗耳**：栌斗从干净方盒改成「下部收分 **0.74** → 斗身 **0.92** → 顶部四边斗耳」，散斗同样加斗耳。
4. **砖缝（零几何）**：`shade_split` 里按 **0.48 × 0.24 m** 逐皮错缝（`u + mod(course,2)*0.24`），并按相机距离淡出 —— 不淡出时 2400 px 鸟瞰出摩尔纹。
5. **瓦当从方块改圆柱**：`prism` n=6，直径 0.208。一排方块读成「黄色齿柱」，一排圆柱才读成檐口。

## 5. 附带修掉的一个 host 侧 bug（可复用）

`star-audit.py` 的 `gh()` 用 `curl -m 20` 拉 `/user/starred?per_page=100`（响应约 200 KB）会在传输中被掐断，`json.loads` 报 `Unterminated string starting at char 214155`。改成 `-m 90 --compressed` + 三档重试后跑通。**判据：凡是 curl 取分页大响应，超时值必须按体积估，不能按「一个请求」估；截断的错误会伪装成 JSON 解析错误。**

同一脚本的另一条经验：仓库名会迁移（`Microsoft/vsce` → `microsoft/vscode-vsce`），直接 PUT 会 307 且 star 落在新仓库上，用旧名复查永远 404。故需 `canonical()` 先解析 full_name 并缓存。
