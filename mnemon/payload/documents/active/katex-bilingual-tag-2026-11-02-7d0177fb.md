# KaTeX / bilingual 转换的公式质量门禁与修复手册

适用场景：把 OCR 出来的数学/CS 教材（Convex EE364a、LALD、Real Analysis 18.100B、Probability 6.041、CLRS、Mackay、Strang 等）转成 `*.bilingual.md` 后，做公式层的静态质量门禁与批量修复。
相关文档：`ae3c93cb-ce27-47f0-a37d-1bbc59d11299`（bilingual 成品静态审计规则体系 R2/R6/R7/R8/R9/R11/R12/R13，口径互补）、`72959942-68c1-4910-8712-e23e43c43b62`（heredoc 转义坑，与本篇「反斜杠被吃」同源）。

## 1. 门禁口径

一次 KaTeX 全量扫描的输出形如 `formulas 98502, failed 14, files with issue 31`。三个数字含义不同，不要混用来判「修完了」：

- **`failed`**：KaTeX `throwOnError` 抛错的数量 —— 这是硬门禁，目标 `failed 0`。
- **`issue`**：含 fail 的文件数。
- **`warn`（strict）**：如 `unicodeTextInMathMode`（math 内直接出现中文未包 `\text{}`）。不影响 `failed 0`，可在后续批次统一处理。

**必须先跑 `.bak` 基线再断言「我修好了」**。本轮用改动前 `.bak` 跑同一命令得 `failed 14`，改动后仍 `failed 14`、逐行 diff 只少 11 条 warning —— 结论是这 14 条是**既有**缺陷、与本轮 `<` 转义无关。没有基线就会把既有账错记成回归，或把无进展报成有进展。

**口径分层**：基线常是「98 份」子集，全仓可能是 595 份，两个口径的 `failed` 数不可比。本轮基线 14 条清零后，全仓跑出 `failed 137 / issue 106`，全部集中在 12 个文件。汇报时必须写清分母。

## 2. 四类 fail 与各自修法

| 类 | 表现 | 修法 |
|---|---|---|
| `Multiple \tag` | 一个 `aligned` 里多个 `\tag`，KaTeX 不支持 | 拆围栏：多重 `\tag` 拆成多个独立 ```math 块，续行用 `\phantom{...}` 保住等号对齐 |
| `Can't use function '$' in math mode` | math block 里混进 `$` | 把中文勘误移出块（一字不删），不要在块内给 `$` 加转义 |
| `Undefined control sequence` | OCR 把控制词粘连：`U\SigmaV^{T}`、`\OmegaP`、`$\*$` | 按上下文断词：`U\Sigma V^{T}`、`\Omega P`、`\ast` |
| `Expected 'EOF', got '&'` | 行内公式塞了 `aligned` 内容、或被跨行切断；或整段中文正文被塞进 ```math 围栏 | 重写结构；后一种是「正文与公式边界塌了」，与前三类不同病，需回原文核对段落归属 |

## 3. 最贵的坑：`aligned` → `align` 会静默丢 `\tag`

看似「一行改名」的捷径，实测在 KaTeX 0.19：

- `align` 多行各带 `\tag` 时**不抛错**，但**只渲染第一个 `\tag`**，其余编号静默丢弃；
- 实测 `class="katex-tag"` 只出现 1 次，HTML 里根本查不到 (4)(5)。

结论：**`throwOnError` 型门禁查不出这一类**。校验器说 passed，页面上编号却少了两个 —— 这是「门禁给假安全感」的典型案例。唯一可靠改法是第 2 节第一行的拆围栏 + `\phantom`。

判据：改动后除 `failed` 外，还要数 `class="katex-tag"` 出现次数是否等于源码 `\tag` 次数。

## 4. 反斜杠在传递链路上被吃（第三次，同一家族）

| 症状 | 原意 | 现象 |
|---|---|---|
| `\x08inom` | `\binom` | `\b` → 0x08 退格 |
| `\v` 变成 0x0B | `\vec` 等 | `\v` → 0x0B |
| `\]\[` | MATLAB 左除 `] \ [` | `\ ` 被折掉 |

实例：`p = [(a1-a2)';(a1-a3)'\]\[(b1-b2);(b1-b3)\];`，正确写法是 `p = [(a1-a2)';(a1-a3)'] \ [(b1-b2);(b1-b3)];`。

判据与规避：凡走 heredoc / `echo -e` / `printf` 的链路都有此风险；**写含 `\` 的内容优先用文件写入或 Python raw string**，并在写完后对 `\\` `\b` `\v` `\ ` 做一次 grep 抽检。同一会话出现三次 `\b`、`\v`、`\ ` 不是巧合，是通道问题。

## 5. 两个「验证器自身有 bug」的假警报

1. **同行为多处替换时 `col` 会失效**。前面的 `<` → `\lt ` 让同行后续列全部 +3。按原始 `col` 校验会报大量「bad」，全是假警报。正确做法：按 `(line, col)` 升序累加 `+3` 偏移再比对。（`apply` 一直是倒序替换，所以真文件没受影响 —— 错的只是校验器。）
2. **`difflib.SequenceMatcher` 不能验单字符替换**。它会把 `\lt ` 的 `\l` 启发式对齐成 equal，报 `replace '<' -> '\\l'` 的假错。换手写双指针逐字符比对后 `problems 0`。

这两条共同教训：**验证器本身有 bug 会给你假安全感，比没验证更危险**。批量写操作的每条验收都必须自带「已知会发生什么」的预期值，不能只看「是否报错」。

## 6. 假阳性：裸 `$` 让 math mode 吞掉中文

`prob_chunk06_p251-300.bilingual.md:669` 报 HIGH 且 `carried: true`，但根因在 L668：OCR 把 `$\lambda(y) = 1/(5 - y)$` 拆成孤立一行的 `$,X(y) = ( 5 - y)` 与 `1/`，该行有 **5 个 `$`（奇数）**。孤立 `$` 让第 3、4 个 `$` 配对，把中间整段中文拖进 math mode —— 改前 KaTeX 对这行报 11 条 `unicodeTextInMathMode`（`与`/`；`/`本`/`式`/`已`/`按`/`语`/`义`/`还`/`原`/`为`），并 carry 到 669 行把 `<!--` 当成标签起始。

正确修法是**把 L668 的裸 `$` 改成 `\$`**（1 字节净增），而不是给 `<` 加转义。`<!--` 是 HTML 注释，改它才毁内容。判据：先看 `$` 计数奇偶，再决定改哪一端。

## 7. 裸 `<` 的批量转义

全库 569 处 / 97 文件，`<` → `\lt `（带尾空格）。重扫后 HIGH 0 / MED 0 / S4 0 / 控制字符 0，INFO 1,218 按契约未动。批量后必须按第 5 节做带偏移的校验。

## 8. 术语方向契约

本项目中文主体的术语形式统一为 `English（中文）`（英文在外、中文短注在括号内），依据是用户语言契约「技术术语保留英文原文，首次出现可用括号加中文短注」。反方向 `中文（English）` 属偏差。

批量反转**不能机械执行**，三个条件同时满足才反转：括号内是小写英文术语、括号外是中文、且不在行首 `**...**` 小标题位置。固定结构必须保住 —— `**Idea（一句话本质）**` 反转成 `**一句话本质（Idea）**` 才是真破坏。

验收附带一条：**中文字符总数改前改后差 < 1%**。反转只搬动字符位置，总数不应大变；变化大说明误删内容，必须回滚。

## 9. 分片合并的验收项

拆片-合并（16 片 → 4 份完整卷）时，除 `formulas failed 0` 外还要核：

- **接缝**：每组相邻片「上片末 3 行 ∩ 下片首 3 行」`dup=0`，无重复段落。
- **标题层级**：合并后 H1 数量应为 1（本轮出现 3 个 H1，因分片正文里塞了 `# Problem 4…`）。
- **首标题与内容一致**：分片模型会看错上下文（`FINAL1_A_f` 标题写 Problem 1、实际承接 Problem 6）。
- **「〔原书缺页：第 N 页起〕」类自述必须回原件核对**。本轮该自述是编造的 —— 第 28 页起完整内容就在下一片 `FINAL06_A_e` 里且已合并。同类分片元信息还虚构删了 2 处。**本会话第三次遇到模型凭空说「原文缺失」**，默认不可信，须核页码与相邻片内容。
- **题号序列**单调不减、无缺号。
