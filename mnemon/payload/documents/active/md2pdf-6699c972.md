# md2pdf 公式块导出失败：根因、修复与未决项（2026-11-08）

承接 [md2pdf / md-open 落地实现（18f9faa7）](18f9faa7-6c6d-41be-97a4-9aa380c911b4) 与 [MarkText 自带渲染链路导出横版 A4 PDF（d42cd4e5）](d42cd4e5-d2bd-437b-9da4-7bee812d9f33)。那两份讲的是"用 MarkText 自己的渲染链路导出"这条方案本身；本篇是之后暴露出的**公式块渲染缺陷**的定位与修复，属于同一条链路上的新一层知识。实现位置：`/home/tianque/.local/bin/md2pdf`（单文件 CLI，约 290 行）。

## 结论（一句话）

问题不在字体，也不在渲染引擎，而在**块级公式的边界**：导出走的解析器比编辑器预览严格，`$$` 未独占一行时整块被降级成普通段落/代码块，LaTeX 源码被原样画进 PDF。

## 根因：同一个 .md 有两条解析路径

| 观察位置 | 走的解析器 | 对 `$$` 的容忍度 |
|---|---|---|
| MarkText 编辑器实时预览 | muya 的 Block 解析器 | 宽松，`$$` 紧贴正文也能识别为公式块 |
| 文件 → 导出（`editor.exportStyledHTML()`） | 导出链路 | 严格，`$$` 必须独占一行且前后有空行，否则降级为段落/代码块 |

这解释了"用户自己在编辑器里看是好的、导出的 PDF 里是乱的"：**预览与导出不是同一个解析器，不能用预览结果去验收导出**。症状表象是"灰底框里躺着 `\underline{V}_i(h)=\max_{s_i}...`"，即被当成代码块。

## 证据：四组对照实验

判据取 `pdftotext` 输出里 LaTeX 源码的残留计数（0 = 已被正确渲染为公式）：

| 写法 | 修复前 | 修复后 |
|---|---|---|
| `$$` 前后有空行 | 0 | 0 |
| `$$` 紧贴正文（无空行） | 1（源码残留） | 0 |
| ` ```math ` 围栏 | 1（源码残留） | 0 |
| `\begin{aligned}` 块 | 1（源码残留） | 0 |

修复后对四个测试文件统一复测，源码残留全部为 0。

## 修复设计

1. **导出前规范化到同目录临时副本** `.{name}.md2pdf-norm.md`，导出完成后删除；**原文件一个字节都不改**。
   - 放同目录而不是 `/tmp`，是为了让正文里的相对图片路径仍然有效。
   - 规范化内容：`$$` 拆成独立行并前后补空行；` ```math ` 围栏转成 `$$` 块。
   - 提供 `--no-normalize` 关闭该行为。
2. **版本守卫**，解决"改了导出器但旧 PDF 因为 mtime 更新反而被跳过"的坑：
   - `EXPORTER_VERSION = "2"` 写入 `~/.cache/md2pdf/version`；版本变化时忽略"已最新"判据，强制重建一次，用户无需手动 `--force`。
   - 该坑实测过：修好逻辑后旧 PDF 仍被判"已最新"跳过，加守卫后能重建并提示"导出器已更新，本次忽略「已最新」判据"。
   - `--force` 仍然保留。

## 顺带修的环境坑：XAUTHORITY 会话重启后 cookie 改名

- 现象：导出报 `Missing X server or $DISPLAY` / `UnableToOpenXServer ':0'`，`import`、Chromium 都起不来。
- 原因：代码原先相信继承来的 `XAUTHORITY`，但 2026-11-07 会话重启后 cookie 文件名从 `.mutter-Xwaylandauth.CFYFY3` 变成 `.K5JXX3`（实测可用路径 `/run/user/1000/.mutter-Xwaylandauth.K5JXX3`）。
- 修法：先 `xdpyinfo` 真连一次验证，失败再按 mtime 遍历候选 auth 文件。可复用的教训：**不要信任环境变量里的 X auth 路径，要做一次真实连接探测**。

## 未决：中文 Type3 字体（体积 vs 兼容性）

- 中文被 Chromium/Skia 转成 Type 3 字体对象：165 个 Type3、4651 个字符里 2891 个由 Type3 承载。原因是系统中文字体为 `NotoSansCJK-Regular.ttc`（CFF 集合），Skia/PDF 无法子集化嵌入，只能逐字形画路径。
- 换 TrueType 中文字体后：Type3 降到 53，PDF 1225 KB → 287 KB。poppler/mutool 下逐页看过渲染正常。
- 风险：Type3 在部分阅读器（如 WPS）兼容性差，是残余显示问题的头号嫌疑。
- 现状：挂在 `MD2PDF_CJK_FONT` 开关上，**未默认启用**，等用户决定。

## 遗留待办

- 用户的原始 md（`~/桌面` 下 `006-r16-*`、`度量三公理-*` 已被整理移走）路径未提供，扫描 `/home/tianque/桌面` 与 `~/文档` 只找到 0–2 个 md，无法确认那份文件；需要用户给路径或自己重开一次 md 触发重建。

## 可迁移的方法论

- 先分清症状归属：Type3 字体问题真实存在，但与本症状无关，早期把两者混在一起会白跑几轮。
- 验收必须用导出产物本身（`pdftotext` 残留计数、逐页截图）当判据，而不是编辑器预览。
- 改渲染/导出逻辑时，必须同时处理"已生成产物被跳过"的缓存判据，否则修复对老文件不可见。
