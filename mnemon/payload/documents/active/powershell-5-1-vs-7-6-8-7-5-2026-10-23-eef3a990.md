# PowerShell 5.1 vs 7.6.8：实测对照与替换边界

**日期**：2026-10-23 ｜ **机器**：Windows（用户目录 `C:\Users\27063`）｜ **触发问题**：用户问「不能替代吗，用 7 换掉 5？5 对 agent 不太友好」

## 一、结论先行

1. **5.1 本体不能卸载**（OS dependency，硬删会破坏 Windows；社区与微软立场一致）。可做的只是**改调用点**让 dsh 侧走 `pwsh.exe`。
2. 5.1 对 agent 的真实痛点不止"旧"，最狠一条是 **`$OutputEncoding = us-ascii`**：中文经管道喂原生命令会**静默丢字**（不报错、结果错）。
3. 本机 `powershell -File x.ps1` 被拒签名检查，**根因未定位**，只能靠 `-ExecutionPolicy Bypass` 绕过 —— 这是 dsh 里所有脚本调用都挂 Bypass 的历史原因。

## 二、对照实测（同一脚本、同一调用方式）

| 探测项 | 5.1 | 7.6.8 |
|---|---|---|
| `$OutputEncoding`（管道给原生程序） | **us-ascii** | utf-8 |
| `"中文输出测试" \| findstr 中文` | **返回空（rc=0）** | 返回 `中文输出测试` |
| `-File x.ps1`（不带 Bypass，UTF-8 无 BOM） | **拒绝执行：not digitally signed** | 跑通 |
| `ForEach-Object -Parallel` | False | True |
| `ConvertFrom-Json -AsHashtable` | False | True |
| `Get-Content -AsByteStream` | False | True |
| runtime | .NET Framework 4.8 | .NET 10.0.13 |
| `chcp` | 65001（ACP utf-8） | — |

`Get-ExecutionPolicy -List` 两侧：

```
5.1 : MachinePolicy/UserPolicy/Process Undefined | CurrentUser RemoteSigned | LocalMachine Unrestricted
7.6.8: …… | CurrentUser Undefined | LocalMachine RemoteSigned
```

## 三、`-File` 被拒签名：已排除项与未定位点

**现象**：5.1 对任何 `.ps1`（Temp 目录与用户根目录都试过）在 `-File` 与 `& 'path'` 两种调用下均报 *"is not digitally signed"*，稳定复现；加 `-ExecutionPolicy Bypass` 可绕过。

**已逐条排除**：
- 文件无 `Zone.Identifier`（`Get-Item -Stream *` 只有 `:$DATA`）
- `__PSLockDownPolicy` 未设置
- SRP 注册表键存在但为空壳（DefaultLevel/AuthEnabled=0/children 全空），`AppIDSvc` 为 Stopped
- 注册表 `HKLM:\SOFTWARE\Microsoft\PowerShell\1\ShellIds\Microsoft.PowerShell` = Unrestricted，`HKCU:` 同名键 = RemoteSigned

**结论**：按 ExecutionPolicy 语义本地未签名脚本本应可跑，但事实不行。**根因未查清**，不要在这上面继续猜；工程上按"必须带 Bypass"处理。

## 四、社区一手经验（SO / GitHub）

- [SO 70931513 How to uninstall PowerShell 5.1](https://stackoverflow.com/questions/70931513/how-to-uninstall-powershell-5-1-on-windows-after-installing-72)：38 分采纳答案开头即 **"You don't."** —— 5.1 内含未开源专有代码；硬删「will very literally break parts of Windows」；21H1 起仍是 OS dependency。另一答案类比：**像 cmd.exe 一样不会消失**。
- [SO 76153269 powershell not recognized](https://stackoverflow.com/questions/76153269/powershell-the-term-powershell-is-not-recognized-as-the-name-of-cmdlet)：装了 7 后 `pwsh` 可用但 `powershell` 不可用，提问者跑的是 Ansible/pywinrm 且**无法改这些调用方**。⇒ `powershell` 不是 `pwsh` 的别名，是**两个独立名字**，外部生态（Ansible、pywinrm、SCCM、部分 MSI custom action）硬依赖前者。
- GitHub PowerShell/PowerShell 相关 issue 检索未命中「用 pwsh 顶替 powershell.exe」的官方路径（`"replace" pwsh "powershell.exe" in:title` = 0 条）。

## 六、三个方案与取舍

- **A 硬删 5.1 —— 不可行**。`System32\WindowsPowerShell\v1.0` 受 WRP 保护，有 WOW64 影子副本，WinRE 紧急 shell 也依赖它。
- **B 改调用点（推荐）** —— 逐个 `powershell.exe` → `pwsh.exe`，每改一处 smoke test。粒度可控、可回滚。
- **C PATH shim 全局劫持 —— 不推荐**。名字叫 powershell 实际跑 7，报错信息指向错对象，排查会先怀疑错目标；且 `Get-WmiObject` 在 7 里是 CIM shim，参数不完全等价，差异**静默**。

## 七、若执行 B 的落地顺序（按风险倒排）

1. `edge-lite/*.py` 3 处 —— 纯工具脚本，坏了不影响 dsh
2. `storages/tools/*.ps1` 的 12 个提权包装 —— 按需触发、单条验证成本低
3. `launch-dsh.ps1` + 两个 GitHub-Mirror 计划任务 —— **最后做**，改前先备份任务 XML（`schtasks /query /xml`）保留 5.1 回滚路径

## 八、可复用教训

- 判断"能否换掉系统自带解释器"时，先分清**解释器本体**（OS 组件，动不得）与**调用点**（可改）。问句"能不能替代"通常真正的答案是改调用点。
- agent 场景下选解释器，第一优先级是 **stdout/管道的编码契约**，不是版本号。`$OutputEncoding=us-ascii` 这类设置会让"看起来成功"的命令静默产出错误数据。
- 工具名 ≠ 实现。用 shim 把旧名字转发到新实现，会把错误归因成本永久外化给以后的排查者。
