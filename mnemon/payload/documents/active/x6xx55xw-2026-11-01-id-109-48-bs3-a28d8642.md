# 旷世 X6xx55xW 关机自启续查（会话 afecf301，2026-11-01）

> 前序三篇：`f7c9342c`（60 天 26 次实证，初判 Realtek Wake-on-Pattern）、`8f426f8b`（推翻 WoL，转向 AC 边沿误触发）、`67873213`（AcRecoverySwitch 机理定案：同方 EC 固件的充电状态边沿，`BiosSupport=0`）。
> 本篇只记本次会话**新增**的事实与判据，不重复前序结论。前序文档一律未修改。

## 1. 本机硬件指纹（售后与刷固件的前置条件）

```
Win32_BIOS.SerialNumber            : 425052C32550470283      （与 Win32_ComputerSystemProduct.IdentifyingNumber 一致）
Win32_Bios.SMBIOSBIOSVersion       : N.1.21MRO16             （ReleaseDate 2025/7/24）
Win32_Bios.Manufacturer            : American Megatrends International, LLC.
Win32_BaseBoard.Product            : KUANGSHI-JIGUANG Series-X6xx55xW-B2
Win32_BaseBoard.Manufacturer       : MECHREVO
Win32_BaseBoard.SerialNumber       : Standard                 （底座序列号 OEM 未填，属正常，不是异常）
OS InstallDate                     : 2025-05-23 23:28:06
```

**关键推理**：`X6xx55xW-B2` 里的 `xx` / `x` 是**通配符占位**——一套 BIOS 覆盖旷世+极光多个 SKU，不是具体型号。因此官网路径里的模具号 `X6RP`（`KSX` = 旷世 X，`JGKS` = 极光旷世）与 SMBIOS 串 **不冲突**，不能据此判定「刷错机型」。

| 关机→启动间隔分布 | 13 / 14 / 15 / 17 / 18 / 19 / 21 / 30 / 34 s（中位 ~18 s） |
| 最早一次 | 2026-08-17 13:45:11 |
| 最近一次 | 2026-11-01 02:00:45 |
| System 日志最早记录 | 2026-08-09（`Get-WinEvent -Oldest` 实测，日志已滚出，8 月前无法验证） |

**这是本篇最有价值的单条判据**：社区「刷错 BIOS」案例是**必现 100%**；48% + 「第二次关常能关住」⇒ 触发器在**外部可变状态**里，不在固件的固定逻辑里。该结论与前序 `67873213` 的 EC 充电状态边沿解释互相印证，不冲突。

## 4. 两个已排除/纠正的误判

### 4.1 「那个 4.86 GB 的包是 BIOS」——错

`https://driver.mechrevo.com/d.mechrevo.com/driver/MECHREVO2025/GameBook/JGKS/KSX_X6RP_BZ_HB_260604.zip`

```
Content-Type: application/zip
Content-Length: 4,855,970,951   （4.86 GB）
Last-Modified: Thu, 04 Jun 2026 08:07:16 GMT
```

BIOS 固件一般 8–32 MB，4.86 GB 只能是**整机驱动合集**。另：该直链有防盗链，HTTP Range 取尾部 64 KB 拿到的是 **HTML 页**（`<!DOCTYPE`，内嵌 `requestInfo` + token），zip 中央目录/EOCD 全部 `at -1` —— 即 Range 探测在此域名上不可用于判断包内容。真正的 BIOS 更新走控制中心或官网「BIOS」分类。

### 4.2 「飞智 BS3 是手柄」——错，是散热底座

用户纠正：**飞智 BS3 是压风式笔记本散热底座**。设备侧证据：

```
USB\VID_367B&PID_1919\5&28CF2CD7&0&9      USB 输入设备            Status = OK
HID\VID_367B&PID_1919\6&2E87F5B9&3&0000   HID-compliant mouse     Status = OK   （mouhid, DriverVersion 10.0.26100.9818, 装于 2026-07-13）
ROOT\FEIZHI_VIRTUAL_MOUSE\0000            Feizhi Pointing Device  （空间站软件造的虚拟 HID）
ROOT\FEIZHI_VIRTUAL_KEYBOARD\0000         Feizhi Virtual Keyboard
BTHLE\DEV_DC7F6429FC2F\7&1F3B9ABF&0&DC7F6429FC2F   FlyDigi BS3     （BLE 通道）
HID\HID_DEVICE_SYSTEM_VHF&COL02/COL03\2&142C91CB&0&0001/0002  VHF 虚拟 HID（2026-10-23 装）
```

⇒ 底座当前**同时占 USB HID + BLE 两条通道**，USB 那条在 S5 下是候选 wake 源。
**但官方文档说它本不需要接笔记本**：独立 Type-C 供电口（BS3 ≥PD 18W，Pro ≥PD 27W），控制走蓝牙，蓝牙断开即停转（或延迟约 1 分钟）。所以「改独立 PD 供电」是零风险的第一步，同时省下 18W 抢电（用户常用 100W 氮化镓）。

## 6. 社区五层解法（按动手成本，含真实有效率）

| 层 | 做法 | 有效率 | 代价 |
|---|---|---|---|
| 1 Windows | 逐设备取消「允许唤醒」+ 关快速启动 + 清唤醒定时器 | 低（对 S5 不彻底） | 零 |
| 2 BIOS | `ErP Ready` = `Enabled (S4+S5)`，关 `Wake on USB` / `Always On USB` | **中高，但取决于选项是否还在** | 失去 WOL / 关机 USB 充电 |
| 3 驱动 | 禁用/卸载虚构 HID 的第三方驱动 | 中 | 要重装 |
| 4 物理 | 拔适配器 / 带开关插排 / 带开关 USB 线 / 静电释放 | **接近 100%** | 每次动手 |
| 5 固件 | 刷回老界面 BIOS、按板号找人刷、改 DSDT | 高但风险大 | 变砖 |

要点：
- 机械革命官方对这块 BIOS 的说法是「**拔了电源插头解决**」，等于承认 S5 不切 +5VSB 且控制台开关无效（新浪投诉 17385131059）；同一投诉称「**老界面 BIOS 没这问题，新界面 BIOS 关不掉 USB 给电**」。
- `ErP` 与 PCIe 唤醒（WOL）在部分 BIOS 互斥；某些板子上 `USB Power Delivery in Soft Off State (S5)` 完全无效（Chiphell 2673165）。
- 机械革命售后会教的一条：设备管理器 → 显示隐藏设备 → 卸载 `ACPI Driver` → 卸载控制中心 → 重启 → 重装控制中心（贴吧 8386723308）。
- 硬核派做法是改 DSDT 在 S5 给 USB 控制器断电（pcbeta 2071261 的 `USB_OFF` SSDT），Windows 上无等价物，但反证了机理判断。

## 7. 本篇的核心取舍洞见：ErP 优先，其次「插座 + 保留来电自启」

不动固件时的判定顺序（每步都能出结论）：

1. **进 BIOS（F2）确认 `ErP` / `EuP` / `Wake on USB` / `Always On USB` 是否存在**。这是**判定性实验**：选项不在 ⇒ 官方砍了这条路，第 2 层直接出局，别在软件层浪费时间；选项在 ⇒ 设 `Enabled (S4+S5)` 后关机 3 次验证。
2. 底座改独立 PD 供电 / 关闭空间站的两个虚拟 HID ⇒ 关机 3 次（每次等 3 分钟不碰设备）。
3. **「来电自启」与「关机不自启」不是同一开关的两面**：把日常关机路径改成「Windows `shutdown /s` → 黑屏后插座断电」，主板进 G3、+5VSB 消失，物理上不可能自启；想开机时插座通电，靠来电自启，**顺带白拿远程开机能力**。这与 `8f426f8b` 里「必须保留通电自启」的约束一致，只是把关机路径从 S5 换成 G3。代价：插座断电后无法远程唤醒；对 SSD 的影响靠「先正常关机、再断电」规避。
4. 都不满意再考虑刷回老界面 BIOS 或走售后。

**为什么用户之前关「来电自启」方向反了**：关掉它使唯一关机路径变成 Windows S5，而 S5 恰是 +5VSB 不断电这个 bug 的温床。
