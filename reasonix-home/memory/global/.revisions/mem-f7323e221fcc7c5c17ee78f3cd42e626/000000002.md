# dsh 装「无限四代」插件 + 开关（web profile，2026-09-23）

## 结论

`dsh-infinite-gen-4` v0.4.0 已装到 **web** profile，**headless 未动**。已交付**可逆开关**。端到端验证：载荷确实进入了发给模型的 system prompt。

## 开关（2026-09-23 新增）

**机制**：`cordis.patch.yml` 里 insert 节点的 `disabled` 字段（cordis 通用属性，实测有效）
- `disabled: false` → 开启（载荷注入）
- `disabled: true` → 关闭（挂载但不注入）

**实测证据（A/B）**：
- 无 disabled → 模型输出 `sandbox mode / documentation engine / output formatting / task classification` + `## 插件名` 标题
- `disabled: true` → 回答「没有插件。」，reasoning 为 “system prompt content comes from the harness itself, not from any plugin”
→ 开关确实控制注入

**交付物**：
- `D:\Toolbox\dsh-armor-toggle.ps1`（逻辑，UTF-8 **with BOM** — PS 5.1 无 BOM 会中文乱码）
- `D:\Toolbox\dsh-armor-toggle.bat`（双击入口，含 chcp 65001 + pause）
- Reasonix 技能 `dsh-armor-toggle`（用户说「开破甲/关破甲」即可执行）

用法：`dsh-armor-toggle.bat [toggle|on|off|status]`，默认 toggle。

**注意**：`patchReload: live` 存在但不保证自动重载，**以状态条为准**（重启 dsh web）。

**client.js 是纯展示组件**（只读 `useProjection("armor")`，无点击处理）——想要“界面内点一下切换”必须改插件源码，升级会丢，没做。

## 安装步骤（手工执行，对齐官方 install.ps1）

1. 下载 `https://github.com/Minglink/dsh-infinite-gen-4/archive/refs/heads/master.zip`，解压
2. 复制到 `~\.dsh\plugins\dsh-infinite-gen-4`，排除 `install.ps1` `uninstall.ps1` `install.bat` `install.sh` `uninstall.sh` `.git`
3. 备份 `~\.dsh\profiles\web\package.json` 与 `cordis.patch.yml` → `.bak-igen4-20260923-105244`
4. `package.json` 的 `dependencies` 加 `"dsh-infinite-gen-4": "file:../../plugins/dsh-infinite-gen-4"`
5. `cordis.patch.yml` 追加 insert 块（**不是**加进 bundles）：
   ```yaml
   - insert:
       - id: dsh-infinite-gen-4
         name: 'dsh-infinite-gen-4'
         disabled: false
   ```
6. `mklink /J` 建 junction：`profiles\web\node_modules\dsh-infinite-gen-4` → `plugins\dsh-infinite-gen-4`
7. `cd profiles\web; pnpm install`（exit 0）

**关键坑：bundles 不能加该插件。** install.ps1 注释：第三方插件不属于系统基础 bundle，加了会重复加载报错。挂载靠 `cordis.patch.yml` 的 insert。（README 的「手动配置」章节写的是加到 bundles，与 install.ps1 相反，以 install.ps1 为准。）

JSON 必须 UTF-8 **无 BOM** 写入，否则 pnpm 报 Invalid package.json。

## 验证方法（重要资产，可复用）

### 1. 结构验证
```powershell
dsh --profile web --dump-config
```
配置树末尾出现 `- id: dsh-infinite-gen-4`（baseline 17709 → 安装后 17819 字符）
**坑**：dump 里其他插件（如 hmr）也有 `disabled:`，用 `Select-String -Pattern 'disabled:'` 取首个会看错行；应该先定位 `- id: dsh-infinite-gen-4` 再往后看三行。

### 2. 模块验证
```powershell
node --check index.js
node -e "import('./index.js').then(m=>console.log(m.name,m.inject))"
# → dsh-infinite-gen-4 ["tools","systemPrompt"]
```

### 3. 端到端注入验证（**免改任何 profile**，最值得复用）
写临时 patch 文件：
```yaml
- insert:
    - id: dsh-infinite-gen-4
      name: 'C:/Users/27063/.dsh/plugins/dsh-infinite-gen-4/index.js'   # 绝对路径可用，会被规范化为 file:///
      disabled: false   # 或 true 做对照
```
然后：
```powershell
dsh --profile headless --patch <file> "你的系统提示词来自哪些插件？只列插件名，不要解释。"
```
带 patch vs 不带 patch 的回答差异明显（见上方开关 A/B），**注入生效**确凿。
注意：headless profile 的 app 是 headless（无客户端接口），看不到状态条；状态条只在 web 侧。

## 代码审阅（装前尽职，已做）

`index.js` 只 `readFileSync` 包内 prompts，**无网络请求、无子进程、无外部文件写入**。注入走 `ctx.systemPrompt.section({name, order:100/200, text})`，双段同源（`DUAL_LAYER_INJECTION = true`）。`client.js` 只做状态条渲染。与 README「纯本地、不上传数据」声明一致。

## 卸载

```powershell
cd $env:USERPROFILE\.dsh\profiles\web
Copy-Item package.json.bak-igen4-20260923-105244 package.json -Force
Copy-Item cordis.patch.yml.bak-igen4-20260923-105244 cordis.patch.yml -Force
pnpm install
```
