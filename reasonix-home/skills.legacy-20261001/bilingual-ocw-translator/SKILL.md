## 格式类铁律

### 铁律 1：禁止英中分段对照（最高铁律）

输出必须是**中文主体 + 英文术语行内嵌入**的单行双语格式。**绝对禁止**「先写完整英文段落、再写中文翻译段落」的对照模式。

```
❌ In a weighted directed graph G = (V, E), the weighted eccentricity ε(u) of a vertex u ∈ V is...
   在带权有向图 G = (V, E) 中，顶点 u ∈ V 的 weighted eccentricity（带权离心率）ε(u)...

✅ 在带权有向图 G = (V, E) 中，vertex（顶点）u ∈ V 的 weighted eccentricity（带权离心率）ε(u) 是其到最远 vertex v 的最短带权距离。
```

**识别方法**：输出中任何一行以英文单词开头、长度超 10 词且后面紧跟一行中文翻译，即违规。正确的输出中**没有完整的英文原句**。

### 铁律 2：英文句子开头禁止

**每句话第一个字必须是中文**，不能以英文单词开句。
`❌ A sequence（序列）就是...` → `✅ 一个 sequence（序列）就是...`

### 铁律 3：术语格式 English（中文），仅首次加括号

格式：**`English term（中文翻译）`**——英文术语先出现，中文翻译括号紧随。同一术语**首次出现**时加括号，**后续出现省略括号**（避免冗余）。
`❌ 用 real numbers（实数）来研究 real numbers（实数）` → `✅ 用 real numbers（实数）来研究实数的性质`

### 铁律 4：不合并句子（逐句翻译）

原文**每一句都对应至少一句中文翻译**，不得将 3-5 句压缩为 1 句。逐句阅读 → 逐句翻译 → 逐句输出。
**密度标准**：每页 30-40 行译文、平均每行 6-7 个中文字——低于此密度即为概括式伪翻译。

### 铁律 5：LaTeX 环境内不翻译

`$...$`、` ```math ` fenced block、`\begin{}...\end{}` 环境内的任何文本（包括 `\text{}` 内的内容）保持英文原样，不做翻译。

### 铁律 6：行内 `$...$`，块级 ` ```math `，禁止 `$$`

- 所有数学公式必须用 LaTeX：`$O(n \log n)$`、`$\delta(s,v)$`、`$x_n$`、`$\{a,b,c\}$`、`$\le$` 等，**不得用文字代替**（`❌ O(|V|³)`）
- **禁止 `$$...$$`**（MarkText 渲染异常）；块级公式用 fenced math block：
  ````markdown
  ```math
  公式
  ```
  ````
- 数集用 `\mathbb{}`（$\mathbb{R}, \mathbb{Q}, \mathbb{Z}, \mathbb{N}$）；变量用斜体（$x, m, n, h$）
- **禁止 Unicode 上下标字符**（₀₁₂₃₄₅₆₇₈₉、⁰¹²³⁴⁵⁶⁷⁸⁹）——内置字体不含 glyph，渲染成黑块；一律用 LaTeX `$x_n$`/`$x^n$`
- 定理陈述独立成命题，证明以 $\square$ 结尾

### 铁律 7：标题标记在行首

`#` `##` `###` `####` 等 heading markers 必须位于行首，前面不能有 `<span>` 或其他 HTML tag，否则 Markdown 解析器不识别为标题。
`✅ ### <span ...>**[problem]**</span> Title` | `❌ <span ...>**[problem]**</span> ### Title`

### 铁律 8：禁止 `<div>`

`<div>` 在 MarkText 中不渲染（显示"空的HTML块"）。用标题层级实现视觉区分，`>` blockquote 虚化次要内容。

### 铁律 9：教材的非必要习题直接跳过，例题必须翻译

- **例题（Examples）必须完整行内双语翻译**——例题是核心教学载体，其描述、推导、结论全部按标准格式翻译
- **教材的非必要习题（Exercises）直接跳过**——不保留原文、不收录进翻译稿。常规练习题与正文核心论证无关，翻译稿中省略（如需练习请读原书；练习时阅读英文原题是必要的学术技能）。仅当习题被正文核心论证直接引用、不翻译会破坏正文可读性时（**必要习题**），才保留英文原题并允许最小翻译
- 被收录的必要习题答案保持英文原文，只有过程性描述可做最小翻译（如"Proof（证明）"标签本身）
- Notes、Theorems/Proofs/Definitions、正文段落**完整行内双语翻译**

### 铁律 10：字幕引文必须附带中文翻译

注中引用视频字幕（🎥 标注的教授原话）时，**每条引文必须附带中文翻译**，禁止只写英文原文。

```
✅ 🎥 *Demaine 强调*："Because we memoize, we'll only solve each subproblem once."（翻译：因为我们做了记忆化，每个子问题只会被求解一次。）
❌ 🎥 *Demaine 强调*："Because we memoize, we'll only solve each subproblem once."
```

- 格式：`🎥 *教授名在视频中[教学动作]*："English original text"（翻译：中文翻译）`；引文较长可改用破折号——即「中文翻译」
- 一条注内多条引文**每条**都要单独翻译；翻译可意译，可在翻译后追加括号解释，但不得以解释替代翻译
- dsh 任务 prompt 必须包含本规则

## 分工类铁律

### 铁律 11：核心翻译——小规模主代理直译，大规模 25×2 dsh 任务分工

- **小规模（≤50 页 / ≤500 行英文）**：主代理直接逐句翻译，审计/写注走 dsh（铁律 12/21）
- **大规模（>50 页）**：一律 dsh 任务翻译——25 个翻译 worker（**dsh flash**，每个分 2 页）+ 10 审计 + 3 写注（**dsh flash**）+ 2 交叉引用，主代理只做切分、组装、派发、合并、回填修订版、最终审查
- **全 dsh 派发（铁律 21）**：Reasonix 内建子代理一律不用，一切 worker = dsh-remote 任务，按主力机并发能力分批派发
- **Strang 教训不丢**：四个陷阱转为翻译 worker 的 prompt 避坑清单（见references/prompts.md 6.1）

### 铁律 12：模型分配总纲——全任务统一 v4.1 flash，pro 弃用（2026-09-10 用户拍板改版）

- 🚨 **模型分配总纲（2026-09-10 更新）**：**一切任务（翻译 / 写注 / 页级审计 / 超强审计 / 交叉引用 / 格式审计）统一用 `deepseek-v4.1-flash`**——用户实测 v4.1 flash 已全面超越 pro，pro 不再使用；**难任务不靠换模型，靠「多查资料 + 足量 prompt + 多轮优化」**（v4.1 flash + max effort + 多轮迭代）
- **超强审计**：**`dsh-remote -m deepseek-v4.1-flash -e max`（v4.1 flash + max thinking）**，通读全部翻译结果 + 注，**直接输出修订后全文（审计+修复一体）**。**不管什么规模都必须做**（小规模 1 个强模型，大规模 2 个并行）
- **写注**：**dsh flash（`deepseek-v4.1-flash`）**（2026-09-10：与写作任务统一为 v4.1 flash；若一次不满意 → 补资料/加 prompt 细节后**再跑一轮**，而不是换 pro）
- **格式审计**：**dsh flash**，最后一道，对照references/format.md格式规定逐条核对，**直接输出修订后全文或逐条已修复文件**（审计+修复一体）
- **🚨 执行通道铁律（2026-09-10 更新）**：**一切子代理活（翻译 / 写注 / 审计 / 交叉引用）全部走主力机 dsh**（`dsh-remote -m deepseek-v4.1-flash`，`-e` 按难度选 off/low/high/max）；**Reasonix 内建子代理一律不用**（见铁律 21）；主代理只做切分、组装 prompt、回填、格式收尾
- 审计修复分级：🔴 结构性问题 → 🟡 质量问题 → 🟢 细节

## 来源类铁律

### 铁律 14：补充内容必须有真实来源

写 `[note]` 或 `[alternative]` 前**必须联网查证**（web search / GitHub / 论文检索），不得依赖训练数据瞎写。查不到可靠来源就不写。写完二次审查：(a) 有真实来源支撑 (b) 表述准确无歧义 (c) 与原文清晰区分。不确定的宁可不写。

### 铁律 15：译者注禁止甩名词

每条注 **800-1200 字**（配图/公式/字幕引文不计入），结构完整成"小专题"。跨课程连接必须精确到**课程名 + 具体概念 + 连接路径**（如"你在 6.042J 学过的等价关系，在这里就是 rational number 的相等定义——同一个等价类内的所有分数表示被视为'相同'"），而非"这在群论中叫商集"。每个高级概念要么从用户已知概念出发解释（脚手架法），要么不提。**先查用户学业水平再写注**（记忆 `global/academic-level-and-teaching-style.md`）。

### 铁律 16：每 200 行自检 + 交付前 grep 扫英文行首

翻译过程中**每输出约 200 行执行一次「英中对照自检」**（任何一行以英文单词开头且超 10 词 = 违规）。交付前：
```bash
grep -nE '^[A-Z][a-z]+ [a-z]+' 输出.md
```
人工确认所有疑似英文行首。

### 铁律 17：全量完整输出，不交增量补丁

交付时一次性给出完整章节/全文，不"先给一部分，其余后续补"。修订版必须包含全文或明确标注"仅修订 XX 节"。审计输出完整清单（所有节，不只问题节）。

### 铁律 18：绝不硬编码编号

翻译稿中所有"见 Theorem X.Y"的引用必须**回原文核对编号后再写**，不允许凭记忆写编号。

### 铁律 19：每一步都必须不断备份

### 铁律 22：dsh 用量纪律——全任务一档模型（v4.1 flash），难任务靠资料/prompt/多轮（2026-09-10 用户拍板）

> 🚨 **用户原话（2026-09-10）："v4.1 flash 全面超越 pro，以后就都用 v4.1 flash，需要 pro 的地方也换成 flash，不管什么任务都暂时用 flash，只不过难任务需要多查资料多给提示词多优化几轮。"** 全流程只有一档模型 `deepseek-v4.1-flash`；**pro 弃用**；难任务不做模型升级，而是**补充资料 + 加厚 prompt + 多跑几轮迭代**（`-e max` + 局部重跑）。
>
> **怎么应用**：
> 1. **一档模型制**：全流程统一 `dsh-remote -m deepseek-v4.1-flash`；`-e` 按难度选 off/low/high/max，没有 pro 档。

### 铁律 24：扫描版（无文字层）源文件必须做视觉核对（2026-09-23 用户拍板「以后可以多侧重视觉」）

> 🚨 凡源文件是**扫描版**（`pdftotext` 提取为空、只能靠 OCR）的翻译任务，**交付前必须过references/vision-check.md的视觉核对流水线**：用 `deepseek/deepseek-v4.1-flash` 的**图像输入**逐页转写原书作为**权威原文** → 与译文比对 → 派终校任务以权威原文为准订正。
>
> **为什么必须**：Windows OCR 会**整段丢公式**。part004 实测三例——公式 (4) 在 OCR 里只剩一个 `and`（两式全丢）；$\delta<\sqrt{2}-1$ 被读成 `軛 一 1`，译者据上下文误还原为 `0.1`，还在注里围绕错误常数写了一整段；示例矩阵 $A_0,B_0,C_0$ 被写成 $A_{11},A_{12},A_{13}$。**这类错误任何基于 OCR 文本的审计都查不出来**，只有看原页才能发现。
>
> **配套必查**（详见 references/vision-check.md §9.4）：订正会**删注**（订正前后统计译者注条数，丢失的从备份回插）、```math 围栏失衡、任务超 **32767 字符**静默失败（rc=0 零输出）。
>
> **人机分工**：机器负责"看得全"（逐页转写 + 编号比对），人负责"看得懂"（相似度低的地方要人判断是不是等价改写）。

### 铁律 25：替换式改稿必须覆盖到公式边界 + 交付前必跑「公式体检」（2026-09-23 part005 实战）

**踩坑事实**：part005 视觉终校用「old 串只匹配到公式中途、new 串以 `（续）` 结尾」的补丁批量改 50 页，`$` 看似正常，但**7 处公式被撕成两半**：

- 3 处在正文行内 → 例：`从最后一个方程 $x_1 = \lambda x_4$ 出发…于是得到 $\lambda^4 = 1$。**mbda^4 q_1$**，于是…` → `$` 计数变奇数，可被捕获；
- 4 处在 ```math 围栏内 → 例：`... = \lambda_j u_j . \tag{3} **\text{ 1}}{h^2}** = \lambda_j(...)`、`\tag{4} **\text{ 2 \end{bmatrix} \tag{4}**`、`\tag{9}**tag{9}**`、`A for low frequencies, } D for high frequencies}` → **`$` 配对检查完全查不出来**；KaTeX 报错后 `throwOnError:false` 让公式以**裸 LaTeX 文本**出现在成品 PDF 里（`\frac`、`\begin{bmatrix}` 直接印在纸上），直到渲染完逐页看才发现 —— 白跑两轮渲染。

**三条纪律**：

1. **补丁的 old 串必须覆盖到公式/围栏的自然边界**（整行、整个 ```math 块，或至少到 `\tag{N}` / `\end{...}`）。宁可用更长、更唯一的 old 串，也不要「前半段匹配 + 后半段自动保留」。**严禁**在 new 串末尾留 `（续）`、`\text{`、`\tag{pre}` 这类「占位式接续」标记——它们就是撕裂源。
2. **交付前必跑公式体检**（主代理直跑，秒级；已并入 `check_mechanical_p005.py`）：
   - 围栏外逐行 `$` 计数必须为**偶**（忽略 `\$`）；
   - 围栏内逐行花括号 `{` / `}` 必须**相等**；
   - 围栏内不得出现 `\tag{X} \text{`、`\tag{X}tag`、同行两个 `\tag{`。
3. **改完合并稿必须同步改 `pages/` 源页**，否则下一次 `assemble` 会把回退带回来（part005 出现过这个次序陷阱：先改合并稿、忘了源页，第二次合并又裂开）。

### 铁律 26：原书插图是内容，不得静默丢弃（2026-09-23 用户拍板）

> 🚨 **凡原书有 Figure（插图 / 曲线图 / 示意图 / 谱图 / 流程框图 / 矩阵结构图），交付稿里必须留下这张图本身**——用 `assets/` 存图 + Markdown 引用；**只翻译图注文字 = 违规**。图注照双语铁律翻译；图内印字按 references/image-pipeline.md §10.2.5 决策树处理；难概念还**鼓励自行绘图**（references/image-pipeline.md §10.3），自绘图必须注明"译者绘制"。
>
> **暴露事实**：part005（Strang LaLFD 书页 198–248）交付稿里，**图 IV.1 只剩一行图注文字**（"$w$ 的各次幂也就是 $\omega$ 的各次幂……"），图本身（两个单位圆 + $N=8$ 标注 + $w=e^{2\pi i/8}$ 对照）从未进入交付物——读者拿不到原书里最直观的那张图。这类"丢图"在任何文本层审计里都不可见（没有文本可查），只有对着原页看才发现。
>
> **为什么**：图是构建主义读者理解空间/结构概念的第一通道；扫描版教材尤其危险——OCR 只吐文字，图在流水线里默认消失。
>
> **怎么做（三步，详见references/image-pipeline.md）**：① 视觉模型逐页定位插图并给**百分比 bbox**（§10.2.2，实测可用）；② PyMuPDF 高 dpi `clip` **重新渲染裁切**（references/image-pipeline.md §10.2.3，不要用屏幕截图、不要用 `pdfimages`——扫描版只会吐出整页 JPEG）；③ 存 `assets/` + 图注双语 + 交付前做"图数比对"（references/image-pipeline.md §10.5）。

> 💡 **根因**：这类撕裂源于「用替换串模拟续写」。真正安全的做法是**整块替换**（把要改的公式整段写进 old，整段写进 new），或**直接重写该行/该块**。

## 2.6 翻译主体（小规模：主代理直译；大规模：25×2 dsh 任务）

### 2.6.1 翻译通用规范（🚨 铁律 1-9 全程生效）

- 中文主体、无英文开句、术语 `English（中文）` 仅首次加括号、逐句不合并、LaTeX 环境不翻译、行内 `$...$` 与块级 fenced math block（无 `$$`）、标题标记行首、无 `<div>`、习题保留英文
- 逐段阅读原文后**直接用中文写作**，英文术语作为行内元素嵌入
- 每个功能模块前加蓝色标签（`<span style="color:#2471a3;">**[tag]**</span>`）
- 用 `---` 分割线分隔大段落
- 颜色匹配原文或按references/format.md配色方案处理
- **翻译节奏自检**：每输出约 200 行执行一次「英中对照自检」；交付前 `grep -nE '^[A-Z][a-z]+ [a-z]+' 输出.md` 扫英文行首（铁律 16）
- 逐句翻译密度标准：每页 30-40 行译文、平均每行 6-7 个中文字（铁律 4）

### 2.6.2 小规模路径（≤50 页或 ≤500 行英文）

- 主代理直接逐句翻译 + 排版输出
- **层次加工**：题目（原文）与答案（解答）均保持**完整行内双语翻译**；答案用 `>` blockquote 包裹实现虚化（MarkText 自动虚化），内容不缩减
- 代码块不受字体缩放影响，保持 1em
- 检查整体视觉层次：标题 → 题目原文 → 答案是否一眼可区分，原文是否被不当压缩
- **译者补充与替代解法（可选）**：若对题目或答案有更好的想法，或知道工业界/学术界更优解法，用专门标签标注后附加在原文之后（🚨 铁律 14：必须有真实来源）：
  - **`[note]`** — 背景知识补充、术语解释、上下文关联、历史沿革。深绿色（见 4.1 配色表）
    ```
    > <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 此算法在现代工业界已由 XX 替代。
    ```
  - **`[alternative]`** — 优于原文的解法、现代替代方案、工业界实践。深紫色（见 4.1 配色表）
    ```
    > <span style="color:#7d3c98;">**[alternative] Alternative（替代解法）:**</span> 实际工程中多用 YY 算法，时间复杂度更低。
    ```
  - 补充内容用 `>` blockquote 包裹，放在原文答案之后，与原文清晰区分。写完后二次审查（见铁律 14）
- 大规模路径见下节 2.7

### 2.7.7 对比原文审计（主代理执行）

大规模翻译完成后，主代理必须执行以下系统性审计，按顺序操作：

**① 提取 PDF 原文文本**
```bash
pdftotext -f <起始页> -l <结束页> /path/to/original.pdf /tmp/original.txt
```
若发现内容明显缺失（定理陈述不完整、节标题后直接跳内容），尝试 `-layout` 或 `-raw` 模式重新提取并对比合并。

**② 定位章节边界**
```bash
grep -n "Section\|Theorem\|Definition\|Example\|Exercise\|Monotone\|Cauchy" /tmp/original.txt
```
建立"原文章节行号对照表"。

**③ 逐节对比审计清单**

| # | 检查项 | 检查方法 |
|---|--------|----------|
| 1 | **开篇段是否完整** | 节标题后原文是否有介绍段→翻译是否包含 |
| 2 | **所有定理/定义编号是否对应** | 原文 Theorem N → 翻译 Theorem N，无跳号/重号 |
| 3 | **证明是否完整** | 原文证明长度 → 翻译证明长度，无明显压缩 |
| 4 | **例子是否全部覆盖** | 原文 Example N → 翻译 Example N，无跳过 |
| 5 | **例子顺序是否正确** | 原文顺序 A→B→C，翻译不能变成 A→C→B |
| 6 | **习题边界检查** | 翻译文件习题编号从 N 开始，检查 N-1 之前的习题是否被跳过 |
| 7 | **过渡段是否遗漏** | 原文在两个定理/例子之间的过渡性段落是否被省略 |
| 8 | **人物/历史介绍是否遗漏** | 原文出现的数学家姓名、年代、背景介绍是否保留 |
| 9 | **内容是否被错误替换** | 原文定理 A 的内容不能出现在翻译的定理 B 中 |
| 10 | **严重翻译错误** | 检查已知易错点：例 2.29 的"还需更多工作"不要译成"极限为0" |

**④ 自动化验证（可选）**：对关键指标编写简单验证脚本，例如 Python 检查所有预期段落是否存在：
```python
checks = {
    "Example 2.32 present": "Example 2.32" in content,
    "Theorem 2.28 proof present": "sup" in content and "lim" in content,
    "Exercises 2.11.1-2.11.6 present": "2.11.1" in content and "2.11.6" in content,
}
```

**⑤ 问题分级与修复策略**（主代理发现即当场修复，🔴 必须补全 → 🟡 建议补全 → 🟢 有时间再修）：
| 严重程度 | 定义 |
|---------|------|
| 🔴 严重 | 整节/整个定理/整个例子缺失；结构重构；顺序混乱 |
| 🟡 中等 | 段落缺失；证明被大幅压缩；编号/顺序错误 |
| 🟢 轻微 | 术语翻译不一致；标点格式问题 |

**⑥ 输出审计报告**（主代理记录，供交付说明用）：
```

| 节 | 严重程度 | 核心问题 |
|----|---------|---------|
```

### 2.8.3 Reader Testing（无上下文盲检）

抽 3 页（开头 1 页 + 中间 1 页 + 结尾 1 页），启动**只读 subagent**（不给原文、不给任何上下文），只输入译文，要求它：
1. 复述这页讲了什么（检验可读性）
2. 指出读不懂的地方（检验盲点：术语没首次翻译、指代断裂、编号悬空）
3. 判断这页是否是"翻译腔"（自然度盲检）

若暴露问题，按严重程度分级修复。此测试查"读得懂不懂"，对比原文审计查"译得对不对"，互补。

### 2.8.4 审稿人视角复查

假装自己是收到这份翻译稿的审稿人，逐条回答：
- 每个定理/定义/例子编号能否在原文中定位？
- 术语表是否一致？同一概念是否出现多个译法？
- 注的内容是否有真实来源支撑？无来源的注是否已删除？
- 是否有"凑数"段落（信息密度不足）？

### 2.8.5 错误记忆

完成翻译后，把犯过的错误记入 `.reasonix/attachments/translation_error_memory.md`（格式见 HISTORY.md 8.1），下次翻译前先读该文件避免重犯历史错误（如 PS01 甩名词教训、prob7sol 英中对照教训）。

## A1. 沙箱与文件操作（重要）

由于 Reasonix 工作区沙箱限制，直接操作桌面目录文件时需注意：

1. **`edit_file` / `delete_range` 等工具**只能操作工作区内的文件（`~/.reasonix/global-workspace/` 及子目录）
2. **目标输出目录**（如 `/home/tianque/桌面/`）不是工作区，不能直接用编辑工具
3. **解决方案**：
   - 先将文件从桌面目录复制到工作区：`cp /桌面/路径/文件 .reasonix/attachments/文件`
   - 在工作区内用 `edit_file` / `delete_range` / `multi_edit` 修改
   - 修改后用 `cp` 命令（bash）复制回桌面目录
4. **`cp` 命令可以成功写入桌面目录**（bash 不受沙箱限制），所以文件传输可行
