## 8.3 错误处理闭环（D4c，对齐用户调试思维）

翻译错误处理对齐用户的「复现→定位→理解→修复→验证」闭环：

```
复现：回到原文，找到误译对应的原句
定位：判断错误类型（术语/编号/遗漏/翻译腔）
理解：为什么译错了（直译陷阱/上下文缺失/知识盲区）
修复：最小改动修正（手术式编辑，只动有问题的最小片段）
验证：对照原文重读该节 + Reader Testing 抽查
```

## 8.3a 审计执行规范（2026-09-03 lec18 实战新增：用户拍板）

> ⚠️ 状态标注（2026-09-05）：本节为 2026-08-16 本机 dsh 时代规范。**本机已不跑 dsh**（2026-09-04 拍板），现行：审计一律 `dsh-remote -m deepseek-v4.1-flash -e max` 转发主力机；主力机 conc 版**无同机锁可并发**（下述「dsh-gate 同机不可并发」仅指旧版）。主规范见技能 `dsh-gate` v2.0 与记忆 `工具-dsh并发调度与命令铁律-20260904.md`。

> 来源：lec18（8 页讲义）双审计实战。用户三条明确要求 + 两次超时教训。

### 8.3a.1 用户要求（拍板，必须遵守）

1. **大任务先开双机 web 界面再跑**——不用 headless 静默跑长任务。`dsh web`（浏览器 UI，http://127.0.0.1:3080）两台机各开一个，用户能看到任务执行。
2. **多块审计并行**——拆成多块后**双机各跑一块**（本机 Linux + 主力机 Windows 并行；dsh-gate 同机不可并发，两机之间可并行）。
3. **不要中途停止正在跑的 dsh 任务**——让它自然完成；headless 只是快任务通道，长任务一律 web/并行。
4. **查知识不是查历史**——译者注的拓展用离线维基查**概念机制**（定义/关系/原理），不要堆论文年表、历史人物（Cook 1971/Karp 1972 这类删掉）。
5. **可以自己生成图片或找图片辅助理解**——空间/结构/流程类概念（子问题 DAG、状态转移表、递推树、谱系嵌套图等）配示意图：自己画（matplotlib/graphviz/Mermaid/ASCII）或找现成图（离线维基/OCW 原图/教材插图，标来源），存 `assets/` 引用；图聚焦单一概念、配图注，不做装饰。详见 4.1 第 6 种 / 4.2 配图条目。

### 8.3a.2 长文 pro 审计的拆块法（headless 超时教训）

- **症状**：30KB 全稿喂 pro+max headless，10 分钟跑不完被杀（rc=143）；本机 commandcode 通道对大任务反复超时。
- **拆块**：按维度拆 3 块——① 注质量（只喂 6 条注 + 读者画像，13KB）② 正文结构+翻译（原文摘要对照 + 去注正文，18KB）③ 事实核对（纯断言清单，2.4KB）。**单块 ≤ 18KB**，双机并行跑。
- 主力机 dsh-gate.ps1 比本机稳（pro 大任务能完成，如块 1/块 2 均 9794B/完整报告）；本机 dsh-gate 大任务多次 rc=143 超时。**大审计块优先派主力机**。
- 结果落盘：主力机 `%TEMP%\dsh-gate\*.txt`（scp 取回）、本机 `/tmp/dsh-gate/*.txt`。

### 8.3a.3 审计修复必须"先核实再改"

审计意见分两类：**真错误**（错字、机制错误、编造引文——直接修）与**误判**（审计方没看到原文就质疑——对照 PDF 原文核实后不改）。lec18 实战核实结果：
- 审计说 "TRUE/FALSE 句原文没有" → 原文 p.4 确有，**不改**
- 审计说 "2× expansion 是 2 种扩展非 2 倍" → 原文就写 "2× expansion"，**不改**
- 审计说 "Nonexpansive 括号改变方向" → 原文就是 "(include first item)"，**不改**
- 审计说 "Rod Cutting work O(1)" → 原文是 "O(ℓ)=O(L)"，**不改**
- 真错误：注 5 错字"它的是实例"、二分搜索优化版（无单调性，改 self-reducibility）、注 2 可达计数口径（自己枚举 15 含 1 基态扣后 14）、注 3 重复引文删除、注 4 谱系 ⊂ 表述、Fibonacci 归类澄清——**都改了**

### 8.3a.4 交付前双备份 + 终检

- 备份点：审计修复前、最终交付前各一次（`backup/<时间戳>-lec18-*.tar.gz`）
- 终检命令：`grep -cE '^[A-Z][a-z]+ [a-z]+ [a-z]+ [a-z]+ [a-z]+'`（英文段=0）、`grep -c '\$\$'`（=0）、Unicode 上下标（=0）、🎥 数、note 数、行数

### 8.3a.5 报告落盘铁律 + 状态判定防误杀（2026-09-05 lec19 实战新增：用户拍板）

> **背景**：lec19 审计时，pro+max 报告实际已完整产出（38+50 条意见），但主代理因**只盯 status 文件（phase 滞后显示 running）**、未见产物就误判"卡死"并 kill 任务——用户被迫自己救回，痛批"浪费钱、浪费 token"。用户拍板两条铁律。

**① 派发 dsh 审计/写注任务时，prompt 必须要求"报告写盘"**：
- 任务描述末尾显式加：**「把完整报告写入文件 <绝对路径>（UTF-8），并在末尾输出该文件路径与大小」**——如 `C:\Users\27063\AppData\Local\Temp\dsh-gate\lec19-<任务名>-report.txt`（dsh-gate-conc 有 tools 能力可写盘）
- 或利用 dsh-gate-conc 自带的产物落盘：**结果自动存 `%TEMP%\dsh-gate\<时间戳>-<模型>.txt`**——派发后直接**轮询该目录**，不要只盯 `~\.dsh\gate\status\<id>.json`（status 的 phase 滞后，任务已完成仍显示 running 是常态）
- 报告取回用 `ssh tqjq "powershell Get-Content %TEMP%\dsh-gate\<stamp>-<model>.txt"` 重定向到本机文件（scp 中文路径转义有坑）

**② 状态判定防误杀（禁止凭单一信号 kill 任务）**：
- `status` 文件 phase 滞后 ≠ 任务没完成；**产物文件出现 = 完成**（dsh-gate-conc 完成时必写 `<时间戳>-<模型>.txt`）
- 判定"卡死"需同时满足：**产物目录无新文件 + node 进程 CPU 长时间（>5min）不增长 + 超过该类任务经验时长**
- 🚨 8.3a.1 铁律重申：**不中断正在跑的 dsh 任务**——宁可多等，不可误杀。误杀一次 = 整块重跑 + 用户信任损失
- 本机 `dsh-remote` 同步调用的 stdout 会被 `tail -n` 截断，**完整报告永远以主力机产物文件为准**，别从截断的 stdout 判断产出质量

**③ 长任务文本传参限制**：
- `dsh-remote "任务"` 的任务文本经 base64 包装传参，**>32KB 会超 Windows 命令行限制而静默失败**（lec19 格式审计 48KB 全文内联即此坑）——超长任务拆块 ≤18KB，或要求 dsh 从文件读（若 dsh 有读文件工具）

**来源**：lec19 实战（2026-09-05，用户明确要求"记住了就直接总结加入技能"）。

## DSH 钩子（DeepSeek Harness 集成）

本技能处理长文档/教材翻译（≥50 页或需逐句精译）时，**难翻译任务优先调用 dsh 走主力机 headless**（pro+max），Reasonix 只整合结果不重复翻译：

### 调用方式（2026-09-04 起：本机不再直接跑 dsh）

**本机不跑 dsh**（性能不够实测超时/崩溃，用户拍板）——统一走 `dsh-remote` 派发到主力机：

- 简单任务：`dsh-remote "任务"`（自动判定难易，难→pro+max，易→flash）
- 强制 pro：`dsh-remote -pro "任务"`
- **自由指定模型**（67 个已登记 commandcode-goat，含 deepseek 系/Kimi/GLM/Gemini）：`dsh-remote -m google/gemini-3.8-flash "任务"`
- **长任务后台化（推荐）**：`dsh-remote --async "任务"` —— schtasks 脱离 SSH 会话，立即返回，完成自动弹本机横幅
- 查进度（只读，不干扰运行）：`dsh-remote --status`
- 主力机并发版脚本：`C:\Users\27063\.local\bin\dsh-gate-conc.ps1`（同机多任务并发 = 每任务独立 settings 副本，互不互踩）

### 学术任务铁律（2026-09-04 用户拍板）

**学术相关、调 dsh 的任务一律走主力机并强调发挥最高能力**：
- 翻译/审计/证明/数学/写注等 → `dsh-remote -pro "任务"`（pro + reasoningEffort=max），任务里写「发挥你最高能力 / max thinking / 详尽输出」
- 自定义模型也要带 `-e max`：`dsh-remote -m <model> -e max "任务"`
- 绝不用本机 dsh、绝不用低 effort 跑学术任务

### 四 agent 完成 → 本机横幅（2026-09-04 实证）

- 主力机 dsh-gate-conc 完成任务 → 自动反向 SSH `notify-send` 弹本机横幅（dbus 实证通过）
- 主力机 Reasonix agent → 同法反向 SSH notify-send
- 本机 Reasonix agent → 直接 `notify-send`（DISPLAY=:0 + DBUS_SESSION_BUS_ADDRESS=/run/user/1000/bus）

### 命令写法铁律（2026-09-04 双写：技能 + 全局记忆）

**禁止 `cmd | python3 -c "..."` 管道形态**——host 会 block（内联解释器后跟可能隐藏失败的段），一次拦截 = 一整轮往返浪费：
- ✅ 正确：`python3 - <<'EOF' ... EOF`（heredoc）
- ✅ 正确：解释器命令放整条命令最后一段（`curl ... -o f && python3 f.py`）
- ✅ 正确：先落盘文件再解析
- ❌ 错误：`curl ... | python3 -c "import json..."`、`gh_search() { ... | python3 -c ...; }`

- DSH 会话自动注入用户记忆/技能/画像上下文（含双语 5 铁律、禁英中分段对照等规范）
