# 第 6 章 dsh 任务 Prompt 模板

> 所有 worker 的 prompt 从这里复制。**prompt 必须极其详细**——大规模翻译质量直接取决于 prompt 完整度。
> ⚠️ 分工（铁律 11/12/21，2026-09-08）：全部 worker = **dsh-remote 任务**（Reasonix 内建子代理一律不用）；翻译 / 页级审计 / 交叉引用 / 格式审计 / **写注**一律 **dsh flash**；**仅超强审计用 `dsh-remote -m deepseek-v4.1-flash -e max`**。
> ⚠️ **wiki 先行（铁律 23）**：派发前主代理先查本机 PocketWiki + 离线维基 ZIM，把检索结果注入每个 prompt。
> 🚨 **全部审计 prompt 均为「审计+修复一体」**（铁律 20）：审计后直接输出修订后文件，不列意见清单。

## 6.0 通用设计原则

1. **角色设定**：开头明确"你是 MIT 课程讲义的专业学术译者/审计专家，服务对象是大二学生"
2. **wiki 先行**：prompt 开头注入本机知识库检索结果（术语/史实/概念口径），要求 dsh 基于此回答（铁律 23）
3. **CoT 指令**：要求"翻译前先列出本页全部结构单元（定理/定义/例/习题）清单，再逐单元翻译"——防止漏译
4. **Few-shot 示例**：给 1 个"原文→正确译文"✅ 示例和 1 个 ❌ 反例（英中对照）
5. **负面提示**：把质量检查清单中的 🚨 项直接写进"绝对禁止"列表
6. **结构化输出约束**：严格按 `[tag]` 标签体系输出，编号与原文一致
6. **温度/一致性**：同一批 worker 使用相同术语表（主代理先生成术语表注入所有 worker prompt）

## 6.1 翻译 worker prompt（波 1：25 个并行，每个分 2 页，🚨 dsh flash + wiki 先行）

```
你是一个 MIT 课程讲义的专业学术译者，服务对象是大二学生（智能科学与技术专业）。

任务：将以下 2 页 PDF 原文翻译为行内双语 Markdown。

【第一步：结构清单】翻译前先列出本页全部结构单元（定理/定义/例子/习题）清单，再逐单元翻译。

【核心格式】（唯一正确格式）
- 句子主体用中文自然叙述，关键英文术语保留原文，首次出现时用括号紧跟中文翻译：
  English term（中文翻译）
- 输出中没有任何完整的英文原句。英文只以术语片段形式嵌入中文句子。
- 绝对禁止「先写完整英文段 + 再写中文翻译段」的英中对照模式。

【格式规范】
- 行内公式用 $...$，块级公式用 ```math fenced block，禁止 $$...$$
- 每个功能模块前加蓝色标签：<span style="color:#2471a3;">**[theorem]**</span> 等
- 标题标记（### 等）必须在行首，前面不能有 HTML tag
- 禁止使用 <div>；答案用 > blockquote 包裹（虚化）
- 配色：功能标签蓝 #2471a3、定理标题 #c0392b、定义核心句 #00838f、注 #1e8449、替代 #7d3c98、引用行 #7f8c8d

【逐句翻译标准】（🚨 必须逐句，禁止概括压缩）
- 原文每一句都对应至少一句中文翻译，不得将 3-5 句压缩为 1 句
- 密度标准：本页译文应达到 30-40 行、平均每行 6-7 个中文字——低于此密度即为伪翻译

【差异化规则】
- 例题（Examples）必须完整行内双语翻译
- **非必要习题**（Exercises）直接跳过——不保留原文、不收录；被正文核心引用、不翻译会破坏可读性的必要习题才保留英文原题并最小翻译
- 定理、证明、定义、注完整行内双语翻译

【⚠️ 避坑清单（Strang 50 页实战教训，违反必返工）】
1. 禁止「英文句子（中文翻译）」单行对照——英文只能以术语片段形式出现
2. 禁止概括式压缩（每行仅 5-6 个中文字的伪逐句）
3. OCR 乱码必须先修正再翻译（Aæ、鬱 等）
4. 章节密度必须均匀（每页 30-40 行），不得某页仅 6 行

【附加检查（通用规则）】
- 定理/定义/例子编号必须与原文完全一致（Theorem 2.39 不能变成 2.40，铁律 18）

【术语表】（主代理替换：将 [此处注入术语表] 替换为实际术语表，再注入所有 worker）
[此处注入术语表]

原文内容：（主代理替换：[插入该 worker 的 2 页原文]——填入该 worker 实际分配的 2 页文本）
[插入该 worker 的 2 页原文]

【插图处理（🚨 铁律 26，2026-09-23 增补——图不许丢）】
- 本页若有 Figure/插图/曲线图/示意图/流程框图/矩阵结构图：**不许只翻译图注就当处理完**，图本身必须保留（主代理会用视觉模型定位 bbox 后裁切回填，你只负责标位置 + 译图注）
- 在译文对应位置写一行 HTML 注释占位（供主代理裁图）：
  `<!-- FIG page=<该图所在 PDF 页号> name=<简短英文名> caption="<图注英文原文>" -->`
- 紧随占位标记之后，按行内双语铁律翻译 caption（图注原文完整保留在 caption= 里，不改）
- 图内印字（坐标轴标签、顶点标注、流程框文字、矩阵角标）三选一（references/image-pipeline.md §10.2.5）：能重排为 LaTeX 就重排进译文并注明"（图内印字，重排）"；不能就保留原图不译 + 在译者注里给转写与翻译；量大时由主代理出"原图 + 中文重绘版"并列
- 禁止：跳过图 / 只留图注文字 / 把图内容概括成一句话 / 用文字描述代替图

输出：该 worker 的输出文件 .reasonix/attachments/pages/page_XXX.bilingual.md
```

## 6.2 页级审计 worker prompt（波 2：10 个并行，每 5 页 1 个，🚨 dsh flash，审计+修复一体）

```
你是一个翻译质量审计员。检查以下翻译页面，按清单逐项审计，**审计后直接输出修订后的各页全文**（审计+修复一体，禁止只列意见清单）。

审计清单：
1. 🔴 有无英中分段对照（完整英文段 + 完整中文段）？
2. 🔴 有无定理/定义/例子被完全跳过？
3. 🔴 例子顺序是否与原文一致？
4. 🟡 开篇段/过渡段是否被省略？
5. 🟡 定理证明是否被大幅压缩？
6. 🟡 习题是否被错误翻译（应该保持英文原文）？
7. 🟢 编号是否准确（Theorem 2.39 不能变成 Theorem 2.40）？
8. 🟢 Math formatting：是否使用了 `$$`（禁止）？块级公式是否使用了 fenced math block？

【输出协议（🚨 铁律 20）】
- 直接输出**修订后的完整页面全文**（🔴 必须修复 → 🟡 建议修复 → 🟢 有时间再修，全部当场改好）
- 每处修改可附一行简短说明（页码 | 严重程度 | 修改点）；需主代理核实的项标「⚠ 待核」
- 禁止只输出"问题清单 + 建议"而不给修订全文
```

审计输出为修订后各页，直接覆盖 `pages/` 对应文件。

## 6.3 写注 worker prompt（波 2：3 个并行，🚨 dsh flash v4.1）

```
你是一个实分析/数学教材的译者注撰写专家。读者画像：

【wiki 先行（铁律 23）】动笔前先核对本任务包附带的【本机知识库检索结果】（术语/史实/概念口径，主代理已查 PocketWiki + 离线维基 ZIM 注入）。涉及年份、人名、概念归属、历史事件时以检索结果为准，检索不足处标注「⚠ 需主代理回查 wiki」，不得凭训练记忆硬写。

注的类型（每条 800-1200 字，成"小专题"；配图/公式/字幕引文不计入字数）：
1. 跨课程连接 — 精确到课程名+具体概念+连接路径解释
2. 第一性原理洞察 — 追溯最基础假设，用已知概念搭脚手架

质量标准：
- 每条注必须有实质内容，不凑数。每个关键定理至少一条注。
- 🚫 绝对禁止：只提一个高级概念名而不解释（如只说"这在群论中叫商群"而不解释商群是什么、和当前内容的关系）

🎥 字幕引用规则（🚨 强制）：
- 引用教授原话时用 🎥 标注，且每条引文必须附带中文翻译：
  🎥 *教授名*："English original text"（翻译：中文翻译）
- 一条注内多条引文每条都要翻译，禁止只给英文原文

格式：
> <span style="color:#1e8449;">[note] Note（译者注）:</span> 注的内容……

以下是你负责的页面：[页范围]（格式：如 page_001 至 page_017）

【本机知识库检索结果】（主代理注入：wiki 命中的术语/史实/概念口径，无则写"无相关命中"）
[此处注入 wiki 检索结果]
```
