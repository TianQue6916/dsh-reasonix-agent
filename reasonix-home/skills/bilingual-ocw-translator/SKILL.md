## 🎯 核心契约（每次开工先读这一段）

**模型**：全流程只有一个模型 **v4.1 flash** = `deepseek-v4.1-flash`；正文引「v4.1 flash」，`dsh-remote` 命令行写完整 id。pro 已弃用。

| # | 契约 | 一句话执行 |
|---|------|-----------|
| 1 | **通道** | 一切「另派代理」的活（翻译 / 写注 / 审计 / 交叉引用 / 终校）走主力机 `dsh-remote -m deepseek-v4.1-flash -e <off/low/high/max>`；**Reasonix 内建子代理一律不用**（铁律 21）。难任务不换模型——只调 `-e`、补资料、加厚 prompt、多跑一轮（铁律 22） |
| 2 | **双语格式** | 中文主体 + 英文术语行内嵌入；**禁止英中分段对照**（成品里没有完整英文原句）；每句以中文开句；术语首次 `English（中文）`、后文省略括号；逐句翻译不合并（铁律 1-4） |
| 3 | **密度** | 每页 30-40 行译文、平均每行 6-7 个中文字——低于此密度即概括式伪翻译（铁律 4） |
| 4 | **数学格式** | 行内 `$...$`；块级 fenced math block；**禁止 `$$`**；禁止 Unicode 上下标字符（铁律 6） |
| 5 | **审计即修复** | 页级 / 超强 / 格式审计一律「审计+修复一体」：直接输出修订后全文，**禁止只列意见清单**（铁律 20） |
| 6 | **wiki 先行** | 派发任何 dsh 任务之前，主代理先查本机 PocketWiki + 离线 ZIM，把命中结果注入 prompt（铁律 23） |
| 7 | **全资源搜索** | 开工前搜双盘区 + 主力机 + 网络 + 本机 ZIM（铁律 13） |
| 8 | **写注** | 每条 800-1200 字；跨课程连接精确到「课程名 + 具体概念 + 连接路径」；**禁止裸甩名词**、禁止空洞赞美（铁律 15） |
| 9 | **扫描版必做视觉核对** | 无文字层的教材，必须用 v4.1 flash 的**图像输入**逐页转写原书作权威原文再比对；两个坑（浏览器 UA、`vision-exp` 不被支持）与副作用清单见 `references/vision-check.md` |
| 10 | **插图是内容** | **原书插图一律不丢**（铁律 26）——图注翻译不能替代图本身；保留原图走「vision 给 bbox → PyMuPDF `clip` 裁切 → `assets/`」，难概念自创图见 `references/image-pipeline.md` |
| 11 | **替换式改稿** | 补丁串必须覆盖到**公式边界**，交付前必跑「公式体检」（铁律 25）——半截替换会把公式撕成两半且 `$` 配对检查查不出来 |
| 12 | **交付自检** | `grep -nE '^[A-Z][a-z]+ [a-z]+' 输出.md` 扫英文行首 + 密度抽查 + 编号回原文核对 + 渲染后泄漏扫描 |

## 核心流程（一条流程，两档参数）

一条流程两档参数：小规模（≤50 页或 ≤500 行英文）主代理直接翻译；大规模（>50 页）25×2 dsh 任务分工。**流程末尾的 2.8 双审计是交付前必经环节（所有规模）。**

1. **2.1 任务上下文确认**——开工前先答 5 个元问题（文档类型 / 主要受众 / 期望效果 / 格式约束 / 其他约束）
2. **2.2 全资源搜索**（🚨 铁律 13，必做）——本机 PocketWiki + 离线 ZIM 优先，再查双盘区 + 主力机 + 网络
3. **2.3 读取源文件**（PDF 多模式提取）——`pdftotext` 默认 → `-layout`/`-raw` → `pdfplumber` → TextIn 兜底
4. **2.4 搜索课程视频字幕**（MIT OCW / OCW 类课程专用）——**先读取目录结构，不要只做关键词匹配搜索**
5. **2.5 分析与排版规划**——识别文档结构 / 功能模块 / 关键术语 / 标题层级，分配标签与配色
6. **2.6 翻译主体**——小规模（≤50 页或 ≤500 行英文）主代理直接逐句翻译；大规模走 2.7
7. **2.7 大规模路径**（>50 页或 >500 行英文，25×2 波次）——波 1 翻译 worker 25 个 / 波 2 页级审计 10 + 写注 3 + 交叉引用 2 / 波 3 超强审计 / 波 4 格式审计；全部 `dsh flash`，主代理只切分·组装·派发·合并·回填
8. **2.8 最终审查**（所有规模必做）——超强审计 + 格式审计（均审计+修复一体）→ 人工审查要点 → Reader Testing 盲检 → 审稿人视角复查 → 错误记忆落盘

每一步的完整参数、审计清单、报告模板与判级标准 → **`references/workflow-core.md` + `references/workflow-large-scale.md`**（第 2 章全文，逐字）。

## 🚨 铁律速记（26 条条目名）

> 所有 🚨 规则集中于此。**每次开工前默念一遍。** 铁律分四类：**格式类（1-10）**、**分工类（11-13）**、**来源类（14-18）**、**流程类（19-26）**。

- **格式类（1-10）**：1 禁止英中分段对照（最高铁律）/ 2 英文句子开头禁止 / 3 术语格式 `English（中文）`，仅首次加括号 / 4 不合并句子（逐句翻译）/ 5 LaTeX 环境内不翻译 / 6 行内 `$...$`，块级 ` ```math `，禁止 `$$` / 7 标题标记在行首 / 8 禁止 `<div>` / 9 教材的非必要习题直接跳过，例题必须翻译 / 10 字幕引文必须附带中文翻译
- **分工类（11-13）**：11 核心翻译——小规模主代理直译，大规模 25×2 dsh 任务分工 / 12 模型分配总纲——全任务统一 v4.1 flash，pro 弃用 / 13 全资源搜索必做
- **来源类（14-18）**：14 补充内容必须有真实来源 / 15 译者注禁止甩名词 / 16 每 200 行自检 + 交付前 grep 扫英文行首 / 17 全量完整输出，不交增量补丁 / 18 绝不硬编码编号
- **流程类（19-26）**：19 每一步都必须不断备份 / 20 一切审计 = 审计 + 修复一体 / 21 Reasonix 不派任何子代理——一切子代理活全部转主力机 dsh / 22 dsh 用量纪律——全任务一档模型（v4.1 flash），难任务靠资料/prompt/多轮 / 23 任何 dsh 任务必须先查小电脑 wiki 再回答/继续 / 24 扫描版（无文字层）源文件必须做视觉核对 / 25 替换式改稿必须覆盖到公式边界 + 交付前必跑「公式体检」/ 26 原书插图是内容，不得静默丢弃

要写 patch、动插图、跑审计、派 dsh 之前，先按下方「按需读取」表读对应铁律原文（逐字全文，本页只留条目名）。
