# 第 3 章 译者注指南（[note] 写法）

> 🚨 **写注用 dsh flash v4.1（铁律 12，2026-09-10：v4.1 flash 全面超越 pro，全任务统一）**

## 3.1 注的类型（6 种）

1. **跨课程连接**：将当前内容与用户知识体系中的其他课程连接。**可用的连接锚点**：离散数学 6.042J（等价关系、偏序集、数论）、CSAPP（浮点表示、机器级编程、内存层次）、CLRS 算法导论（二分搜索、分治、复杂度分析）、线性代数 Strang（矩阵方法、SVD）。具体到课程名和章节，并解释连接路径。
2. **第一性原理洞察**：解释定理背后的核心直觉，追溯最基础的假设。回答"为什么必须这样？"用用户已经理解的简单概念作为脚手架搭建新概念。
3. **证明策略模板**：把证明方法抽象为可复用的思维模板（ε/2 技巧、ε-剥离法、峰点论证、分组放缩、归纳三步法、supremum sandwich 等）。**命名模板**（如"上确界夹逼法""ε-剥离法"）便于记忆复用。
4. **历史与人物**：数学家为什么这么想？当时要解决什么具体问题？对后世的影响。标注具体年份（如 Bolzano 1817、Cauchy 1821、Weierstrass 1872）。⚠️ 2026-09-03 用户校准：**以机制/概念为主，历史只作点缀**，不要堆年表（"查知识不是查历史"）。
5. **拓展前沿**：相关的更高级概念。**必须从用户已知概念出发解释**，不得裸甩名词。如果用户没学过前置知识，要么搭建脚手架解释，要么暂时不提。
6. **图解注（配图辅助理解，2026-09-03 用户要求）**：对空间/结构/流程类概念（子问题 DAG、状态转移表、递推树、依赖图、谱系嵌套图等），**自己生成示意图或找现成图**辅助理解。可以：① 用 matplotlib/graphviz/ASCII 艺术/Mermaid 手绘概念图嵌入注中；② 从离线维基/OCW 原文/教材找现成插图（标注来源）；③ 生成 SVG/PNG 存到译文同目录 `assets/` 并用 Markdown 图片语法引用。图要小、聚焦一个概念、配一句图注，不做装饰性配图。

> 🖼️ **图解注的完整规范见references/image-pipeline.md**（2026-09-23 增补）：§10.2 保留原书插图（视觉模型给百分比 bbox → PyMuPDF `clip` 裁切 → `assets/` + Markdown 引用）、references/image-pipeline.md §10.2.5 图内印字三选一决策树、references/image-pipeline.md §10.3 自创图（判定清单 + 四条生成通道 + 视觉模型"生成→复核→纠错"闭环）、references/image-pipeline.md §10.4 实测坑清单。**原书图一律不丢**（🚨 铁律 26）。

## 3.2 质量标准（必须严格遵守）

- **每条注 800-1200 字**（配图/公式/字幕引文不计入），信息密度高，不凑数、不注水；写成可独立阅读的"小专题"——机制展开 + 例子 + 连接
- 跨课程连接要明确提及**课程名 + 具体概念 + 连接路径**（如"你在 6.042J 学过的等价关系，在这里就是 rational number 的相等定义——同一个等价类内的表示被视为'相同'"而非"这在群论中叫商集"）
- 🚫 **禁止甩名词**——不得只提高级概念名而不解释。写注前先查 `memory`（`global/academic-level-and-teaching-style.md`）确认用户学业水平
- 分布均匀，每个关键定理至少一条注
- 结合视频字幕中的教授口语化讲解，增加"教学现场感"；引用字幕时使用 `🎥` 标注来源（🚨 铁律 10：每条引文必须附中文翻译）
- 📖 交叉引用：指向用户已有的讲义（如 L01/L02/L03）或教材（如 CLRS §x.y）
- 🖼️ **配图辅助（2026-09-03 用户要求）**：空间/结构/流程类概念尽量配图——自己生成（matplotlib/graphviz/Mermaid/ASCII）或找现成图（离线维基/OCW 原图/教材插图，标来源），存译文同目录 `assets/` 引用；图聚焦单一概念并配图注

## 3.3 拓展连接的铁律（PS01 教训）

用户对拓展知识**有强烈兴趣**（跨学科连接是人格画像核心特征），但**禁止甩名词**——不能只提一个高级概念的名字而不解释。这是 PS01 初版犯的错误（甩了群论/商环/拓扑学/非标准分析等用户没学过的概念）。

**每条拓展连接的处理规则：**

1. **先查学业水平**——写注前必须用 `memory` 工具查询 `global/academic-level-and-teaching-style.md`，判断用户是否已具备理解该概念的前置知识
2. **脚手架法**——如果用户没学过前置知识，要么从第一性原理构建解释（从用户已知的概念出发，逐步推导到新概念），要么暂时不提。**绝不裸甩名词**
3. **精确连接路径**——每条跨课程连接必须精确到：课程名 + 具体概念 + 为什么类比成立 + 区别在哪。不是"这在群论中也有"而是"你在 6.042J 学过的等价关系，在这里就是 rational number 的相等定义——同一个等价类内的所有分数表示被视为'相同'。群论中把这个结构称为'商群'，但核心思想你已经会了。"
4. **拓展 ≠ 炫耀**——拓展的目的是帮用户看到知识地图的全貌，不是展示你懂多少高级概念。如果一个拓展概念需要 3 页纸才能讲清楚，而当前上下文只够提一句名字，那就不要提

## 3.5 结合字幕素材的注写法（重要）

- 从 2.4 提取的字幕中，找到教授对关键概念的**口语化解释、直觉比喻、证明中的关键步骤强调**
- 将这些素材以引用形式嵌入注中，格式：
  ```
  🎥 *教授名在视频中[教学动作]: "原文关键句子"（翻译：中文翻译）*
  ```
- 例如：
  ```
  🎥 *Colding 在视频中以极其口语化的方式将这一步讲透了：因为 $a$ 本身就是上界，$a_n \le a$ 自动成立，所以* "you don't need absolute value because I already know this is bigger than that"——*不等式方向天然确定，绝对值完全多余。（翻译：你不需要绝对值，因为我已经知道这个比那个大）*
  ```
- 字幕素材能提供**讲义中没有的教学细节**：教授的语调强调、直觉类比、证明节奏等
- 🚨 铁律 10：每条 🎥 引文必须附中文翻译，一条注内多条引文每条都翻译

## 3.8 设计问题驱动视角

每个关键定理的注，先回答**"这个定理在解决什么设计问题"**，再给连接与直觉：

```
> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 本节的设计问题是「……」。定理 X.Y 正是为解决它而设计：……
```

整章翻译完成后，提取 5-7 个"对全章有统摄力"的天才设计点，每个设计点回答"为什么这样设计抓住了本质"，而不是复述定义。

## 3.9 卡点诊断注（可选）

`[note]` 中可包含 `[我的卡点]` 片段，预判读者（用户）可能卡住的位置："这里的直觉陷阱是……如果以为……就会……正确理解是……"。

## 3.10 费曼式注

当某个概念特别抽象（如 supremum、eccentricity），写一条**费曼式注**：用不超过 3 句话、不用任何未解释术语的方式向"高中生"解释它，然后指出它和正式定义之间的差距（即"知识缺口"——正式定义里的每个词在费曼解释里对应什么）。费曼式注 + 卡点诊断注配合使用：前者给直觉，后者标陷阱。

## 3.11 效率视角类比

用户对"漂亮算法"与效率敏感。数学证明策略注可加"效率视角"类比——"这个证明技巧相当于把复杂度从 $O(n^2)$ 降到 $O(n \log n)$：ε-剥离法避免了反复重新检查整个区间"。用算法复杂度语言给数学证明建立直觉，是用户的母语。

## 3.12 事实核查

对所有注中出现的数字、年代、技术声明交叉验证：
- 公式推导是否正确（尤其是注中自创的类比公式）
- 历史年代是否准确（如 Bolzano 1817、Cauchy 1821——写前必须核对）
- 第三方工具/算法行为描述是否精确
- 查证手段：web search / 教材原文 / GitHub / 论文 / 离线维基（见 2.2 全资源搜索）
