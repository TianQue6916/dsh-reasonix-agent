## 2.7 大规模路径（>50 页或 >500 行英文，25×2 波次）

> ⚠️ **架构原则：不惜计算成本，质量优先。** 多批次大规模并行，给每个 dsh 任务的 prompt 必须极其详细（完整翻译规范、格式示例、避坑清单——模板见references/prompts.md）。
> **分工总纲（2026-08-09 用户拍板；2026-09-08 通道改 dsh）**：一律 dsh 任务翻译，主代理只做切分、组装、派发、合并、执行审计修复、回填修订版。**Reasonix 内建子代理一律不用（铁律 21）**，按主力机并发能力分批派发。
> **Strang 教训**：翻译 worker 的 prompt 必须包含四陷阱避坑清单（见references/prompts.md 6.1），逐句密度标准照旧。

### 2.7.1 按页切分

- 将 PDF 的**每一页**切分为一个独立文件（`page_001.txt`、`page_002.txt`…）
- 每页独立处理，避免跨页上下文断裂
- 如果某页边界正好在定理中间（定理跨页），将该定理所在页范围合并为一个文件
- 保存到临时目录：`.reasonix/attachments/pages/`
- 程序化实现：pypdf 按页拆分（references/toolchain.md 5.1）或 `qpdf 讲义.pdf --pages . 1-5 -- pages1-5.pdf`

### 2.7.2 波 1——翻译 worker（25 个并行，每个分 2 页，🚨 dsh flash）

- 🚨 铁律 11/12/21：一律 dsh 任务翻译，**模型 dsh flash**。启动 **25 个翻译 worker**，每个 worker 处理 **2 页**（25×2 = 50 页；超过 50 页分多批）
- 每个 worker 的 prompt 见references/prompts.md 6.1（必须包含：完整翻译规范、Strang 四陷阱避坑清单、逐句密度标准、格式示例、该 worker 的页范围、**wiki 检索结果注入（铁律 23）**）
- Write paths 声明为各自输出文件（`.reasonix/attachments/pages/page_XXX.bilingual.md`），**25 个 worker 的 write_paths 不能重叠**
- 翻译 worker 开工前完成 2.2 全资源搜索 + wiki 检索（术语表先由主代理生成并注入所有 worker prompt，保证术语一致性）

### 2.7.3 波 2——页级审计 worker（10 个并行，每 5 页 1 个，🚨 dsh flash，审计+修复一体）

- 翻译完成后启动 **10 个审计 worker（dsh flash）**，每个审计 **5 页**
- prompt 见references/prompts.md 6.2（10 项审计清单：英中对照/漏译/顺序/过渡段/证明压缩/习题误译/编号/公式格式）
- **🚨 铁律 20：审计+修复一体**——每个 worker 对照原文审计后**直接输出修订后的各页全文**（🔴 必须补全 → 🟡 建议补全 → 🟢 有时间再修，全部当场改好），不再单独输出意见清单让主代理另派修复
- 主代理只回填修订页 + 抽查 🔴 修复质量

### 2.7.4 波 2——写注 worker（3 个并行，🚨 dsh flash v4.1）

- 使用 **3 个 dsh flash（`deepseek-v4.1-flash`）worker** 撰写译者注（🚨 铁律 12：全任务统一 v4.1 flash，pro 已弃用）
- 每个写注 worker 处理约 1/3 的总页数
- prompt 见references/prompts.md 6.3（含：读者画像、注类型、质量标准、E 规则、页范围、**wiki 检索结果注入（铁律 23）**）
- Write paths 声明为译者注补充文件（`.reasonix/attachments/notes/`），不能重叠

### 2.7.5 波 2——交叉引用 worker（2 个并行，🚨 dsh flash）

- 分配 **2 个专用 dsh 任务**执行交叉引用标注，每个处理约 1/2 的翻译页面
- prompt 见references/prompts.md 6.4
- 注意：交叉引用需回原文核对页码，不硬编码编号（铁律 18）

### 2.7.6 合并与统一

- 合并所有翻译 worker 输出（按页码顺序）与页级审计修订、译者注、交叉引用标注为单个文件
- 合并译者注到对应位置
- 统一标题层级（`#` 课程名 → `##` 章 → `###` 节 → `####` 子节）
- 统一标签格式（颜色、写法）
- 修复 `$$` → fenced math block
- 检查跨页的上下文连贯性（页码边界处的句子是否断裂）

### 2.7.7 对比原文审计（主代理执行）

大规模翻译完成后，主代理必须执行以下系统性审计，按顺序操作：

**① 提取 PDF 原文文本**
```bash
pdftotext -f <起始页> -l <结束页> /path/to/original.pdf /tmp/original.txt
```
若发现内容明显缺失（定理陈述不完整、节标题后直接跳内容），尝试 `-layout` 或 `-raw` 模式重新提取并对比合并。

**② 定位章节边界**
```bash
grep -n "Section\|Theorem\|Definition\|Example\|Exercise\|Monotone\|Cauchy" /tmp/original.txt
```
建立"原文章节行号对照表"。

**③ 逐节对比审计清单**

| # | 检查项 | 检查方法 |
|---|--------|----------|
| 1 | **开篇段是否完整** | 节标题后原文是否有介绍段→翻译是否包含 |
| 2 | **所有定理/定义编号是否对应** | 原文 Theorem N → 翻译 Theorem N，无跳号/重号 |
| 3 | **证明是否完整** | 原文证明长度 → 翻译证明长度，无明显压缩 |
| 4 | **例子是否全部覆盖** | 原文 Example N → 翻译 Example N，无跳过 |
| 5 | **例子顺序是否正确** | 原文顺序 A→B→C，翻译不能变成 A→C→B |
| 6 | **习题边界检查** | 翻译文件习题编号从 N 开始，检查 N-1 之前的习题是否被跳过 |
| 7 | **过渡段是否遗漏** | 原文在两个定理/例子之间的过渡性段落是否被省略 |
| 8 | **人物/历史介绍是否遗漏** | 原文出现的数学家姓名、年代、背景介绍是否保留 |
| 9 | **内容是否被错误替换** | 原文定理 A 的内容不能出现在翻译的定理 B 中 |
| 10 | **严重翻译错误** | 检查已知易错点：例 2.29 的"还需更多工作"不要译成"极限为0" |

**④ 自动化验证（可选）**：对关键指标编写简单验证脚本，例如 Python 检查所有预期段落是否存在：
```python
checks = {
    "Example 2.32 present": "Example 2.32" in content,
    "Theorem 2.28 proof present": "sup" in content and "lim" in content,
    "Exercises 2.11.1-2.11.6 present": "2.11.1" in content and "2.11.6" in content,
}
```

**⑤ 问题分级与修复策略**（主代理发现即当场修复，🔴 必须补全 → 🟡 建议补全 → 🟢 有时间再修）：
| 严重程度 | 定义 |
|---------|------|
| 🔴 严重 | 整节/整个定理/整个例子缺失；结构重构；顺序混乱 |
| 🟡 中等 | 段落缺失；证明被大幅压缩；编号/顺序错误 |
| 🟢 轻微 | 术语翻译不一致；标点格式问题 |

**⑥ 输出审计报告**（主代理记录，供交付说明用）：
```
## 翻译审计报告
| 节 | 严重程度 | 核心问题 |
|----|---------|---------|
| §2.10 | 🔴 | Example 2.34 完全缺失 |
| §2.12 | 🟢 | 仅缺习题 2.12.6–2.12.10 |
```

## 2.8 最终审查（所有规模必做，含双审计）

### 2.8.1 双审计（🚨 铁律 12/20/21，所有规模必做，审计+修复一体）

- **超强审计**：1-2 个 **`dsh-remote -m deepseek-v4.1-flash -e max` 任务**（小规模 1 个，大规模 2 个并行），通读全部翻译结果 + 注，**直接输出修订后全文（审计+修复一体）**。prompt 见references/prompts.md 6.5。
- **格式审计**：1 个 **dsh flash** 任务，对照references/format.md格式规定逐条核对，**直接输出修订后全文（审计+修复一体）**。prompt 见references/prompts.md 6.6
- 主代理回填修订版、处理 ⚠待核项后，再人工过一遍references/format.md质量检查清单

### 2.8.2 人工审查要点（对照references/format.md质量检查清单）

对照质量检查清单逐项核查（交叉引用 / 排版基础 / 双语格式 / 内容层次 / PDF 与字幕 / 译者注），重点确认：
- [ ] 所有 sections 已覆盖，编号连续且与原文一致
- [ ] 交叉引用灰色行格式统一、页码准确
- [ ] 译者注分散插入、每条 800-1200 字、无甩名词
- [ ] 补充内容有来源（铁律 14）
- [ ] 全资源搜索已完成（2.2）且成果已用于查证/写注
- [ ] 超强审计/格式审计修订版已回填且 ⚠待核项已处理

### 2.8.3 Reader Testing（无上下文盲检）

抽 3 页（开头 1 页 + 中间 1 页 + 结尾 1 页），启动**只读 subagent**（不给原文、不给任何上下文），只输入译文，要求它：
1. 复述这页讲了什么（检验可读性）
2. 指出读不懂的地方（检验盲点：术语没首次翻译、指代断裂、编号悬空）
3. 判断这页是否是"翻译腔"（自然度盲检）

若暴露问题，按严重程度分级修复。此测试查"读得懂不懂"，对比原文审计查"译得对不对"，互补。

### 2.8.4 审稿人视角复查

假装自己是收到这份翻译稿的审稿人，逐条回答：
- 每个定理/定义/例子编号能否在原文中定位？
- 术语表是否一致？同一概念是否出现多个译法？
- 注的内容是否有真实来源支撑？无来源的注是否已删除？
- 是否有"凑数"段落（信息密度不足）？

### 2.8.5 错误记忆

完成翻译后，把犯过的错误记入 `.reasonix/attachments/translation_error_memory.md`（格式见 HISTORY.md 8.1），下次翻译前先读该文件避免重犯历史错误（如 PS01 甩名词教训、prob7sol 英中对照教训）。
