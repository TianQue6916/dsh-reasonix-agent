# Planning With Files — 文件化计划管理

Manus 风格：用持久化 markdown 文件作为"磁盘上的工作记忆"，解决长任务上下文丢失问题。

## 何时使用

多步骤任务（5+ 步）、调研任务、复杂项目、任何需要跨 session 跟踪的工作。简单问题或单文件编辑跳过。

## 三文件核心模式

| 文件 | 用途 | 更新时机 |
|------|------|---------|
| `task_plan.md` | 阶段、进度、决策 | 每个阶段完成后 |
| `findings.md` | 研究发现、关键信息 | 每次发现后 |
| `progress.md` | Session 日志、测试结果 | 整个过程中持续更新 |

基本原理：**上下文窗口 = RAM（易失，有限），文件系统 = 磁盘（持久，无限）**

## 工作流程

### 1. 创建计划

```markdown
# task_plan.md — [项目名称]

## 目标
[一句话描述项目目标]

## 阶段

### Phase 1: [名称]
- Status: `in_progress`
- 任务: [任务详情]
- 产出: [预期产出]

### Phase 2: [名称]
- Status: `pending`
- ...

## 决策记录
| 决策 | 原因 | 日期 |
|------|------|------|
| ... | ... | ... |
```

### 2. 记录发现

```markdown
# findings.md — 研究发现

## [日期] [主题]
- 关键发现
- 技术细节
- 参考链接

## [日期] [主题]
...
```

### 3. 记录进度

```markdown
# progress.md — 进度日志

## Session [日期-时间]
- 完成: [做了什么]
- 错误: [遇到的错误及解决]
- 下一步: [计划]
```

## 核心规则

### 2-行动规则
> 每 2 次浏览/搜索操作后，立即将关键发现写入文件。

### 先读后决策
> 重大决策前先读 task_plan.md — 让目标回到注意力窗口。

### 完成后更新
> 每个阶段完成后更新状态（in_progress → complete），记录错误。

### 所有错误都要记
```
## 错误记录
| 错误 | 尝试次数 | 解决方案 |
|------|---------|---------|
| FileNotFoundError | 1 | 创建默认配置 |
| API timeout | 2 | 添加重试逻辑 |
```

### 3-次重试协议
```
尝试 1: 诊断并修复 → 识别根因，应用修复
尝试 2: 换方法 → 相同错误？换不同工具/库
尝试 3: 重新思考 → 质疑假设，搜索解决方案
3 次失败后 → 上报用户，解释尝试过程
```

## 读 vs 写决策

| 情况 | 行动 | 原因 |
|------|------|------|
| 刚写完文件 | **不读** | 内容仍在上下文中 |
| 看了图片/PDF | **立即写 findings** | 多模态→文本，防止丢失 |
| 浏览器返回数据 | **写入文件** | 截图不持久 |
| 开始新阶段 | **读 plan/findings** | 重新定位 |
| 发生错误 | **读相关文件** | 需要当前状态来修复 |
| session 恢复 | **读所有规划文件** | 恢复状态 |

## 5-问重启测试

| 问题 | 答案来源 |
|------|---------|
| 我在哪？ | 当前阶段 (task_plan.md) |
| 我要去哪？ | 剩余阶段 |
| 目标是什么？ | 目标陈述 |
| 我学到了什么？ | findings.md |
| 我做了什么？ | progress.md |

## 与 Reasonix submit_plan 协同

- `submit_plan` → 创建完整计划（适合需要审批门的场景）
- `planning-with-files` → 手动管理 task_plan.md（适合持续跟踪、跨 session）
- 可以组合使用：submit_plan 提交大计划，task_plan.md 维护阶段细节
