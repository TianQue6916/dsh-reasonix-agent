## Merge-Back 报错机制链（证据强度标注）

已证实：
- 官方文案 `projectTree.worktreeCreatedDirty` =「已在 {branch} 创建隔离工作区；**源目录中未提交的改动没有被复制**」→ 用户 2.3 万文件几乎全未提交，所以 worktree 里几乎空（实测 `ced0b3b5cb` 只有 1 个 md）
- Merge-Back 预检要求「source 干净且无进行中 Git 操作」（SESSION_OWNERSHIP.zh-CN.md）
- **`.reasonix/` 是 Reasonix 运行时目录，只要在 git 跟踪范围内，源目录永远不可能干净** → 清理环节持续被阻止。这是结构性根因
- `rewind.forkWorktreeDirtySource`（创建隔离**分叉**要 source 干净/先 commit-stash）——修正之前「创建 worktree 需干净」的错误说法

机制推断（未验证：日志里找不到任何 merge 失败记录）：实际报错属于「合并已完成但清理未完成」一族。
