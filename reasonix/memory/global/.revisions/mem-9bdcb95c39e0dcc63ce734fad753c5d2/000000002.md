# dsh 0.1.5-rc.2 升级档案（Windows 主力机，2026-09-20）

## 结论一句话
CLI 调用方式**零变化**（dsh-gate 无需改），但**插件默认挂载 / 会话日志文件名 / session 对象 API** 三处变了，其中 session API 变化会让 anchored-standard 锚定**静默失效**（必须打补丁）。

## 升级动作
`npm i -g @deepseek-ai/dsh@0.1.5-rc.2`（npm latest；alpha 当时 0.1.6-alpha.2 未采用）。
备份：`~/.dsh/_backup-20260920-upgrade/`（settings.yaml、.env、整个 .agent-presets、两个 profile 的 yml、npm 全局清单、兼容性 dump、一次性工具脚本。）

## 兼容性核查（升级前实测）
- **CLI 参数未变**：`--profile` / `--patch` / `web` / `plugin` / `--dump-config` 全兼容；新增 sdk / sdk-minimal / acp profile。
- **包清单**：0.1.1 的 196 个 `@deepseek-ai/*` 包，0.1.5 只少 4 个（`dsh-client-runtime`、`dsh-host-apiproxy`、`dsh-tool-subagent-report`、`node-addon-landlock-run`），其余 240 个健在。
- **settings schema 未变**：`id: settings` + `config.path`（dsh-gate 注入点）、`persona`、`llm-pi-ai` 路由、`fallbacks`、`agent-loop.maxParallelToolCalls` 照旧生效（gate 实跑证实）。
- **变了的三处**：① `str_replace_editor` 不再默认挂载（官方改推 read/write/edit）；② 会话文件 `session.jsonl.zstd` → `session.v3.jsonl.zstd`；③ `session.events`（数组）被移除，改为 `snapshotEvents()` + `log`。

## 三处必改（已做）
1. `~/.dsh/profiles/headless/cordis.patch.yml`：`insert:` 尾部补挂 `@deepseek-ai/dsh-tool-str-replace-editor`（maxOutputChars: 16000）。**不补的后果**：tool-bootstrap 的 keep 集工具名缺失 → warnOnce 后把**全量 26 工具目录**暴露给首轮，锚定失效且无报错。
2. `~/.dsh/.agent-presets/anchored-standard/compaction-epoch.mjs`：新增导出 `sessionEvents(session)`（优先 snapshotEvents() → 旧 events 数组 → 可迭代 log → 空数组兜底），`scan()` 改用它；`tool-bootstrap.mjs` 的 `unlockedFor()`、`instruction-hint.mjs` 的 `hintIsDurable()` 同步改 import + 使用。
   - **回归根因**：`for (const event of session.events)` 在 0.1.5 抛 TypeError，被 tool-bootstrap 的 catch 吞掉后返回全量目录。修前首轮 26 工具，修后 2 工具。
3. junction 维护：`~/.dsh/profiles/node_modules/@deepseek-ai/*` 全是指向*当前 dsh 安装目录* 的 junction，**任何 dsh 实例启动都会重建**——用临时目录的 dsh 跑一次会把生产 profile 的 249 个链接全改指临时目录（本次踩到）。修法：用生产 `dsh --profile headless ...` 跑一次自动改回。另清理 9 个无主 junction。

## 插件面核查（本轮补做）
- **两个 profile 的 `dependencies` 均为空**：无树外插件；`dsh plugin --profile <p> list` 无输出（rc=0）。bundles 只有内置：web = `[dsh-base, dsh-web-app]`，headless = `[dsh-base, dsh-headless]`。
- **订正**：早期 `dsh-mode` 技能记的「dsh-hooks / dsh-llm-fallbacks / dsh-model-router」已不在 profile 依赖中（LLM 降级现由 settings.yaml 的 `fallbacks:` 节承担）；技能第五节已订正。
- 0.1.5 随包新增、**默认不挂载**的可选插件：`dsh-hooks-claude-code`、`dsh-hooks-codex`、`dsh-webhook`、`dsh-webhook-github`、`dsh-http-proxy`、`dsh-acp-app`、`dsh-sdk-app`、`dsh-sdk-minimal`、`dsh-tool-present`、`dsh-session-log-export`。
- **preset 7 个 mjs 的接口核查**：8 个事件名（agent/pre-step、agent/request、session/event、system-prompt/assemble、compaction/end、assistant/message、tool/call、user/message）**8/8 在 0.1.5 存在**；`session.header` 仍是 object（custom-bash / skill-search 依赖的 header.cwd 可用）。

## 验证证据
- headless 首轮 tools = `pwsh, str_replace_editor`（2 个，与 0.1.1 一致）；带工具任务实跑成功（pwsh echo 返回 ANCHOR-OK）。
- `dsh-gate-conc.ps1` 同步 4s 完成 ✅；**异步**（schtasks 脱离会话）派发→4s 完成→产物 13B 落盘 ✅。
- web：端口监听 + 401 授权围栏 + token URL 正常；浏览器 UI 正常渲染且**完整列出 5 个 preset**（含 Anchored Standard），无 JS error。
- `sessionEvents()` 单元测试四形态通过（snapshotEvents / legacy events / iterable log / 缺字段）；epoch 语义正确。

## 验证边界（未完成项）
web 会话的 UI 端到端（发消息 → 首轮 tools=2）**未打通**：无头浏览器里「选择工作区」候选点击后进不去会话（合成 click / 真实 mouse 事件 / URL 深链三种方式都试过）。人工验证法：打开 `dsh web` → 选工作区 → 选 Anchored Standard → 发一句话 → 用 `dump-session.mjs` 看首个 `request/header`，tools 应为 2 个。
另已证实：**preset 是 web 专属路径**，headless 无法承载（用 --patch disabled profile 的 tool-bootstrap 再 insert agent-presets，配置树正确但会话仍拿不到 preset）。

## 坑（新）
本机 bash 工具里 `$env:TEMP` 被 Reasonix 重定向到 `reasonix-session-tmp-*`，与真实 `%TEMP%` 不同 —— 传路径给 dsh 的 `--patch` 必须用**绝对真实路径**，否则 dsh 报 `failed to read overlay`（本次一度误导探针结论）。

## 回滚
`npm i -g @deepseek-ai/dsh@0.1.1-rc.2` + 从备份恢复 settings.yaml / .agent-presets / profiles 的 yml（sessionEvents 补丁对 0.1.1 向后兼容，可不回退）。

## 待办（Linux 天阙机）
升级时 Linux（100.79.96.82）**offline（已 7 天未上线）**，双机版本暂不一致（Linux 仍 0.1.1-rc.2）。上线后需：`npm i -g @deepseek-ai/dsh@0.1.5-rc.2` + 补挂 str_replace_editor + 打同一个 sessionEvents 补丁 + 重建 junction + 跑锚定验证（首轮 26 工具 = 未打补丁）。

## 细节档案
`dsh-mode` 技能 v1.2.0 第十一节（完整兼容性表 + preset 插件核查表 + 验证边界 + 坑位）；`dsh-gate` 技能 v2.3.0（会话文件名已更新）。探针脚本存 `~/.dsh/_backup-20260920-upgrade/web-verification/`。
