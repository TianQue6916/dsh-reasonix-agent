## 现象
dsh Web GUI 对话里出现一行「图片无法预览 · <图注>」（`dsh-client-ui-chat` 的 `"image.failed": "图片无法预览"`）。

## 定案（2026-11-17 实测，两端都验过）
不是远程控制插件故障。是 **markdown 图片路径指向不存在的文件**。

Windows 会话 `--C-Users-27063--/session-d73d1bf0-6803-471d-9900-ca1ad725bb1f` 里写的是：

```
![球套球：三条标尺对着同一条边界线](C:/Users/27063/Desktop/课程文件/待处理文件夹/数学/fig-ball-ruler.png)
```

- Windows：`C:\Users\27063\Desktop\课程文件\待处理文件夹\数学` **不存在**（`pwsh -EncodedCommand` 验证，避开中文编码假阴性）。
- Linux：`~/桌面/课程文件/待处理文件夹/` 只有 `计算机`，也没有该路径。
- 真实落点在 **Linux**：`/home/tianque/桌面/待处理文件夹/数学/实分析/课程问题/fig-ball-ruler.png`（85794 B，与生成日志 `png 85794` 一致）；`fig-ball-ruler-katex.png` 在 `…/实分析/课程问题/球套球-图片方案对比/`（89348 B）。

⇒ 路径是「Linux 目录结构 + Windows 前缀」的**混合幻觉路径**。

## 机制（源码级）
`dsh-client-ui-chat/lib/client.js`：
```js
fileMediaUrl(base, path) { … return new URL(`api/file?path=${encodeURIComponent(path)}`, base).href }
```
`isAbsoluteWorkspacePath` 接受 POSIX `/` 与 Windows `C:/`、`\\` ⇒ 方言路径原样发出，URL 只相对 `document.baseURI`，**没有 host 维度**。
服务端 `dsh-api-session-controller` 的 `SessionMediaReferences` → `/api/file` 走 `ctx.fs`（本机），上限 `ctx.attachments.imageLimits.maxImageBytes`，错误映射 `FS_NOT_FOUND→404 / FS_SANDBOX_DENIED→403 / FS_TOO_LARGE→413`。

### 关键新发现（2026-11-17 18:40 实测）
**在 POSIX Host 上请求 `C:/…` 得到的是 `400 absolute path required`，不是 404。** 服务端先用 `node:path` 的 POSIX `isAbsolute` 判定，失败即 400。这一条决定了跨机方言路径的修理方式（见下）。

## 已装：dsh-media-rescue 0.2.0
`dsh plugin --profile web add git+https://github.com/BrainZombie/dsh-media-rescue.git`（无 dependencies，自动插入 `dsh.profile.bundles`）。
profile patch（`~/.dsh/profiles/web/cordis.patch.yml` 末尾）：
```yaml
- id: media-rescue
  config:
    enabled: true
    roots:
      - /home/tianque/桌面/待处理文件夹/数学
      - /home/tianque/.dsh/.learn/run/figs
    materialize: workspace
    log: true
```
备份：`package.json.bak-20261117-183603-pre-media-rescue`、`cordis.patch.yml.bak-20261117-183603-pre-media-rescue`、`compatibility.json.bak-20261117-183603`。

### 必须打的一行本地 patch（升级插件会被覆盖）
`node_modules/dsh-media-rescue/index.js:316` 原文 `if (response.status !== 404) {`，改为 `if (response.status !== 404 && response.status !== 400) {`。原文件留在 `index.js.orig-20261117`。
原因：上游只在 404 介入，而跨平台方言路径先撞 400；插件自身的 `lib/media.js:isAbsolutePath` 本来就接受 `C:/`、UNC，所以放进救援路径即可按文件名从 `roots` 找回。

## 生效条件
**需要重启 dsh 进程**（client bundle 与 host 插件都不进 HMR）。截至 2026-11-17 18:40 用户要求「先不要重启」，故 3081 上的 GUI 尚无变化。
上游空白：建议给 BrainZombie/dsh-media-rescue 提 issue——内置 `/api/file` 在 POSIX Host 上对 Windows 方言路径返回 400，插件应把 400 纳入救援路径。

## 顺带两处隐患
1. `dsh-tunnel.service` 是 `-L 3082:127.0.0.1:3080`，但 Windows `netstat -ano` 里 3080/3081/3799 **都没有 LISTENING** ⇒ 隧道指向死端口。
2. `~/.dsh/logs/dsh-web.log` 里 `[ds-harness-remote] server control connection failed` 大量刷屏：`RATE_LIMITED 429 reason:"invalid_json"`（`phase: credential_refresh`）、`503`、`timeout`。

## 教训
- 「图片无法预览」先 `ls` 那个 path，别先怀疑 remote/插件；UI 文案不区分 400/401/403/404/413。
- 跨机给图：`data:` 内嵌或会话 attachment；路径式引用只在同机有效，且**方言（`C:/` vs `/`）在 POSIX Host 上直接 400**。
- 排查 Windows 中文路径用 `pwsh -EncodedCommand`（UTF-16 base64）走 ssh stdin。
- Windows session 是 `session.v4.jsonl.zstd`，`grep` 搜不到，用 `zstandard.stream_reader` 解压。
