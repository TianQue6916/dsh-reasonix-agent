## ⚠ 最大的坑：`pnpm install` 在 dsh 的 Low IL shell 里必定失败

```
[EPERM] EPERM: operation not permitted, symlink 'D:\Toolbox\goat-gateway\dsh-plugin-local-search'
        -> 'C:\Users\27063\.dsh\profiles\desktop\node_modules\dsh-plugin-local-search'
```

**根因**：dsh 给 workspace（`C:\Users\27063`，含 `.dsh`）打了 **Low integrity label**，Low IL 进程创建 symlink/junction 需要 write-up ⇒ 被拒。

**后果**：
- pnpm 会**先完成包安装**（这次 5 个包全部装好了），然后在最后的 `linkDirectDeps` 阶段失败
- 失败的 symlink 被改名成 **`.ignored_<name>`**（半复制残留，只有 README.md）
- 于是 `node_modules/dsh-plugin-local-search` **消失** ⇒ desktop profile 启动时缺这个 bundle

**修复**（UAC 提权）：

```powershell
cmd /c mklink /J "C:\Users\27063\.dsh\profiles\desktop\node_modules\dsh-plugin-local-search" `
                "D:\Toolbox\goat-gateway\dsh-plugin-local-search"
```

junction 在 Low IL 下也会 Access denied，**必须提权**。

**预防**：以后跑 `pnpm install` 前先想一遍哪些依赖是 `link:` / `file:` 协议 —— 那些都要在 install 后手动检查并重建。

## 验证清单（升级后必查）

```bash
# 1. 目标包版本是否到位
python -c "import json,io;print(json.load(io.open('node_modules/<pkg>/package.json',encoding='utf-8'))['version'])"
# 2. node_modules 里手工改过的文件是否被覆盖（thinking-guard 的 cancel kind 修复）
md5sum node_modules/@ethanwong-hk/dsh-thinking-guard/lib/index.js   # 期望 9b00c90352d80ffeae49759f232bb52b
# 3. link: 依赖的 symlink 是否还在
ls -la node_modules/ | grep '^l'
```

这次 md5 **未变** ⇒ thinking-guard 的修复保住了（`pnpm install` 没有重装它，因为版本没变）。

`dsh.profile.bundles` 里 `@deepseek-ai/dsh-base` / `dsh-web-app` / `dsh-experimental-voice-input-bundle` 在 desktop 的 `node_modules` 里**解析不到是正常的** —— desktop 的 dsh 内核来自 Electron 的 `resources/app.asar`，不在 profile 的 node_modules 里。判据是 `dependencies` 全部可解析即可。
