## 症状
Windows 的 GUI 预设选择器里有「大一统理论与第一性原理」（`preset-learn`），Linux 上没有。但 `~/.dsh/.agent-presets/learn/preset-declaration.yml` **两边内容完全一致**（sha256 相同，0 个文件不同）。

## 根因：预设由两层组成，只有一层在同步范围里
| 层 | 路径 | 在 sync 里吗 |
|---|---|---|
| 预设实体的钩子文件 | `.agent-presets/learn/*.yml` | ✅ 同步 |
| **把它注册进 GUI 列表的 patch row** | `profiles/<name>/cordis.patch.yml` 里的 `- id: preset-learn` | ❌ **在 `EXCLUDE_FILES` 里，各机自己维护** |

`cordis.patch.yml` 被排除是因为里面混着机器专有的绝对路径与平台二进制。代价就是：**加新预设必须双机各写一次 patch row**，否则「文件同步了、GUI 里没有」。

## 2026-11-17 补法
把 Windows `profiles/web/cordis.patch.yml` 的 765–1218 行（`preset-learn` 整块，454 行）插到 Linux 的 `- id: agent-default-model` 之前（第 730 行）。改完 `dsh --profile web --dump-config | grep preset-learn` 能打出：

```
- id: preset-learn
    name: 大一统理论与第一性原理
```

## 顺带挖出的第二个雷：Linux patch 里有 Windows 绝对路径
重启后新进程直接崩：
```
Error: Cannot find module '/home/tianque/D:/Toolbox/goat-gateway/mcp-goat-quota.mjs'
```
`profiles/web/cordis.patch.yml` 有两处 `args: [ 'D:/Toolbox/goat-gateway/mcp-goat-quota.mjs' ]`
（728 行 = anchored-standard 里，1183 行 = 新插入的 learn 块里）。Linux 上真身是
`/home/tianque/goat-gateway/mcp-goat-quota.mjs`。**这个雷在重启前就存在，只是旧进程
（13:35 起的）读的是旧配置、没暴露；一重启就炸。**
⇒ 教训：跨机搬 `cordis.patch.yml` 的片段，必须 `grep -nE 'D:/|C:/|Users'` 逐条改绝对路径。

## 另外
- Linux `dsh-web.service` 的 ExecStart 实际是 `--port 3080`（unit 描述文字里写 3081 是过时的注释），HTTP 401 = 需要认证，正常。
- Linux 上 `dsh-pilot` 加载时报 `cannot get property "config" without inject` —— 它在 Windows 侧已因为是 0 调用被移除，Linux 侧还装着。
