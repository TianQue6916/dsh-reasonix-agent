## 新工具（`~/.dsh/storages/tools/`）

- `mnemon-reconcile.py`：vault ↔ mnemon 对账。判据 = front-matter `description` 归一化后子串匹配，**并**用 `tag[0] == name`（或 `name + '.md'`）兜底。输出 synced / missing / orphan 与 `--json` / `--orphans-md`。
- `mnemon-heal-rename.py`：读上一步 json，① `mnemon forget` 掉 tag 以 `.md` 结尾（旧版脚本用文件名当 name）或含 `fixture` 的孤儿；② 对 missing 的 fact 生成 draft 后 `mnemon import --no-diff` 强制写入；执行前自动备份 db 到 `~/backups/`。

## 三个已定论的坑

1. **`memory-to-mnemon.py --full` 会造重复**：mnemon 的去重按 content 相似度，`--full` 重新喂 398 条后实测冒出 **33 个重复组 / 55 条**（`discrete-math ×10`、`advanced-math ×9`）。跑完 `--full` **必须**接 `mnemon-dedupe.py --apply`（判据：存活条数 == 唯一标题数）。
2. **改名不会反映到 mnemon tag**：import 判「内容已存在」→ 新 name/tag 写不进，旧 insight 成为孤儿（实测 12 条 `*.md` tag 残留）。修法：`--no-diff` 强制写 + forget 旧条目；`--no-diff` 之后同样要接一次 dedupe。
3. **`/tmp` 与 Windows Python 不互通**：Git Bash 的 `/tmp` → `C:\Users\27063\AppData\Local\Temp`，Python 里写 `open('/tmp/x')` 会 FileNotFoundError。中间产物一律写到 `~/` 下。
