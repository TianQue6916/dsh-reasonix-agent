## 最终状态（2026-11-16 03:47 完成，已实测验证）

WPS 从「4 版本并存 + 更新链断裂」修复为**单一 12.1.0.29161**。

### 做了什么
1. 下载官方 32 位完整包 `https://official-package.wpscdn.cn/wps/download/WPS_Setup_29161.exe`（293.8 MB，SHA256 `d5a7d632411c73962a2e1ee8d5545fe125f414ad845f8de7f5dc393c4e10f391`，签名 `CN="Zhuhai Kingsoft Office Software Co., Ltd."`）到 `C:\Users\27063\Downloads\WPS_Setup_29161.exe`
2. 关闭全部 9 个 WPS 进程 → `Start-Process -Verb RunAs` 提权运行安装器 → 用 wincu 点击「立即安装」（GUI 是 Qt5QWindowIcon，UIA 读不到按钮，只能用物理坐标 `x=1719 y=1094`）
3. 安装约 50 秒完成，装到 `D:\wps\WPS Office\12.1.0.29161`（**沿用原路径，因为 InstallPerUser + 读注册表 InstallRoot**）
4. 删除旧版本目录 `12.1.0.28043` 成功；`12.1.0.28505` 删到只剩 2 个文件 18.2 MB —— `kbaseconfigcenter64.dll` + `qingnse64.dll` 被 **explorer.exe (pid 13940) 作为 shell extension 加载锁定**，`taskkill /f /im explorer.exe` 报 Access denied（非管理员），**需重启电脑后删**
5. 任务栏 lnk 已于修复前改为 `D:\wps\WPS Office\ksolaunch.exe` + `/prometheus /fromksolaunch /from=taskbar`（备份 `.bak-20261116-pre-ksolaunch`）

- `D:\wps` 是指向 `D:\30-软件\wps` 的 junction（ReparsePoint），注册表一律记 `D:\wps\...`。这可能是 0x80070002 的深层来源，但改动收益低风险高，**不建议动**

### 关键教训
- WPS 每次升级新建 `12.1.0.xxxxx` 版本目录、**不清旧目录**，任务栏 lnk 会硬编码带版本号的绝对路径 → 升级后任务栏仍启动旧版
- 正确做法：所有入口一律指向 `D:\wps\WPS Office\ksolaunch.exe`（不含版本号）
- 覆盖安装会**自动清空 addons pool 并重建**，不需要手动删
- `uninst.exe /S` 静默卸载在 12.1.0.28505 上实测无效（社区反证 https://mole.fit/zh/windows/tested-apps/wps-office），覆盖安装更省事
