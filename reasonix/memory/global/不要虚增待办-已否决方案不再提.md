## 规则（2026-10-28 用户指出，原话：「3是什么意思？我让你做这个么」）

**不要把「我自己提出、但已被用户排除」的备选方案重新列进待办清单。**

事情经过：我给过一个三选一（A 注入 PLAN / B Windows 计划任务 watcher / C 按需 dispatch），
明确推荐 C 默认 + A 兜底，用户回「可以」= 批准推荐方案 ⇒ **B 已经被排除**。
但我随后在验收清单里写「3. B 方案未装，要装再说」—— 把一个被否掉的选项当成欠用户的活，
既是虚增待办，也是变相二次推销（B 会持续烧 token）。

## 为什么这是错的

- 用户的「可以 / 好 / 就这样」= 对推荐方案的批准，**不是对全部备选的打包授权**。
- 已排除项在清单里占位，会让人误以为还有事没完、还要再拍一次板。
- 清单里只该出现：① 用户明确要求过的 ② 我自己弄坏或漏掉的。不该出现「我提议但被否」的。

## 落地做法

- 验收清单只列「他要求的」和「我搞坏的」，一项一格，带证据。
- 被排除的方案要在记忆里显式标成「已否决，不再提」，而不是「未装，待定」。
- 想改主意时也不主动提，除非用户先问。
