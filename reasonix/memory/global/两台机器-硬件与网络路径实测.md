## 网络拓扑与三条 SSH 路径（2026-11-11 实测）

`~/.ssh/config` 三个别名：
| 别名 | 地址 | 路径 |
|---|---|---|
| `tianque` | `100.79.96.82` | Tailscale（**实际底层走 Wi-Fi**，见下） |
| `tianque-lan` | `192.168.243.2` | 网线直连：Windows 2.5GbE 静态 `192.168.243.1/24`（Manual，无网关）↔ X1C7 **USB 网卡** `enx00e04c074608`（Realtek RTL8153，MAC `00:E0:4C:07:46:08`） |
| `tianque-wifi` | `192.168.0.106` | X1C7 的 `wlp0s20f3`，同网段 Windows RNDIS `192.168.0.100`，网关 `192.168.0.1` |

**Python TCP 吞吐实测（8 秒，4MB buffer，单向 server→client）**：
| 路径 | 吞吐 | 占理论 |
|---|---|---|
| `tianque-lan` 192.168.243.2 | **118.6 MB/s / 0.95 Gbps** | 95% of 1GbE |
| `tianque-wifi` 192.168.0.106 | 9.8 MB/s / 0.08 Gbps | — |
| `tianque` 100.79.96.82 (Tailscale) | 7.0 MB/s / 0.06 Gbps | — |

**根因**：
1. X1C7 的 Wi-Fi 连的是 SSID `Tian Que Workspaces`，**2.4GHz 信道 11（2462 MHz）**，PHY 仅 **150 Mbps**（802.11n MCS7 40MHz），信号 -25 dBm 极强 —— 慢在频段和 PHY 速率，不是信号。
2. `tailscale status` 显示 `direct 192.168.0.106:41641` —— **Tailscale 选了有默认网关的 Wi-Fi 接口做 endpoint，没有选无网关的 192.168.243.x 有线网段**。所以 `tianque` 实际走的是 2.4GHz Wi-Fi，再叠一层 WireGuard 加密（9.8 → 7.0，加密开销约 30%）。
3. X1C7 路由：`192.168.243.0/24 dev enx… metric 100`（有线，优先）、`default via 192.168.0.1 dev wlp0s20f3 metric 600`（Wi-Fi 是唯一出口）。

## 定论（不要重新推导）

- **大文件传输必须用 `tianque-lan`**（118 MB/s ≈ 1GbE 线速）。`tianque`（Tailscale）只有 7 MB/s，**只适合命令、小文件、远程管理**。
- 不要假设"Tailscale 在同一局域网内会走直连、速度等于有线" —— **本机实测证伪，差 17 倍**。Tailscale 的 direct 指的是"不经 DERP 中继"，不代表走最优物理链路。
- 链路上限 1Gbps 是因为 X1C7 用 **USB 千兆网卡**（RTL8153），不是原生网口（`enp0s31f6` DOWN，X1C 无 RJ45）。要提速有两条路：USB 2.5GbE 网卡（150-250 元，实测约 230MB/s）或 Thunderbolt 3 直连（两台都有雷电，理论 10-20Gbps，雷电线 100-200 元）。
- 若想让 Tailscale 也走有线：需要给 192.168.243.x 网段配默认路由（例如 Windows 做 ICS 共享），但这会让 X1C7 的路由变复杂，收益有限。

## 两台机器的共性短板

- **主盘都是 QLC**（Kingston OM8 / Intel 660p）—— 大块持续写入都会掉速，是两台机器共同的性能陷阱
- 机器 A 的 RTX 5070 只有 8GB VRAM：7B Q4 推理勉强、13B 不行、LoRA 微调极紧张 —— **定位是推理机，不是训练机**
