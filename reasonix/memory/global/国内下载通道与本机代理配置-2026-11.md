## 一、下载通道矩阵（先查这张表，别再试直连）

| 场景 | 走什么 | 实测 |
|---|---|---|
| **GitHub 文件/仓库** | `https://ghfast.top/https://github.com/<path>` | **0 KB/s → 53~1842 KB/s** |
| GitHub 其他反代 | `gh-proxy.com` ✓ / `ghproxy.net` ✓（慢）/ `kkgithub.com` ✗挂了 / `ghfast.top` 对网页 403 | 只代理文件，不代理 HTML |
| PyPI | `mirrors.aliyun.com/pypi/web/simple/` | **1.34~1.62 MB/s** |
| HuggingFace | `HF_ENDPOINT=https://hf-mirror.com` | 200 / 0.93s |
| npm（Linux 上） | `npm config set registry https://registry.npmmirror.com` | 必须，否则 npm 全超时 |
| GitHub 仓库单文件 | `cdn.jsdelivr.net/gh/<user>/<repo>@<branch>/<path>` | 官方 CDN，合规 |

**已永久配置**：
- Windows + Linux 都设了 `git config --global url."https://ghfast.top/https://github.com/".insteadOf "https://github.com/"`（clone 自动走反代；**push 不受影响，因为用 ssh**）
- 私有仓库 clone 前要临时 `git config --global --unset url."https://ghfast.top/https://github.com/".insteadOf`

## 二、⚠️ 测速陷阱（我踩过，浪费了一小时）

`curl -w %{speed_download}` 在以下情况会**严重失真**：
- **302 重定向的文件**（如 `mirrors.aliyun.com/.../ubuntu-*.iso` 会重定向）→ 返回 `size=0 speed=686B/s`，看着像"被限速"
- **小文件**（HTML 首页、SHA256SUMS 几百字节）→ `speed_download` 毫无意义（baidu 首页显示 6 KB/s）

**正确测法**：用确定有实体的大文件，下 12~15 秒看 `size_download / time_total`：
```bash
curl -s -L -o /dev/null --max-time 15 -w "%{http_code} %{size_download} %{speed_download}\n" \
  "https://mirrors.aliyun.com/pypi/web/simple/"   # 21 MB / 15s = 1.34 MB/s，这才是真带宽
```

## 三、本机出口与链路（2026-11-14 实测）

- 出口 = `以太网 2` = **Remote NDIS**（USB\VID_19D2，ZTE 随身 WiFi），GW 192.168.0.1
- **不能换网**（用户隐私考虑），随身 WiFi 手机测速 40 Mbps，实测国内 1.34~1.62 MB/s ✓
- **路径 MTU = 1500**（`ping -f -l 1472` 通）。⚠️ 我之前误判成 1400 并写进计划，已纠正
- 国际链路**分钟级剧烈波动**：
  ```
  00:03  20.205.243.166 → 000 超时
  00:06  同一 IP → 200 / TTFB 0.47s
  00:20  同样 5 次里 3 次超时
  ```
  凌晨 01:00 GitHub 能到 **381 KB/s**，23:00 只有 8~35 KB/s（差 11~45 倍）

## 四、dev-sidecar 2.3.5 的能力边界（已升级，2026-11-13）

- **ECH 是真的有用**：`dns.ech.domains` 内置 25 条（x.com/twitter/chatgpt/openai/pixiv/medium/substack/docker…），
  用 `cloudflare-ech.com` 当 public_name 骗过 SNI 阻断。
  **实测：x.com 000→200、twitter 000→301、pixiv 000→200、status.openai.com 000→200**
- **ChatGPT 主站仍 403**：OpenAI 服务端按 IP 属地拉黑（页面直接显示你的出口 IP `117.61.185.101`），**ECH 改不了出口 IP ⇒ 无解**
- `dns.nat64` 默认 enabled 但 `prefix` 为空（需运营商前缀）
- **`intercepts` 语义变了**：v2.3.5 里 `null` = 从列表移除（比 2.2.0 更彻底）
- **dev-sidecar 不读系统 hosts**，用自己的 `preSetIpList` 做 DNS；要让 hosts 生效必须把域名加进 `proxy.excludeIpList` 让它 bypass

## 五、hosts 优选的真实效果（别再抱期待）

- ghprobe（Windows）/ ghauto（Linux）能挑出**我手工枚举不到的活 IP**（如 `20.175.192.147`）
- **但有效期是分钟级**：23:45 挑的 IP，00:03 就死了
- **A/B 实测（2026-11-15 00:22）**：有 hosts 2/3 成功，删掉 hosts 2/5 成功 —— **删 hosts 没有更好，已回滚**
- **结论**：hosts 优选收益（±5 KB/s）远小于链路波动幅度（0↔30 KB/s）。**GitHub 网页晚上就是不稳定，这是物理事实**
