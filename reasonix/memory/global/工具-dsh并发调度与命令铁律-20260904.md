## 〇·补、2026-09-11 铁律（最高优先级，双机对照实验锁定）

1. **长任务（预计 >90 秒）一律 `--async`**
   同一任务/模型/`-e high` 对照：同步 `dsh-remote`（SSH 前台）→ ❌ `rc=1`、167s、**0 字节输出**；
   `--async`（schtasks 脱离 SSH 会话）→ ✅ `done`、192s、6426 字节。唯一变量是进程树归属。
   已排除：API 上游（同 prompt curl 148s/HTTP 200/10.37MB 成功）、dev-sidecar 代理、Node 内存（8GB 堆无效）、
   SSH/TCP 保活（同方式 SSH 空跑 210s 正常）、传参/长度/并发。失败耗时刚性集中在 164–181s 且零诊断输出。
2. **除非用户明确要求静默，禁止 `--no-notify`**
   通知链路完好（本机 `notify-send` + 反向 SSH 均实测发出横幅）。「通知没了」的真因是调用方在 9 处调用上全加了该开关。
3. **`-e/--effort` 已修复（此前长期完全失效）**
   根因：`settings.yaml` 的 `agent-default-model:` 段无 `reasoningEffort:` 键，脚本 `-replace` 静默空转 →
   铁证是 `-e high` 与 `-e off` 的 settings 副本 SHA256 完全相同。已补 `reasoningEffort: high` 并改为按键存在性判断。
   验证：`-e off`/`-e max` 副本 hash 不同。**判断 YAML 键存在性必须用 `-match`，不能靠替换前后差异**（否则重复插入 → `DUPLICATE_KEY` → dsh 启动即失败）。
4. **失败排障**：`dsh-remote --status` 的 `note` 现含 rc/耗时/输出字节，并给出 `.diag.txt`（原始 stdout+stderr）路径。

## 一、核心变更（2026-09-04）

**本机(Linux 天阙)不再直接跑 dsh**——性能不够（实测并发测试 CONNECTION error/node 崩溃；dsh-gate 大任务 rc=143 超时）。所有 dsh 任务统一派发到主力机（Windows 天阙九泉）。

### 主力机并发机制（已验证双并发/三并发 done）
- 新脚本：`C:\Users\27063\.local\bin\dsh-gate-conc.ps1`
- **并发核心**：每次调用造独立 settings 副本（`~\.dsh\gate\settings-<id>.yaml`）+ `--patch` 指定 path → 不碰全局 settings.yaml → 同机多任务并行互不互踩
- **Async 后台化**：`-Async` 参数 → schtasks 一次性任务（`/TR` 限 261 字符，用 `dsh-gate-runner.ps1 <TaskId>` 短引导）→ 脱离 SSH Job Object（否则 SSH 断开子进程被杀 = GitHub #7974）
- **状态文件**：`~\.dsh\gate\status\<id>.json`（phase: spawned|running|done|failed|killed）；`-Status` 只读查询不干扰运行
- **结果落盘**：`%TEMP%\dsh-gate\<时间戳>-<模型>.txt`
- **完成通知**：反向 SSH `notify-send` 弹本机横幅（dbus 实证：`DISPLAY=:0 DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1000/bus`）

### 本机统一入口：`~/.local/bin/dsh-remote`
```
dsh-remote "任务"                                  # 自动判定难易
dsh-remote -pro "任务"                              # pro+max
dsh-remote -m google/gemini-3.8-flash "任务"        # 自由模型
dsh-remote --async "长任务"                         # 后台派发+完成横幅
dsh-remote --status                                 # 查主力机全部任务
```

## 三、PowerShell/SSH 实战教训（本次反复踩，防复发）

1. **PS 5.1 `@array` splatting 对含 switch 参数错位**（`& $bin @inner` 会把值左移）→ 一律显式命名参数调用
2. **`$args` 是 PS 自动变量**，脚本里 `$args += ...` 污染 → 用自定义变量名
3. **PowerShell 远程执行**：scp 脚本文件 + `-File` 执行，别用内联命令（引号/`$`/中文转义地狱）
4. **schtasks `/TR` 限 261 字符** → 长命令用短 runner 脚本中转
5. **Windows 远程进程随 SSH 断开被杀**（Job Object）→ 后台任务必须 schtasks 脱离

## 四、命令写法铁律（host block 规避）

**禁止 `cmd | python3 -c "..."`**（host: inline interpreter 后跟可隐藏失败的段 → block + 连锁跳过，一次拦截一整轮浪费）：
- ✅ `python3 - <<'EOF' ... EOF` heredoc
- ✅ 解释器命令放命令末尾（`curl ... -o f && python3 f.py`）
- ✅ 先落盘文件再解析
- ❌ `curl ... | python3 -c "..."`、函数内嵌管道
