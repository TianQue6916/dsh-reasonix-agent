## ① 绑核脚本：`~/.dsh/tools/pin-pcore.ps1`

用法：

```powershell
cd ~/.dsh/tools
.\pin-pcore.ps1 pnpm install
.\pin-pcore.ps1 npx vitest run
.\pin-pcore.ps1 npm run build
```

- 默认 mask `0x0000FFFF`（P-core 0-15 = 8 物理核 × 超线程）
- **只绑从该命令派生的进程树**（用 parent 链算后代），不碰 dsh 自己的 Electron 进程
- 每 250ms 扫一次子孙进程并绑，覆盖 pnpm → node → esbuild 这类多级派生
- 立即绑 root（否则短命令会在第一次循环前退出，实测 `node --version` 时 `bound 0`）
- 实测：2 秒的命令 `bound 1 process(es)` ✓
- 退出码 = 子命令退出码（`-NoNewWindow` 下 `$p.ExitCode` 偶尔读成空，非致命）

**依据**：本机实测 8 路默认 1150ms → 绑 P-core 878ms（**-24%**）。

## ② subagent 的模型策略：**dsh 原生已完整支持，不需要插件**

`@deepseek-ai/dsh-subagent/lib/index.js:315-331`：

```js
function resolveChildAgentOptions(parent, requested, childDepth) {
  const parentOptions = parentAgentOptionsForDelegation(parent);
  const resolved = {
    ...parentProvider !== void 0 ? { provider: parentProvider } : {},
    ...parentModel !== void 0 ? { model: parentModel } : {},
    ...parentReasoningEffort !== void 0 ? { reasoningEffort: parentReasoningEffort } : {},
    ...parentMaxTokens !== void 0 ? { maxTokens: parentMaxTokens } : {},
    ...requested,                 // ← 调用方显式传的覆盖父的
    subagentDepth: childDepth
  };
  // 换 model 但没显式给 reasoningEffort ⇒ 丢弃父的 effort，避免不匹配
  if ((resolved.provider !== parentProvider || resolved.model !== parentModel) && requested?.reasoningEffort === void 0) delete resolved.reasoningEffort;
  return resolved;
}
```

⇒ 三条同时成立：
1. **不传 `agentOptions` → 完全继承父 agent 的 route**
2. **传 `agentOptions` → 逐字段覆盖**（provider / model / reasoningEffort / maxTokens 都可单独覆盖）
3. **换模型时自动丢掉父的 reasoningEffort**（`:329`），避免给新模型传不匹配的 effort

`dsh-subagent` 的 `static Config` 只有 `maxDepth` / `maxActiveSubagents`，**没有默认模型字段** —— 所以「默认 v4.1-flash」要靠父 agent 显式传，或者靠 instruction 约束。
