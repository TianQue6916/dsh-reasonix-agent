# Bilingual Translator（双语翻译技能）

> ⚠️ **铁律：禁止英中分段对照。** 输出必须是**中文主体 + 英文术语行内嵌入**的单行双语格式。见下方「核心格式」与「❌ 致命错误」。

将各种格式的文件（PDF、DOCX、TXT、HTML 等）翻译为 **行内双语 Markdown**：句子主体用中文自然叙述，关键英文术语保留原文，首次出现时用括号紧跟中文翻译。数学公式、代码块、URL 等保持原样。

## 核心格式（必须严格遵守）

### ✅ 唯一正确的格式

**句子主体用中文自然叙述**，关键英文术语保留原文，首次出现时紧跟括号中文翻译。同一术语在后续出现时可省略括号翻译，只保留英文。

```
Transformer 架构依赖 self-attention 机制（自注意力机制）来捕获序列中的 long-range dependencies（长程依赖关系），并使用 positional encoding（位置编码）来注入关于 tokens（词元/标记）相对位置的信息。
```

格式模板：**`English term（中文翻译）`** —— 英文术语先出现，中文翻译用括号紧随其后。

整段输出中**没有完整的英文原句**，英文只以术语片段的形式出现在中文句子中。每条内容只写**一行**（一段中文），而不是「一行英文 + 一行中文」。

### ❌ 致命错误：英中分段对照

以下是我犯过的错误——**绝对禁止**：

```
In a weighted directed graph G = (V, E), the weighted eccentricity ε(u) of a vertex u ∈ V is the shortest weighted distance to its farthest vertex v...
在带权有向图 G = (V, E) 中，顶点 u ∈ V 的 weighted eccentricity（带权离心率）ε(u)...
```

（问题：先写完整英文段落，再写中文翻译段落。这是英中对照，不是行内双语。）

✅ **正确写法应该是**：

```
在带权有向图 G = (V, E) 中，vertex（顶点）u ∈ V 的 weighted eccentricity（带权离心率）ε(u) 是其到最远 vertex v 的最短带权距离。
```

**识别方法：** 如果输出中有任何一行以英文单词开头、长度超过 10 个词且后面紧跟着一行中文翻译，那就错了。正确的输出中**没有完整的英文原句**。

## 排版规范

### 标题层级

```
# 课程全称
## 讲次/大节（Lecture N）
### 定理/推论（Theorem / Corollary）
#### 定义（Definition）
```

用标题层级实现视觉区分，**不使用** `<div>`（MarkText 中不渲染）。`>` blockquote 可用于虚化次要内容（MarkText 中自动虚化）。

**🚨 铁律：`#` `##` `###` `####` 等 heading markers（标题标记）必须位于行首。** 行首不能有 `<span>` 或其他 HTML tag 在 `#` 之前，否则 Markdown 解析器不会将其识别为标题。

```markdown
✅ ### <span style="color:#2471a3;">**[problem]**</span> <span style="color:#c0392b">Title</span>
❌ <span style="color:#2471a3;">**[problem]**</span> ### <span style="color:#c0392b">Title</span>
```


对于习题集/Problem Set 类文档，遵循以下层级与字号规范：

| Markdown 层级 | 字号 | 颜色 | 用途 |
|:---|:---:|:---:|:---|
| `#` h1 | 最大 | 默认 | 课程全称 |
| `##` h2 | 大 | `#c0392b` 深红 | 讲次/大节标题（如 Problem Session N） |
| `###` h3 | 中 | `#c0392b` 深红 | 题目标题（如 Problem N-M. Title） |
| `<span>正文</span>` | 1em | 默认 | **题目描述**——完整的双语行内翻译 |
| `> blockquote` | 虚化 | 默认虚化 | **答案/解答**——完整行内双语翻译 + 虚化显示 |

### 习题与例题的差异化翻译规则

翻译教材/讲义时，不同类型的模块采用不同的翻译策略：

| 模块类型 | 翻译策略 | 说明 |
|---------|---------|------|
| **Exercises（习题）** | **保留英文原文，不翻译** | 习题的题目描述、选项、提示等全部保持英文原文，不做行内双语翻译。原因：练习时阅读英文原题是必要的学术技能。 |
| **Examples（例题）** | **完整行内双语翻译** | 例子中的描述、推导、结论全部按标准行内双语格式翻译。 |
| **Notes / 译者注（Notes/译者注）** | **完整行内双语翻译** | 正文注释和译者补充均按标准行内双语格式翻译或撰写。 |
| **Theorems / Proofs / Definitions（定理/证明/定义）** | **完整行内双语翻译** | 标准行内双语格式，定理名用 `English（中文）` 标注。 |
| **正文段落实例描述** | **完整行内双语翻译** | 节与节之间的过渡段、介绍性文本等均按标准格式翻译。 |

**示例对比：**

```
✅ Example（例题）—— 需要翻译：
[example] **Example 2.32: Geometric Progressions（例 2.32，几何级数）**
设 $r$ 是一个实数。序列 $1, r, r^2, \ldots$ 构成一个 geometric progression（几何级数）。
若 $r > 1$，则 $r^n \to \infty$。

❌ Exercise（习题）—— 不需要翻译：
**2.11.7** Which statements are true?
(a) If $\{s_n\}$ is unbounded then it is true that either $\lim_{n\to\infty} s_n = \infty$ or $\lim_{n\to\infty} s_n = -\infty$.
```

这一规则也适用于解题答案：习题答案保持英文原文，只有过程性描述可以做最小必要翻译（如"Proof（证明）"标签本身）。

### 内容层次原则

每个功能模块用 `<span style="color:#2471a3;">**[tag]**</span>` 标签开头，蓝色统一。

对「题目 + 答案」这种成对结构，严格区分处理规则：

1. **题目（原文）**—— **不得缩颈**。保持完整的行内双语翻译，正文 1em，默认色。原文的故事、背景、细节全部保留。
2. **答案（解答）**—— **完整翻译 + 虚化显示**。用 `>` blockquote 包裹答案全文（与题目一样完整的行内双语翻译），MarkText 自动渲染为虚化文字。答案内容同样保留完整论证，不缩减。
   ```
   > [solution] **Solution（解答）:** 完整翻译的答案内容。
   ```

代码块（```python 等）不受上述字号缩放影响，保持默认大小。

### 译者补充与替代解法

若你对题目或答案有更好的想法，或知道工业界/学术界有更优的解法，用专门标签标注后附加在原文之后：

- **`[note]`** — 背景知识补充、术语解释、上下文关联、历史沿革等。使用深绿色 `#1e8449`。
  ```
  > <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 此算法在现代工业界已由 XX 替代。
  ```
- **`[alternative]`** — 优于原文的解法、现代替代方案、工业界实践等。使用深紫色 `#7d3c98`。
  ```
  > <span style="color:#7d3c98;">**[alternative] Alternative（替代解法）:**</span> 实际工程中多用 YY 算法，时间复杂度更低。
  ```

补充内容同样遵循行内双语格式，放在原文答案之后，用 `>` blockquote 包裹以保持视觉层次。

**注意：**
- 必须明确标注标签，让读者能清晰区分「原文」与「译者补充」。
- **🚨 补充内容必须基于真实来源，不得依赖训练数据瞎写。** 写 `[note]` 或 `[alternative]` 前必须用 web search / GitHub / 论文检索验证信息准确性。例如查证：
  - 工业界当前使用什么算法/框架（GitHub 仓库、技术博客、官方文档）
  - 算法的时间复杂度或工程实践是否有更新
  - 是否有已知的更优解法（SOTA 论文、竞赛获奖方案）
- 如果无法查到可靠来源，则不写补充，不要编造。
- **写完补充后必须二次审查：** 逐条检查每条补充是否（a）有真实来源支撑、（b）表述准确无歧义、（c）与原文答案清晰区分。不确定的宁可不写。

### 数学规范

- **🚨 所有数学公式必须使用 LaTeX 行内公式 `$...$`，不允许用文字代替。** 包括：复杂度 $O(n \log n)$、变量 $\delta(s, v)$、下标 $G_k$、上标 $k^*$、负数 $-6$、集合 $\{a, b, c\}$、运算符 $\min$、$\max$、$\le$、$\ge$ 等。
- **🚨 禁止 `$$...$$`。** 行内公式用 `$...$`；块级公式（需要独立居中显示的大表达式、多行推导等）用 fenced math block：
  ````markdown
  ```math
  公式
  ```
  ````
- 在 blockquote 内使用 fenced math block 时，每行加 `>` 前缀：
  ````markdown
  > ```math
  > 公式
  > ```
  ````
- 数集用 `\mathbb{}`：$\mathbb{R}, \mathbb{Q}, \mathbb{Z}, \mathbb{N}$
- 变量用斜体：$x, m, n, h$
- 定理陈述作为独立命题，证明以 $\square$ 结尾
- ✅ 正确：复杂度为 $O(|V|^3)$，其中 $\delta(s, v)$ 表示最短路径距离
- ❌ 错误：复杂度为 O(|V|³)，其中 δ(s, v) 表示最短路径距离（文字代替 LaTeX）
- ❌ 错误：用 `$$...$$` 包裹公式（应用 ```math fenced block 替代）

## 工作流程

### Step 1: 读入
- 读取源文件，识别文件类型
- **查知识库**：用 `memory` 工具搜索相关主题，了解已有背景知识
- 提取文本内容，保留结构信息（标题层级、列表、表格、代码块、数学公式）
- 对于 PDF：
  - 先用 `pdftotext` 默认模式提取
  - 若发现内容明显缺失（如定理陈述不完整、节标题后直接跳内容），尝试 `pdftotext -layout` 或 `pdftotext -raw` 模式重新提取
  - 同一 PDF 的不同提取模式可能捕获互补的内容片段，需对比合并
  - OCR（Tesseract）对数字生成 PDF 帮助有限，仅对扫描版 PDF 使用

### Step 1b: 搜索课程视频字幕（MIT OCW / OCW 类课程专用）

翻译 MIT OCW 讲义时，必须搜索 Windows 主力机上的视频字幕（如果课程有视频讲座）。字幕包含教授的口语化讲解，是写译者注的珍贵素材。

**⚠️ 关键教训：不要只做关键词匹配搜索，要先读取目录结构。**

具体操作：

1. **列出目录结构**：用 `control-main-machine` 技能连接 Windows 主力机，执行：
   ```powershell
   powershell -Command "& { Get-ChildItem 'D:\b站视频\解析视频\' -Directory | ForEach-Object { $_.Name } }"
   ```
   先看有哪些子目录，而不是直接 grep 关键词。

2. **识别课程目录**：B站上的课程名可能和 MIT 课程编号不同。已知映射：
   - 18.100B → "数学分析"
   - 6.006 → "【MIT6.006最新】算法导论(中英2020春) Introduction to Algorithms 麻省理工"
   - 18.046 → 也可能包含实分析内容（18.046 是旧编号）
   
3. **深入目标目录**：在识别出的课程目录下，搜索字幕文件位置：
   - `06-字幕文件\` 或 `06-字幕文件\终版字幕\` — 独立字幕（.srt, .webvtt）
   - `05-视频讲座\` — 视频配套字幕（.srt + .zho-hans.srt 中英双语）

4. **读取字幕内容**：
   ```powershell
   # 读取英文字幕
   powershell -Command "& { Get-Content 'D:\b站视频\解析视频\{课程目录}\06-字幕文件\终版字幕\V{NN} - {Title}.srt' -Encoding UTF8 }"
   
   # 读取中文字幕
   powershell -Command "& { Get-Content 'D:\b站视频\解析视频\{课程目录}\06-字幕文件\终版字幕\V{NN} - {Title}.zho-hans.srt' -Encoding UTF8 }"
   ```

5. **提取关键教学片段**：从字幕中提取教授对核心概念的口语化解释、直觉比喻、关键条件强调。这些是写译者注的**第一手教学素材**。

6. **编码注意事项**：中文路径在 SSH 中可能遇到编码问题。使用 `ForEach-Object { $_.Name }` 而不是 `Select-Object Name | Format-Table` 来避免编码破坏。读取文件时指定 `-Encoding UTF8`。

7. **已记录的路径**（来自记忆 `project/100b-subtitle-paths.md`）：
   - 18.100B（数学分析）：`D:\b站视频\解析视频\数学分析\`
   - 字幕在 `06-字幕文件\终版字幕\`（.srt 格式，英中双语）
   - 文件命名：`V{NN} - {Title}.srt` 和 `V{NN} - {Title}.zho-hans.srt`

### Step 2: 分析
- 识别文档结构：目录、章节、小节、段落
- 区分功能模块：定理、证明、定义、推论、例子、问题
- 识别关键术语、颜色信息

### Step 3: 排版规划
- 确定标题层级：`#` → `##` → `###` → `####`
- 为每个功能模块分配蓝色标签 `[theorem]` `[proof]` `[definition]` 等
- 规划配色方案

### Step 4: 翻译 + 排版输出
- **🚨 铁律：输出中不得出现完整的英文原句。** 英文只以术语片段的形式嵌入中文句子。
- 逐段阅读原文后，**直接用中文写作**，将英文术语作为行内元素嵌入。
- 格式：**`English term（中文翻译）`**，英文术语先出现，中文翻译用括号紧随其后。
- **禁止**「先写完整英文段 + 再写中文翻译段」的英中对照模式。
- **🚨 行内公式用 `$...$`；块级公式用 ` ```math ` fenced block；禁止 `$$...$$`。** 这是最常见的错误——`$$...$$` 在 MarkText 中可能渲染异常，必须用 fenced math block 替代。
- 每个功能模块前加蓝色标签。
- 用 `---` 分割线分隔大段落。
- 颜色匹配原文或按配色方案处理。
- **禁止使用** `<div>`（MarkText 不兼容）。`>` blockquote 可用于虚化次要内容。
- **译者注位置**：每条注必须**分散插入到对应内容后面**（定理后、证明后、定义后等），绝不允许堆叠在文件末尾。布局原则：读者读到某个概念时立即看到注，不需要翻页查找。
- **字幕素材引用**：如果在注中使用了视频字幕中的教授原话，用 `🎥 *教授名在视频中强调: "原文..."（翻译）*` 格式标注来源，增加教学现场感。

### Step 5: 层次加工
- **区分主次内容**：题目（原文）和答案（解答）均保持**完整行内双语翻译**；答案用 `>` blockquote 包裹以实现虚化。答案内容不缩减。
- 答案内容不缩减，与题目一样保留完整行内双语翻译。
- 代码块不受字体缩放影响，保持 1em。
- 检查整体视觉层次：标题 → 题目原文 → 答案是否一眼可区分，原文是否被不当压缩。

### Step 6: 译者补充（可选）

#### 6a: 常规补充（知识查证类）
- **🚨 写补充前必须先联网查证。** 不要依赖训练数据编写 `[note]` 或 `[alternative]` 内容。
- 用 web_fetch、GitHub 搜索等方式查证现代工业界做法、最新研究进展、SOTA 算法等。
- 判断是否有比原文更优的解法、工业界替代方案、或值得补充的背景知识。
- 如有可靠来源，用 `[note]`（深绿）或 `[alternative]`（深紫）标签标注，放在原文答案之后。
- 补充内容同样用 `>` blockquote 包裹，保持视觉一致。
- 如果查不到可靠来源，则不写补充，不要编造。
- **写完补充后必须二次审查：** 逐条检查每条补充是否（a）有真实来源支撑、（b）表述准确无歧义、（c）与原文答案清晰区分。不确定的宁可不写。

#### 6b: 学术教材译者注（针对实分析/数学/CS 教材）
当翻译数学或计算机科学教材时，译者注应匹配用户的「认知系统架构师」画像。

### ⚠️ 拓展连接的铁律（PS01 教训 — 2026-07-31）

用户对拓展知识**有强烈兴趣**（跨学科连接是人格画像的核心特征），但**禁止甩名词**——不能只提一个高级概念的名字而不解释。这恰恰是之前 PS01 初版犯的错误（甩了群论/商环/拓扑学/非标准分析等用户没学过的概念）。

**每条拓展连接的处理规则：**

1. **先查学业水平** —— 写注前必须用 `memory` 工具查询 `global/academic-level-and-teaching-style.md`，判断用户是否已具备理解该概念的前置知识。
2. **脚手架法** —— 如果用户没学过前置知识，要么从第一性原理构建解释（从用户已知的概念出发，逐步推导到新概念），要么暂时不提。**绝不裸甩名词。**
3. **精确连接路径** —— 每条跨课程连接必须精确到：课程名 + 具体概念 + 为什么类比成立 + 区别在哪。不是"这在群论中也有"而是"你在 6.042J 学过的等价关系，在这里就是 rational number 的相等定义——同一个等价类内的所有分数表示被视为'相同'。群论中把这个结构称为'商群'，但核心思想你已经会了。"
4. **拓展 ≠ 炫耀** —— 拓展的目的是帮用户看到知识地图的全貌，不是展示你懂多少高级概念。如果一个拓展概念需要 3 页纸才能讲清楚，而当前上下文只够提一句名字，那就不要提。

**注的类型：**
1. **跨课程连接**：将当前内容与用户知识体系中的其他课程连接。**可用的连接锚点**：离散数学 6.042J（等价关系、偏序集、数论）、CSAPP（浮点表示、机器级编程、内存层次）、CLRS 算法导论（二分搜索、分治、复杂度分析）、线性代数 Strang（矩阵方法、SVD）。具体到课程名和章节，并解释连接路径。
2. **第一性原理洞察**：解释定理背后的核心直觉，追溯最基础的假设。回答"为什么必须这样？"用用户已经理解的简单概念作为脚手架搭建新概念。
3. **证明策略模板**：把证明方法抽象为可复用的思维模板（ε/2 技巧、ε-剥离法、峰点论证、分组放缩、归纳三步法、supremum sandwich 等）。**命名模板**（如"上确界夹逼法""ε-剥离法"）便于记忆复用。
4. **历史与人物**：数学家为什么这么想？当时要解决什么具体问题？对后世的影响。标注具体年份（如 Bolzano 1817、Cauchy 1821、Weierstrass 1872）。
5. **拓展前沿**：相关的更高级概念。**必须从用户已知概念出发解释**，不得裸甩名词。如果用户没学过前置知识，要么搭建脚手架解释，要么暂时不提。

**质量标准（必须严格遵守）：**
- **每条注 ≥ 5 句话**，信息密度高（不是 ≥ 3 句）
- **每条约 200–400 字**（不是 100–300）
- 有实质内容，不凑数
- 跨课程连接要明确提及**课程名 + 具体概念 + 连接路径**（如"你在 6.042J 学过的等价关系，在这里就是 rational number 的相等定义——同一个等价类内的表示被视为'相同'"而非"这在群论中叫商集"）
- 🚫 **禁止甩名词** —— 不得只提高级概念名而不解释。写注前先查 `memory` 确认用户学业水平。
- 分布均匀，每个关键定理至少一条注
- 结合视频字幕中的教授口语化讲解，增加"教学现场感"
- 引用字幕时使用 `🎥` 表情标注来源

**结合视频字幕素材的注写法（重要）：**
- 从 Step 1b 提取的字幕中，找到教授对关键概念的**口语化解释、直觉比喻、证明中的关键步骤强调**
- 将这些素材以引用形式嵌入注中，格式：
  ```
  🎥 *教授名在视频中[教学动作]: "原文关键句子"（翻译）*
  ```
- 例如：
  ```
  🎥 *Colding 在视频中以极其口语化的方式将这一步讲透了：因为 $a$ 本身就是上界，$a_n \le a$ 自动成立，所以* "you don't need absolute value because I already know this is bigger than that"——*不等式方向天然确定，绝对值完全多余。
  ```
- 字幕素材能提供**讲义中没有的教学细节**：教授的语调强调、直觉类比、证明节奏等。

**执行方式：**
- 小规模翻译（1-2 节）：在翻译过程中同步写注
- 大规模翻译（整章/多节）：先完成主体翻译，再用 `task` subagent（优先 `deepseek-v4-pro` 模型）批量撰写注，然后合并。subagent prompt 需包含：
  - 读者画像描述（见下方）
  - 注的类型清单（5 种）
  - 质量标准（≥5 句、200-400 字、命名模板、字幕引用等）
  - 具体要覆盖的节范围

**读者画像（注入 subagent prompt）：**
```
- 大二上学期，智能科学与技术专业
- 方舟计划：数学9门+计算机11门知识体系
- 核心特质：构建主义学习 + 第一性原理追问 + 跨学科连接狂热
- ✅ 已完成的课程：离散数学 MIT 6.042J（含等价关系、偏序集、数论、图论）、CSAPP 全12章、线性代数 Strang（收尾中）
- 🔄 正在推进（暑假）：100B 实分析（Thomson TBB + Rudin，PS1阶段）、6.006 算法导论（CLRS）、18.065 矩阵方法（Strang）
- 📋 大二上计划：概率论（Bertsekas）、计算机网络（CS144）、凸优化（Boyd前5章）、信息论（Cover前6章）
- ⚠️ 尚未学习：抽象代数（群/环/域）、拓扑学、泛函分析、非标准分析
- 可用脚手架（连接新概念的锚点）：等价关系、浮点表示、二分搜索、矩阵分解、分治算法
- 反感：甩名词不解释、几何直觉式教学、只给公式不给直觉
```

### Step 7: 最终审查
- 全文通读一遍，对照质量检查清单逐项确认。
- 重点核查：标题是否渲染正确、双语格式是否一致、答案是否虚化、补充内容是否有来源。

### Step 8: 大规模翻译策略（适用整章/多节）

当翻译量超过 50 页或 500 行英文时，使用以下策略。⚠️ **架构原则：不惜计算成本，质量优先。** 多批次大规模并行，给每个子代理的 prompt 必须极其详细（包含完整翻译规范、格式示例、避坑清单）。

**8a: 按页切分（核心原则）**
- 将 PDF 的**每一页**切分为一个独立文件（`page_001.txt`、`page_002.txt`…）
- 每页独立处理，避免跨页上下文断裂
- 如果某页边界正好在定理中间（定理跨页），将该定理所在页范围合并为一个文件
- 保存到临时目录：`.reasonix/attachments/pages/`

**8b: 第一波——翻译子代理（50 个并行）**
- 使用 `fleet` 启动 **50 个翻译 worker**，每个 worker 处理 **1 页**
- 每个 worker 的 prompt **必须极其详细**，包含：
  ```
  你是一个专业学术翻译。请将以下 PDF 原文翻译为行内双语 Markdown。

  ⚠️ 铁律：
  1. 禁止英中分段对照——输出中没有任何完整的英文原句。
  2. 格式：中文主体 + `English term（中文翻译）` 行内嵌入。
  3. 数学公式用 $...$（行内）或 ```math fenced block（块级），禁止 $$。
  4. 功能标签用 <span style="color:#2471a3;">[tag]</span>。
  5. 习题（Exercises）保持英文原文，不翻译。
  6. 例题（Examples）和注（Notes）按行内双语翻译。
  7. 译者注用 > blockquote + 深绿色 `#1e8449`。
  8. 所有定理编号、定义编号、例子编号必须与原文完全一致。
  9. 🔴 特别注意：Example 2.29 类的问题——原文说"还需更多工作才能证明极限为0"，不要翻译成"极限为0"。

- Write paths 声明为各自的输出文件（`.reasonix/attachments/pages/page_XXX.bilingual.md`），**50 个 worker 的 write_paths 不能重叠**
- 如果 50 个并行超上限，分 2 批（25 + 25）或按可用上限调整

**8c: 第二波——审计子代理（10 个并行）**
- 翻译完成后，启动 **10 个审计 worker**，每个 worker 审计 **5 页**
- 每个审计 worker 的 prompt：

  4. 🟡 开篇段/过渡段是否被省略？
  5. 🟡 定理证明是否被大幅压缩？
  6. 🟡 习题是否被错误翻译（应该保持英文原文）？

  8. 🟢 Math formatting ($$ vs ```math) 是否正确？

  对每个问题输出：页码 | 严重程度 | 问题描述 | 建议修复

  1. 跨课程连接 — 精确到课程名+具体概念+连接路径解释

**8f: 交叉引用标注（Cross-Reference Mapping）**
为每个定理/定义/例子/公式标注其在主教材（源 PDF）中的位置，便于读者在翻译版中快速查询原文。

**8f-1: 编号体系映射规则**
对每个结构单元，在标题后添加灰色引用行：
```
Theorem 2.28 (Monotone Convergence Theorem, 单调收敛定理)
> <span style="color:#7f8c8d;">TBB §2.9, p.47</span>
```
格式模板：`<教材缩写> <章节>，p.<页码>`。
- 教材缩写：TBB (Thomson-Bruckner-Bruckner)、CLRS、CSAPP、Rudin、Strang、Horn、Boyd 等
- 章节：`§2.9` 表示第 2 章第 9 节
- 页码：`p.47` 表示源 PDF 的书页编号（非 PDF 文件页码）

**8f-2: 覆盖范围**
| 单元类型 | 标注要求 | 示例 |
|---------|---------|------|
| Theorem | 必标 | `TBB §2.9, p.47` |
| Definition | 必标 | `TBB §2.9, p.47` |
| Example | 必标 | `TBB §2.10, p.50` |
| Corollary | 必标 | `TBB §2.8, p.43` |
| Formula (关键公式) | 建议标 | `TBB §2.10, p.51` |
| Exercise | 选标（仅在跨卷引用时） | `TBB §2.9, p.49` |
| Lemma | 必标 | `TBB §3.4, p.85` |

**8f-3: 跨教材交叉引用**
如果翻译内容引用了其他教材中的定理（如讲义中说"见 CLRS Theorem 24.8"），也要标注：
```
> <span style="color:#7f8c8d;">CLRS §24.5, p.661 | TBB §2.9, p.47</span>
```

**8f-4: 专用子代理执行**
分配 **2–3 个专用子代理**执行交叉引用标注。
每个子代理处理约 1/3 的翻译页面。
子代理的 prompt：
```

1. 读取已完成的翻译文件，定位所有 [theorem]、[definition]、[example]、[corollary] 标签
2. 根据 PDF 原文（已提供页码信息），为每个标签添加灰色引用行
3. 格式：> <span style="color:#7f8c8d;">TBB §X.Y, p.Z</span>
4. 教材缩写 TBB = Thomson-Bruckner-Bruckner, Elementary Real Analysis, 2nd ed.
5. 页码指书本页脚的实际书页编号，不是 PDF 文件页码
6. 如果一个定理跨页，标注起始页
7. 不要修改任何已有内容，只在每个结构单元后插入引用行

```

**8g: 最终审查**
- 确认所有 sections 已覆盖
- 确认所有定理/例子/习题编号连续，且与原文一致
- 确认每个定理/定义/例子都已有交叉引用标注
- 确认零 `$$` 残留
- 输出到目标路径
- 全文通读一遍，对照质量检查清单逐项确认。
- 重点核查：标题是否渲染正确、双语格式是否一致、答案是否虚化、补充内容是否有来源、交叉引用页码是否准确。
- 发现任何不符合技能规则的地方，立即修正后再输出。

**8h: 对比原文审计（Post-Translation Audit）**
大规模翻译完成后，必须执行以下系统性审计步骤，按顺序操作：

**8f-1: 提取 PDF 原文文本**
```bash
pdftotext -f <起始页> -l <结束页> /path/to/original.pdf /tmp/original.txt
```
若发现内容明显缺失（定理陈述不完整、节标题后直接跳内容），尝试 `-layout` 或 `-raw` 模式重新提取并对比合并。

**8f-2: 定位章节边界**
对原文文本运行 grep 定位所有章节标题、定理、定义、例子的行号：
```bash
grep -n "Section\|Theorem\|Definition\|Example\|Exercise\|Monotone\|Cauchy" /tmp/original.txt
```
建立"原文章节行号对照表"。

**8f-3: 逐节对比审计清单**
对每一节，逐项检查：

| # | 检查项 | 检查方法 |
|---|--------|----------|
| 1 | **开篇段是否完整** | 节标题后原文是否有介绍段→翻译是否包含 |
| 2 | **所有定理/定义编号是否对应** | 原文 Theorem N → 翻译 Theorem N，无跳号/重号 |
| 3 | **证明是否完整** | 原文证明长度 → 翻译证明长度，无明显压缩 |
| 4 | **例子是否全部覆盖** | 原文 Example N → 翻译 Example N，无跳过 |
| 5 | **例子顺序是否正确** | 原文顺序 A→B→C，翻译不能变成 A→C→B |
| 6 | **习题边界检查** | 翻译文件习题编号从 N 开始，检查 N-1 之前的习题是否被跳过 |
| 7 | **过渡段是否遗漏** | 原文在两个定理/例子之间的过渡性段落是否被省略 |
| 8 | **人物/历史介绍是否遗漏** | 原文出现的数学家姓名、年代、背景介绍是否保留 |
| 9 | **内容是否被错误替换** | 原文定理 A 的内容不能出现在翻译的定理 B 中 |

## 沙箱与文件操作（重要）

由于 Reasonix 工作区沙箱限制，直接操作桌面目录文件时需注意：

1. **`edit_file` / `delete_range` 等工具**只能操作工作区内的文件（`~/.reasonix/global-workspace/` 及子目录）
2. **目标输出目录**（如 `/home/tianque/桌面/`）不是工作区，不能直接用编辑工具
3. **解决方案**：
   - 先将文件从桌面目录复制到工作区：`cp /桌面/路径/文件 .reasonix/attachments/文件`
   - 在工作区内用 `edit_file` / `delete_range` / `multi_edit` 修改
   - 修改后用 `cp` 命令（bash）复制回桌面目录
4. **`cp` 命令可以成功写入桌面目录**（bash 不受沙箱限制），所以文件传输可行
