# 方舟课程总结器

基于 CSAPP 总结实战中验证的方法论。将任意教科书从「知识点罗列」重构为「设计问题驱动的方舟复述」。

## 触发条件
用户要求总结/复述/整理一本教科书或一门课程，且明确要求「方舟风格」「设计问题驱动」「不是笔记」。

## 核心流程

### 第一步：提取全书结构
1. 获取完整目录（TOC）
2. 定位每章引言（作者自己说的「这一章要解决什么问题」）
3. 提取每章总结（作者自己做的归纳）
4. 标注章间依赖关系

### 第二步：确定「生态位」
回答三个问题：
- 这本书在用户的课程网络中扮演什么角色？（中轴/前置/出口）
- 它向上承接哪些课程/知识？（数学→CS、前置课程）
- 它向下展开为哪些课程/领域？（后续课程、论文、实践方向）

### 第三步：逐章重构
每章遵循固定模板：
```
### ChN · 不是「教科书原标题」，而是「这一章的设计问题是什么」

[核心设计问题 + 为什么这个问题重要]

[关键机制/公式 - 只保留能解释设计意图的]

【连接】[与方舟体系中其他课程/论文的具体衔接点]

[我的卡点] [具体误解 + 正确理解 + 如何搞懂的]
```

### 第四步：提取天才设计点（5-7 个）
选取标准：**对全书的统摄力**——理解这个设计就能串联多个章节。
每个设计点格式：设计名 + 为什么这个设计抓住了本质（不要写「这是什么」的教科书复述）。

### 第五步：标注待验证问题
- 格式：方向 + 优先级（P1-P4）+ 建议阅读时机 + 关键资源
- P1 = 大二上可开始，P4 = 研究生阶段
- 每个问题必须附带可追踪的阅读路径（具体章节/论文/源码）

### 第六步：事实核查
对所有数字、年代、技术声明进行交叉验证：
- 公式推导是否正确（尤其是自创公式）
- 历史年代是否准确（如 COW 首个实现、ISA 起始年）
- 代码行数等数字是否可核实
- 第三方工具行为描述是否精确（如链接器策略差异）

## 风格约束
- **零空洞赞美**：不用「精妙」「经典」「极致」「极好」
- **无页码**：用户使用不同版本/译本
- **设计问题驱动**：每章标题必须锚定设计问题，不是知识点摘要
- **连接具体化**：不能写「与XX课有关」，必须写「CSAPP 的 fork+execve 为 OSTEP 的进程调度提供了底层动机——调度器管理的进程由 fork 创建」

## 输出
- 单一 Markdown 文件，15-20 页
- 预留 `[我的卡点]` 供用户补充个人体验
- 末尾附自查清单（10-12 项容易在快速阅读中跳过的细节）
